# Menote V2 平台能力功能设计（v0.1）

- **整理日期**：2026-10-31
- **文档状态**：《Menote 核心重设计方案 v0.7》的配套技术能力规格。覆盖 V1 已存在、V2 必须保留的平台能力的**功能级设计**（功能行为 / 数据契约 / 边界与安全 / 验收），使开发**脱离 V1 项目即可进行**。具体实现选型仍属技术设计。
- **事实来源**：V1 代码勘查（基线 commit `605f553`，2026-10-31；仅作事实输入与核对基准，不作为设计依据）+ v0.7 主文档定稿结论。
- **标记约定**：`[V1 已验证]` = V1 代码已按此行为运行、V2 继承的机制；`[V2 适配]` = 按 v0.7 定稿调整；`[V2 新增]` = V1 缺失、V2 必须补齐；`[待定]` = 产品或技术层尚未定稿。

## 1. 认证与会话

### 1.1 总体

- 唯一部署机密 `AUTH_PEPPER`（主文档第十二章）。`[V1 已验证]` 系统不设其他服务端常驻密钥：会话令牌是不透明随机串、服务端只存 SHA-256 哈希，**无需签名密钥**——与 12.1"单 Secret 推算"结论一致且更简。
- `AUTH_PEPPER` 的每个用途带独立上下文后缀、互不可推 `[V1 已验证]`：
  1. 登录防枚举假盐：`HMAC-SHA256(AUTH_PEPPER, "menote-prelogin-v1:" + 用户名小写)` 取前 16 字节；
  2. 登录校验值：`auth_verifier = HMAC-SHA256(AUTH_PEPPER, 登录密钥)`；
  3. 备份包裹键：`SHA-256(AUTH_PEPPER ‖ "menote-backup-wrap-v1")`；
  4. 分享访问令牌签名密钥。
  V2 新增任何 pepper 用途必须使用新的独立后缀。
- 三套凭据分离（主文档 5.3 定稿）：登录密码仅用于认证；私人空间密码与单篇笔记密码是内容加密凭据，KDF 在客户端执行，服务端永不接触明文或可逆材料（见第 7 节）。

### 1.2 注册 / 登录 / 会话端点 `[V1 已验证，V2 保留]`

| 端点 | 行为 |
| --- | --- |
| `POST /api/auth/prelogin` | 按用户名返回 `auth_salt` + `auth_kdf`；**不存在的用户名返回确定性假盐**（防枚举） |
| `GET /api/auth/registration-state` | 公开注册状态；库中无用户时前端直接进注册页 |
| `POST /api/auth/register` | 单语句判定「库中无用户」或「注册开关开启且未到期」；**首个用户 role=owner**，其余 member；重名（大小写不敏感唯一）→「用户名已被占用」；成功即建私人空间内置行（幂等）+ 会话 + Cookie |
| `POST /api/auth/login` | 节流检查 → **无论用户是否存在都执行一次 verifier 计算**（防耗时探测）→ 常量时间比对 → 清失败计数、补私人空间、建会话；失败**一律同一文案**「用户名或密码错误」 |
| `POST /api/auth/logout` | 删当前会话行 + 清 Cookie；**不清本机缓存的明文数据与未上传内容**（outbox 保留） |
| `GET /api/auth/me` | 返回 `{id, username, role}` |
| `POST /api/auth/password` | 旧登录密钥校验 → 写新盐 / 新 KDF / 新校验值 → **失效其他设备全部会话、保留当前设备**，返回失效数 |

- 登录限流 `[V1 已验证]`：按用户名与来源 IP 双键（不取 `X-Forwarded-For`）；第 5 次失败起冷却，基值 30 秒指数翻倍、上限 15 分钟；响应含 `retry_after` 秒。
- 用户名：`/^[A-Za-z0-9_.-]{1,32}$/`，大小写不敏感唯一。
- `/api/*` 统一挂安全头 + CSRF 中间件。

### 1.3 密码派生与校验 `[V1 已验证]`

- **慢哈希只在浏览器**（Workers 免费版 CPU 受限，服务端不做 PBKDF2）：登录密钥 = `PBKDF2-SHA-256(密码, prelogin 盐, iterations)`，32 字节 base64url 上传。
- KDF 参数契约：`alg: "PBKDF2-SHA256"`、iterations ≥ 100,000（默认 600,000）、salt ≥ 16 字节、dkLen ≥ 32；服务端校验格式与长度。
- 服务端仅执行一次 `HMAC-SHA256(AUTH_PEPPER, 登录密钥)`，常量时间逐字节比对。
- **确定性假盐，注册与改密沿用同一盐**：副作用是 prelogin 无法探测用户名存在性、跨账号彩虹表无效；客户端不得另取随机盐（否则改密后立即锁死）。盐是公开数据，作用是「不复用」而非保密。
- 私人空间密码 / 单篇密码与登录 KDF 参数统一（零 wasm），但**作用域、存储与包装链完全独立**（第 7 节）。

### 1.4 会话 `[V1 已验证]`

- Cookie `menote_session`：httpOnly、SameSite=Lax、Path=/、https 下启用 Secure；**不透明 32 字节随机令牌（非 JWT）**，服务端查库，库存 SHA-256 裸哈希。
- TTL 30 天滑动续期：每次校验续 `expires_at`；`last_seen_at` **每天最多写一次**（控制 D1 写入）；过期会话顺手删除。
- 校验失败（无 Cookie / 非法格式 / 不存在 / 已过期）**一律按未登录处理**，不区分原因、不泄露差异。
- 改密失效其他设备会话（保留当前）；登出仅清会话态。
- **密码恢复机制 `[第五批后定稿]`**：内容加密凭据采用单一恢复码体系（见第 7 节）；**登录密码遗失仍无恢复通道**（无邮件/找回机制，账号级问题后续单独定）。

### 1.5 验收（认证）

1. prelogin 对存在 / 不存在用户名返回结构一致、耗时无差；
2. 登录失败统一文案；第 5 次失败触发冷却且 `retry_after` 正确；
3. 会话过期 / 缺失按未登录；改密后其他设备会话全部失效；
4. 库中任何表不含密码明文、登录密钥明文或可逆材料；`AUTH_PEPPER` 缺失时认证 fail-closed。

## 2. 本地存储与同步引擎

### 2.1 本地权威与 outbox 队列

- 本地 IndexedDB 保存运行时权威副本（离线可用、多标签页协调）；云端 D1 是多端同步权威（主文档 6.1 口径）。
- **outbox 队列** `[V1 已验证]`：行结构 `seq(自增) / entity / entity_id / op / base_rev / base_meta_rev / retries / next_retry_at / last_error / queued_at`；**正文不复制进队列**，指向本地草稿（编辑中约 2 秒落盘），上传成功且与草稿一致才清除。
- 操作类型 `[V1 已验证 → V2 适配]`：`create / save_body / patch_meta / trash_item / create_folder / patch_folder / put_settings` → V2 对应 **Note / Memo / 表格文档、主题、分组、设置**的创建 / 正文保存 / 元数据修改 / 移入回收站；Memo 的 `status`、`source` 等结构化字段随 create / patch 上报。

### 2.2 推送 `[V1 已验证]`

- 单轮上限 20 操作；队首连续可批量操作合并，每请求 ≤ 10。
- `save_body` 请求携带：`base_rev`（正文基版本）、`content_hash`（正文 sha256）、`deviceId`（服务端写 `items.last_device`）、`attachmentRefs`（正文引用的附件哈希列表；**缺省 = 不动引用表**；批量路径同样携带，防断网重连后引用漂移）。
- 失败分派：可重试错误指数退避（1/2/4/8s…±20% 抖动，封顶 60 秒）；不可重试（422/403/404）移入「上传失败」列表——不阻塞队列、界面可见 `last_error`。
- 触发时机：应用打开、写入成功后 300ms 防抖、标签页重新可见、网络恢复、前台每 5 分钟；**不做实时推送**。

### 2.3 增量拉取 `[V1 已验证，字段名 V2 适配]`

- `GET /api/sync?cursor=<n>` → `{items, folders, tombstones, settings, next_cursor, has_more, full_resync}`（V2 中 `folders` 语义 = 主题/分组）。
- 循环推进游标至 `has_more=false`；**每页落库即持久化游标**；防御上限 50 页。
- 落库顺序：**先墓碑、再条目 / 主题**（避免同页既删又更新残留旧行），设置最后；设置不参与游标、每页都带（本地有未上传改动或服务端 rev 未变时跳过）。
- `full_resync=true`：清空**已同步**内容重拉、游标归零；pending 队列与未上传草稿**保留**。

### 2.4 多标签页协调 `[V1 已验证]`

- Web Locks 主锁（`ifAvailable`，抢不到不排队等待）：所有标签页都可写本地库与 outbox，**仅持锁者推送与拉取**；不支持 Web Locks 的环境退化为直接执行。
- BroadcastChannel 事件（**广播不带用户内容**）：`item-updated{itemId}`、`cursor-advanced{cursor}` 由引擎发出并被各页订阅（收到后只重读本地库、不再发起同步）；隐私锁状态事件归隐私模块订阅。无 BroadcastChannel 的环境降级为空实现。

### 2.5 冲突与幂等 `[V1 已验证 + 议题 7 定稿]`

- 版本字段：`rev`（正文）/ `meta_rev`（元数据）/ `content_hash` / `updated_at`；服务端 409 detail 回传 `rev / meta_rev / content_hash`。
- **Note 正文冲突**：本地 hash 与服务端一致 → 判定为响应丢失的重放，按返回 rev 落账；否则本地稿另存**冲突副本**（命名含日期时间与设备，记录与原条目的关联），原条目采纳服务端版本并失效正文缓存——与议题 7「当前 + 冲突副本人工裁决」一致，V2 确认保留。
- **元数据冲突**：服务端胜出、不生成副本，记回 `meta_rev`。
- **Memo 结构化字段** `[V2 新增]`：字段级 last-writer-wins；删除用墓碑；删除与编辑并发时编辑胜（复活）。
- 幂等：服务端按 `operation_id` 去重（客户端命令与 MCP 共用）。

### 2.6 验收（同步）

1. 断网编辑 → 恢复后按序补传，附件引用不漂移；
2. 双设备并发改同一 Note → 产生冲突副本、原稿取服务端版本，无静默丢失；
3. 删除 + 编辑并发 → 编辑胜；
4. `full_resync` 不丢未上传内容与草稿；多标签页同时只有一个同步者；
5. 同 `operation_id` 重复提交不产生双份记录。

## 3. 附件管线

- 上传队列（进度 / 失败重试）→ Worker → R2；**内容寻址去重**（sha256）`[V1 已验证]`。
- 引用对齐：正文保存与 `attachment_refs` 在**同一次写**中对齐；引用抽取器与分享查看器同源复用；孤儿引用 30 天后**真删 R2 对象**；附件管理页列出全部附件与引用状态 `[V1 已验证]`。
- 缩略图（图片）生成与懒加载；4.3 瀑布流复用同一批附件数据。
- 加密附件 `[V2 适配 / 必须实测]`：单篇加密与私人空间条目的附件以密文存储与传输（5.3 / 6.2 边界）；V1 已有密文附件路径但未完成验证（主文档 10.2 指出），V2-C 必须实测网络、本地缓存、缩略图、历史与备份边界。
- MCP **不含任何附件工具**（结构性边界，见第 5 节）。
- **md 引用格式 `[第七批定稿]`**：正文内图片/附件以相对路径 + 内容寻址引用（`attachments/<sha256>--<原文件名>`），渲染时解析为鉴权 URL；`attachmentRefs` 哈希抽取继续承担同步与引用计数（双层各司其职）；导出默认 zip（`.md` + `attachments/` 目录，仅含被引用附件），加密附件解锁后明文随行（见主文档 6.2）。
- 验收：去重不重复存储；删引用后孤儿按期清理；未授权不可取加密附件明文；失败重试与断点续传可用。

## 4. 版本历史与回收站

### 4.1 版本历史 `[V1 已验证]`

- 全文快照（gzip 或原样），行级对比展示；恢复前**先封存当前稿**。
- 容量：每篇 50 版、每用户总量 2000。
- 自动封存触发：autosave 空闲；**session**（换设备或隔 1 小时后首次编辑，依据 `items.last_device`）；MCP 写前自动封存 `pre_mcp`（保留 1 份、10 分钟节流）；表格结构损坏降级（table→note 单向）前。
- 读取与恢复入口：UI 历史面板；MCP `read_item` 支持 `version_id`、`edit_item` 有 `restore_version` 模式。
- V2 适配：加密条目的版本只存密文（5.3 边界：历史只处理密文）。

### 4.2 回收站 `[V1 已验证]`

- 条目与主题 / 分组的软删 / 恢复 / 永久删除 / 清空；软删传播**墓碑 + `sync_seq`** 推进。
- 服务端在软删或隐私标记置位时**真撤销分享行**（不依赖客户端清理）；MCP `trash_item` 同样使分享失效，且 MCP **无永久删除**。
- 软删内容对 MCP 不可见（可见性谓词含 `deleted_at IS NULL`）。
- 空白草稿不落库 `[V1 已验证]`：正文无可见字符且标题未改的种子**从不上传**；三道闸——非 create 状态不动 / outbox 有该条目任何行不动 / 仍空白才回收；启动兜底扫描带 30 秒宽限期。
- V2 适配：加密条目入回收站仍是密文；恢复路径需凭据（第 7 节）。

## 5. MCP Agent 接入

### 5.1 令牌 `[V1 已验证]`

- 字面量 `mn_` + 32 字节随机（base64url）；**SHA-256 哈希存储，且哈希输入必须带 `mn_` 前缀**（域分离，防会话令牌字符串冒充 MCP 令牌——回归测试项）。
- 每用户有效令牌上限 20；限速默认 60 次/分钟（可调上限 600），用 D1 计数实现（不依赖平台限速绑定，与 `last_used_at` 合并一条 UPDATE）。
- 权限位：READ=1（**恒含**，归一而非拒绝）/ CREATE=2 / EDIT=4 / TRASH=8。
- 令牌维度：`folder_scope`（范围 = 选中集合 ∪ 其直接子层，**最多两层**；null = 全部）`[V2 适配：主题/分组]`；`include_memos`；`allow_url`（是否允许 URL 路径携带令牌）；`expires_in`（7 / 30 / 90 天预设或永久）；名称 ≤ 64 字符。
- 记录不含任何凭据材料；完整令牌**仅在创建响应出现一次**，此后只有 `token_prefix`；撤销为软撤销（幂等），**无物理删除接口**。
- 管理接口（全部走会话，与 MCP 协议端点隔离）：创建 / 列表 / 撤销 `DELETE /:id` / 审计分页 `GET /:id/audit`。

### 5.2 协议端点 `[V1 已验证]`

- `POST /mcp`（Bearer 头）与 `POST /mcp/k/<令牌>`（须令牌勾选 `allow_url`）；无状态 JSON-RPC；`GET /mcp` 返回 405；**不挂依赖 `AUTH_PEPPER` 的配置守卫**——令牌体系独立于部署密钥，支持 12.1 单 Secret 结论。
- 通用分页：`cursor` + `limit`（1..50，默认 50）；工具描述统一附调用顺序提示（先 search/list → read → 带 rev 修改）。

### 5.3 工具契约（5 读 + 6 写）`[V1 已验证；V2 适配注记]`

| 工具 | 关键契约 |
| --- | --- |
| `search`（读） | query ≤ 200 字符；按类型（note/table/memo）/ 归属 / 标签过滤；返回 ID、标题、类型、片段、rev；**加密内容永不出现在结果中** |
| `list_folders`（读） | 范围内目录树（含条目数）+ 标签统计；`[V2 适配]` 语义变更为主题 / 分组；工具名沿用或提供新名按「向后兼容优先」原则在 V2-C 定（议题 9） |
| `list_items`（读） | 按归属 / 类型 / 标签 / 任务状态 / 更新时间过滤；**仅返回元数据** |
| `read_item`（读） | 整篇 / 小节 / 游标续读；单条目 > 512KB 自动走分段不报错；单次 ≤ 20000 字符；`version_id` 读历史版本 |
| `list_versions`（读） | 历史版本：时间、原因、大小、备注 |
| `create_item`（写） | type / content 必填（笔记与表格须 title，Memo 不接受）；`operation_id` 必填（幂等去重）；`[V2 落箱]` Note → 收件箱、Memo → 时间线，内容记 `source=agent`（议题 9） |
| `append_to_item`（写） | 向文末 / 小节末追加文字；表格追加行（行 ID 服务端分配）；**不需要 expected_rev**（服务端在最新版本上追加） |
| `edit_item`（写） | `expected_rev` 必填；5 种模式：replace_text / replace_section / replace_all / merge_properties / restore_version；修改前服务端自动封存 `pre_mcp` 版本；冲突默认返回当前 rev 提示重读，`on_conflict: "copy"` 可生成副本；正文 ≤ 256KB |
| `edit_table_rows`（写） | 按行 ID 更新 / 删除表格行；`expected_rev`；表格 > 256KB 拒绝 |
| `organize_item`（写） | 移动 / 改标题 / 增删标签 / 置顶收藏；`expected_meta_rev`；**范围外目录与私人空间均拒绝**（MCP 不能改变加密归属） |
| `trash_item`（写） | 移入回收站（分享同时失效）；**不提供永久删除** |

**加密条目边界 `[第五批修订]`**：单篇加密 Note 在 `search` / `list_items` 中返回标题与加密标识、**无内容片段**；`read_item` 返回加密状态而非明文；`edit_item` / `append_to_item` / `edit_table_rows` / `organize_item` / `trash_item` 对加密条目一律拒绝。私人空间条目不出现在任何工具结果中。

### 5.4 可见性不变式 `[V1 已验证，V2 沿用]`

- **MCP 可见集合 `[第五批修订]` = 令牌范围 ∩ 非私人空间 ∩（Memo 须令牌勾选）∩ 非回收站；单篇加密 Note 以「标题 + 加密状态标识」形态可见**，与浏览器隐私锁是否解锁**无关**。
- 过滤在 SQL 谓词层统一实现——私人空间（`in_enc_space`）与单篇加密（`enc_self`）使用**分开的谓词**：前者整条排除；后者排除正文/内容字段、保留标题与加密标识（MCP / 分享 / 导出 / 服务端兜底搜索各自引用，配断言测试防漂移）。
- 「不存在」与「不可见」返回一致（同形响应），Agent 无法探测存在性（该原则对私人空间继续成立；单篇加密条目按产品决策允许被枚举到标题）。
- **私人空间对 MCP 完全不暴露（含标题）**；**单篇加密 Note 标题可查、接口反馈加密状态；正文 / 附件 / 历史内容不可读，所有写类工具（编辑 / 追加 / 表格行 / 整理 / 回收站）对加密条目拒绝执行**（v0.1 第五批修订，产品负责人指示；Agent 不能解锁或改写密文）。
- 可写目录三条拒绝：不属于该用户（404 形状）/ 是加密空间（forbidden）/ 不在令牌范围内；限定范围的令牌不允许移到根。

### 5.5 审计 `[V1 已验证]`

- 仅记写类工具：`tool / item_id / rev_before / rev_after / result(ok|conflict|denied|error) / operation_id / at`；按令牌分页查询。
- V2 适配：审计随 `source` / `status` 结构化字段扩展；清理保留期 `[待定，技术设计]`。

### 5.6 验收（MCP）

主文档 11.4 第 1–3 条之外补充：

1. `mn_` 前缀域分离回归：会话令牌字符串不得通过 MCP 令牌校验；
2. 浏览器解锁私人空间后，MCP 查询仍完全过滤私人空间内容；单篇加密 Note 标题可查、加密状态正确反馈、正文读取与**所有写类工具被拒**（SQL 层验证）；
3. `operation_id` 幂等、`expected_rev` 冲突路径、`append` 无 rev 的并发安全各有自动化用例；
4. 限速与 20 令牌上限生效；撤销 / 过期令牌立即拒绝。

## 6. 远程备份与恢复

### 6.1 目标配置 `[V1 已验证]`

- `kind`: webdav | s3；字段 `label(≤64) / endpoint / bucket(S3 必填) / region(S3) / username / secret / enabled / delete_policy / schedule`。
- **凭据永不回显**：secret 仅在创建 / 替换时一次性提交，服务端包裹落库；任何读取只给 `has_secret: boolean`；连接测试端点可用库存凭据且不回显。
- `delete_policy`: **append_only（默认）** | sync；`schedule`: daily | weekly（只决定「某天推不推」，不决定一轮推多少）。
- 运行状态：`last_run_at / last_result(ok|partial|failed) / last_error`（错误原文平铺给用户、不含凭据）。

### 6.2 备份包格式 `[V2 新格式，继承 V1 完整性机制]`

- V2 采用**按月分片整体快照 + manifest**（议题 5 定稿）：每月一个分片，片内为归属该月记录的当前完整内容（Note 的 Markdown、Memo 的结构化记录、主题/分组树、收件箱/草稿箱归属），附件按内容寻址随包；manifest 记录全部分片与附件的路径、哈希、版本。
- 继承 V1 的完整性机制 `[V1 已验证]`：
  - **manifest + COMPLETE 双标记**：COMPLETE 为两行文本（格式版本 + manifest 的 sha256），置于被校验对象之外（自保护即循环）；校验顺序 = COMPLETE 识别 → 版本比对（高于程序版本提示先升级）→ **对 manifest 原始字节**算哈希比对 → JSON / schema 校验 → manifest 内 version 复核（防标记被单独改）；任一步失败整包拒收、绝不读一半；
  - **路径安全**：段非空、非 `.`/`..`、不含路径分隔符与控制字符；拒绝绝对路径、Windows 盘符、任何 `..` 段；归一化后必须落在包内目录中（最后一道闸）；
  - 附件文件名与条目 ID 走同一安全段校验。
- 出站加密信封 `[V1 已验证，V2 保留格式]`：`AES-GCM` 信封，字节布局定长逐字段校验——魔数 8B（`MENOTE1\0`）/ 版本 1B / KDF 迭代数 2B（千次为单位）/ KDF 盐 16B / K 包裹 IV 12B / K 密文 32B / K 标签 16B / 内容 IV 12B / 内容密文（可变）/ 内容标签 16B。
  - **K 包裹块逐字节复制用户库中的 `k_wrapped_pw`**（密码包裹密文；服务端无隐私密码，不重算）`[第五批修订]`；备份包同步携带**恢复码包装块 `k_wrapped_recovery`**（单一恢复码体系，见第 7 节），干净环境恢复时可用恢复码解开内容密钥；
  - 内容密钥 K 由**备份包裹键**（`SHA-256(AUTH_PEPPER ‖ "menote-backup-wrap-v1")`）从 `k_wrapped_backup` 解开；缺 pepper 时 fail-closed（「服务未完成配置」）；
  - 出站包**不含任何 `user_crypto` 字段**；仅私人空间 / 单篇条目套信封；空正文不套信封；内容 IV 每次现生成。
- **口径**：manifest 中 `content_hash / size_bytes` 记**明文正文**（非信封字节）；加密条目在包内为信封密文，标题按 V2 决策为明文元数据（议题 6）。

### 6.3 快照物化与推送 `[V1 机制 → V2 适配]`

- 物化：Cron 增量物化（V1 每 15 分钟一轮，游标 `user_snapshot_state.cursor_seq`）；两个独立配额——每轮文件数（V1=10）与出站加密字节（V1=2MB）；撞加密配额时该隐私条目**留到下一轮、游标停在它之前**，普通条目照写；无变更不写任何字节（manifest 也不重写）。
- 推送一轮 = 一批（V1 上限 40 个外部 PUT，兼容免费版子请求上限）；三条不变量 `[V1 已验证，V2 原样保留]`：
  1. 只推已物化到的位置；
  2. 游标只推进**连续成功**那一段；
  3. `append_only` 绝不执行远端 DELETE。
- 跳过条件：未到调度日（weekly 距上次成功 ≥ 7 天）/ 无新快照 / 目标未启用；手动「推一次」绕过调度档位但**不绕过物化关**。
- 结果判定：`error===null ? (remaining>0 || 配额停 ? partial : ok) : failed`；`remaining` 按推完后的新游标重算（避免「全推完仍显 partial」）。
- 删除：仅 `sync` 策略且本轮无错误时执行；删除队列按时间升序、**按 rev 条件删**（防并发误删新记录）；删除计入预算。
- V2 分片适配：分片对象（月份切片 + 附件）替代 V1 的「每条目一对象」，游标 / 批量 / 断点 / 结果判定机制不变。

### 6.4 恢复 `[V2 新增，V1 缺口]`

完整链路（主文档 11.4 第 5 条验收）：取回 manifest → COMPLETE / 哈希校验 → 加密条目用备份包裹键解信封（**解密凭据 = 隐私密码或恢复码**，对应 `k_wrapped_pw` / `k_wrapped_recovery`）→ 干净环境重建（记录、主题/分组归属、附件引用、Memo 结构化状态、加密内容的凭据提示）。**V1 的隐私条目「解信封恢复」未实现，V2 必须补齐并实测。**

### 6.5 验收（备份）

主文档 11.4 第 4–6 条之外补充：

1. 断点续传：失败 / 配额尽后游标停在最后连续成功处，下轮从该处继续；
2. `append_only` 目标远端永不出现删除操作；
3. 凭据不回显回归；pepper 缺失时推送 fail-closed 而非降级明文；
4. manifest 篡改（含单独改 COMPLETE）整包拒收。

## 7. 内容加密底层组件（衔接主文档 5.3）

- 信封加密 `[V1 已验证]`：内容密钥 K（32 字节）加密正文 / 附件；用户密码经 PBKDF2 派生 KEK 包装 K；`k_wrapped_pw` 存库（密码包裹密文，服务端无明文、不可逆）。
- 私人空间 `[V1 已验证 → V2 适配]`：V1 用内置加密空间行 + `in_enc_space` 标记 + 解锁状态广播（事件不带内容）；V2 保持「主题级锁」语义：解锁一次全开、作用域与单篇隔离、新会话默认锁、不活动超时可配（议题 6）。
- 单篇密码 `[V2 适配]`：V1 已有单篇门禁（`enc_self`）；V2 按议题 6 核实其密码体系与主题锁**互不连通**，落实三凭据分离；实施前勘查 V1 对应实现（主文档 10.2）。
- **密码恢复机制 `[第五批后定稿]`**：单一恢复码体系——全账户一个高熵恢复码；启用加密的内容密钥在密码包装（`k_wrapped_pw`）之外同时以恢复码派生 KEK 包装（新增 `k_wrapped_recovery`，明文码永不入库）；凭码解锁/重设、换码统一重包装所有受覆盖密钥。**服务端托管解密（「后台密钥重置」）已评估并否决**（预埋后门，违背 5.3 底线）。恢复码遗失 = 对应内容永久不可解。
- 锁定态边界（标题明文决策，议题 6）：服务端存储与列表接口可见**标题元数据**；正文 / 附件 / 版本 / 缓存 / 缩略图只处理密文；MCP / 分享 / 导出对加密内容按第 5 节不变式与第 6 节信封处理。
