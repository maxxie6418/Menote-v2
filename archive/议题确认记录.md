## 0. 总原则补充：内容解耦（可移植性第一）— 已确认 [2026-10-31]

由产品负责人补充提出，v0.7 回填至主文档「最终原则」及三、六章：

1. **编辑能力可以富，内容必须裸**：富编辑（所见即所得、属性控件、表格字段控件）都是应用层体验；持久层的内容真相**只有标准 Markdown + YAML**，编辑器内部 AST 仅存在于编辑会话，绝不落盘为专有格式。
2. **单篇导出无损**：任一 Note/Memo 导出为 `.md` 后，在 Typora / Obsidian / GitHub 等标准渲染器中内容完整、结构不丢；不得出现 Menote 专有语法（外部阅读器忽略未知 YAML 键是允许的，内容本体不得依赖 Menote 才能解读）。
3. **存储直读无损**：从 D1 / 备份 JSON 直接取出的内容字段是自洽 Markdown（Memo 的 tags/status 等结构化字段在备份 JSON 中、导出时生成 YAML，不写入正文）；应用卸载后内容仍可被任何 Markdown 工具解读。
4. **不支持 ≠ 改写**：编辑器/渲染器不支持的语法**原样存储、降级显示**，绝不剥离、转义或静默修正（含 Memo 中的标题、表格等超集语法）。
5. **加密例外说明**：锁定态只能拿到密文，这是访问控制而非内容耦合；单篇导出加密笔记须先解锁。
6. **图片/附件引用与管理**：~~另议~~ **已于补充设定 F 定稿关闭**（相对路径 + 内容寻址 + 导出随行附件目录，见主文档 6.2）。

## 1. 表格的文档身份 — 已确认 [2026-10-31]

1. **双轨**：Note 内任何 Markdown 表格均可进入结构化编辑（增强是编辑器能力，跟随内容）；「以表格为主体、YAML 携带字段定义」的 Note 作为连接器 / 浏览器收藏的绑定目标——它是 Note 的一种用法，不是第三种内容形态。
2. **字段配置**：持久字段定义只存在于表格主体文档的 YAML（如 `fields:` 结构），与属性区共用控件与序列化规则；Note 内表格一律无类型编辑，可手动「抽出」为独立表格文档。
3. **类型推断**：v1 不做自动类型识别；无定义表格的单元格一律按文本编辑、所见即写回。
4. **多选写回契约**：`值A, 值B`（逗号+空格分隔）；配套硬约束——候选值禁止包含逗号（校验强制）、单元格内容禁止换行、竖线按 GFM 规则转义、值首尾空格不保留（GFM 会 trim）。

## 2. 属性编辑器 — 已确认 [2026-10-31]

1. **类型集合**：v1 支持 8 种——文本、多行文本、数字、日期、单选、多选、复选框、链接（URL）。属性区与表格共用同一套类型定义与控件；表格侧因单元格禁换行不提供多行文本。日期时间、人员、引用等列为后续。
2. **定义存放**：类型/显示名定义存在该 Note 自己 YAML 的保留命名空间（具体键名技术设计时定）；单选/多选候选必须显式定义。
3. **无定义键**：按值做安全推断——能无损解析为日期/数字/URL/布尔才启用对应控件，否则一律文本；解析失败或编辑冲突一律文本降级、原样写回。主题级/全局 schema 继承列为后续增强。
4. **外来值兼容细则**：无法按声明类型解析的值降级为文本显示与编辑，保存原样写回，不报错阻断、不自动转换、不丢弃。
5. 属性区多选在 YAML 中是原生数组，不受表格单元格逗号契约约束（该契约仅适用于表格写回）。

## 3. Memo Markdown 编辑 — 已确认 [2026-10-31]

1. **语法范围（轻量集）**：块级——段落、有序/无序列表、任务列表、引用、fenced 代码块（无高亮或基础高亮）、分隔线；行内——加粗、斜体、删除线、行内代码、链接。不支持标题、表格、脚注；图片不走手写语法（附件上传自动插入引用）。
2. **任务列表复选框**：正文 `- [ ]` 渲染为复选框且**可点击**，点击改写正文中的 `[ ]`/`[x]`；它是内容级清单，与侧板 todo 的结构化 `status` 字段相互独立、互不驱动（todo 状态仍只走侧板）。
3. **编辑态形态**：源文本编辑（等宽纯文本，所见即源码）+ 保存/失焦后渲染显示；与 Note 的所见即所得编辑器彻底解耦。
4. 无常驻格式工具栏，手写 Markdown + 快捷键；后续可加极简工具栏。

## 4. 收件箱 — 已确认 [2026-10-31]

1. **双固定入口**（修订主文档 2.1/2.2 的单一收件箱设计，v0.7 回填）：
   - **收件箱**：外部内容的进站口——未来的剪藏条目、AI Agent 产生的输入都存这里，待用户整理确认；

2. **剪藏即 Note**：每次剪藏生成一篇 Note 进收件箱，正文为网页正文的 Markdown 化结果，YAML 带来源属性（source_url、剪藏时间等，键名技术设计时定）。

## 5. 备份 — 已确认 [2026-10-31]（复核通过）

1. **快照模型：按月分片整体快照**——每次备份执行把当前完整状态按月份分片导出（一月一片，片内为归属该月记录的当前内容）+ manifest；daily/weekly 调度只是执行频率，走同一流程。老月份记录被编辑 → 其分片更新重推。恢复 = 取全部分片 + manifest 校验重建，无重放链。
2. **保留策略：全保留 + 可选清理**——远端默认 append_only 全保留；提供按份数/时间的滚动清理选项，清理须显式确认且不影响本地；与 V1 的 append_only/sync 策略兼容。
3. **加密入备份：密文 + 密钥包装**——加密笔记/附件以密文写入备份包并附密钥包装元数据；恢复需用户凭据，无凭据 = 不可恢复（UI 明确警示单篇密码遗失不可找回）；主密码/明文密钥绝不入备份。密钥包装方案与议题 6 对齐。
4. **推导规则**：导出与远端备份同一格式（导出 = 手动触发一次备份包生成）；备份包 = 结构化 JSON + 附件文件 + manifest（版本与哈希）；恢复验收沿用 11.4（manifest 校验 → 哈希 → 干净环境演练）。

## 6. 加密具体实现 — 已确认 [2026-10-31]（第 3 条复核定稿；第 4 条密码恢复机制已定稿，见补充设定 E）

1. **三套凭据分离**：登录密码 ≠ 私人空间密码 ≠ 单篇笔记密码，互不连坐；拿到登录态 ≠ 能看私人空间。实施前勘查 V1 隐私锁/单篇门禁的密码体系是否已如此分离。
2. **锁定策略**：新会话默认锁定 + 不活动超时自动锁定（默认 15 分钟、可配置）+ 随时手动锁。
3. **标题明文（复核修订）**：加密笔记的**标题保持明文**——锁定时列表可辨识（否则无法知晓加密内容）、可按标题检索；**正文与附件始终密文**，锁定态不可访问；缩略图、历史版本、缓存仍只处理密文。已知并接受的边界：服务端存储与列表接口中标题为明文元数据。MCP 对私人主题与单篇加密 Note 仍按 11.1 完全不暴露（含标题）。
4. **密码恢复机制 `[已定稿，见补充设定 E]`**：单一恢复码体系（全账户一码、双包装、明文码不入库）。
5. **推导规则（信封加密方向）**：每篇 Note 独立内容密钥；私人空间内笔记的密钥由主题密钥包装（解锁一次全开）；单篇密码独立派生包装该篇密钥；算法选型（AES-GCM + Argon2id/PBKDF2 等）留技术设计。
