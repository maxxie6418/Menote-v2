属性区按内容规整：四个布局方案

现在这版的问题是「排版算法在决定阅读顺序」：双列用 grid-auto-flow: row dense，链接和多行文本跨列后留下的半格，被后面的短值回填进去——于是「标题」旁边是「作者」，「收藏于」旁边是「标签」，属性源顺序被拆散。再加上短行键列 72px、跨列行键列 88px 两档宽度，键名起点也不在同一条竖线上。下面四个方案都在解决同一件事：让排布服从内容语义，而不是让填充算法决定顺序。同一份数据（剪藏那篇知乎文章），可以切换对比。

左右列不配对标题↔作者、收藏于↔标签、喜欢↔批注，状态单悬一行 dense 把后续短值塞进跨列行留下的半格，视觉顺序 ≠ 源顺序 A / B / D C 用流式带绕开列
键名起点参差title 比 url、captured 右移约 16px 短行键列 4.5rem、跨列行 5.5rem，同一区两种栅格 全部 统一一档键列宽
中英键名混排title/like 与「作者」「状态」并置 剪藏只写值键，预设里没有这四条的显示名，回落到原键 全部 补预设显示名，键名降为 title 属性
长值不收敛整条 URL 铺满一行，概述被压成一行截断 链接跨列拿到全宽，多行文本却按单行 nowrap 处理 全部 链接去 scheme + 尾部省略；概述 2 行 clamp
类型没有视觉差异日期、布尔、枚举、长文用同一套灰字 只有输入控件区分类型，展示态全是文本 全部 日期等宽、枚举胶囊、布尔勾/破折
空值与真值同权空标签、空批注、假布尔各占一整行 没有「空」的专门形态，空值仍是可点文本 B / C / D 空值收成淡 —，悬停才给添加入口
头部与内容无关「属性 9 / + 属性」压在栅格外 头部是独立 flex 行，不与属性行共用键列起点 全部 头部左内边距对齐键列
「加标签」像第 10 行输入框与属性区之间无分界 标签编辑是独立区块，却排在属性列表正下方 B / C 标签回属性行内联，去掉底部输入

四个方案共用同一套值形态（日期等宽 / 链接去 scheme / 枚举胶囊 / 布尔勾破折 / 多行 2 行 clamp / 空值淡破折），差别只在「怎么排」。 选一个方向后再谈值形态与就地编辑，不要并行改两件事。
