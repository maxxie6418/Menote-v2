本地优先的密钥分层

2026-10-28 · 更新于 2 分钟前 · 1,284 字 · 7 分钟
状态草稿
可见性加密 · 本机
标签加密架构
字数1,284 · 7 分钟

服务端只保存密文，主密码永不离开发起设备。这条约束听起来简单，但它决定了整个密钥体系的结构 —— 也决定了每一次「为了便捷」的妥协都必须被拒绝。

一三层密钥

我们把密钥拆成三层，每层只解决一个独立问题，并且可以单独轮换。上层泄露不会自动导致下层失效 —— 这是分层唯一站得住的理由。

前提：AUTH_PEPPER 由部署者注入。缺失时 Worker 必须 fail-closed，绝不静默降级为无认证模式。
derive.ts · hkdf / aes-gcm 
// 派生链：mainKey → spaceKey → itemKey
async function deriveSpaceKey(main: CryptoKey, salt: Uint8Array) {
  const base = await crypto.subtle.exportKey('raw', main);
  const bits = await hkdf(base, salt, 'menote/space/v1', 256);
  return crypto.subtle.importKey('raw', bits, 'AES-GCM', false, ['encrypt', 'decrypt']);
}
主密码 → Argon2id → mainKey（仅存在于本地内存）
spaceKey 按空间派生，随空间删除一并销毁
itemKey 每条内容独立，密文头部携带 salt 与版本号

二边界与降级

降级路径比正常路径更值得设计。当 Worker 检测不到 AUTH_PEPPER，唯一正确的行为是拒绝启动 —— 而不是回落到「无认证」，因为后者的代价是不可见的。

安全设计里最难的部分，从来不是「加密什么」，而是「失败时会发生什么」。 — 内部评审记录 · 2026.10.30

检索、缓存、缩略图、历史版本与快照都必须在密文边界之内。MCP 侧只按可见性谓词裁剪：私人空间整条排除，单篇加密只保留标题与加密标识。

层级存储位置轮换代价失效影响
mainKey本地内存全库重加密不可用
spaceKeyD1 · 密文头单空间重写单空间不可读
itemKeyR2 · 内容头单条重写单条不可读

剩下的问题是轮换时机 —— 当设备丢失时，是否值得为一次「可能的泄露」重写全库。

Menote visual language · v3

墨台 / INKSTAND

一套围绕「纸与栏线」建立的界面语言。它不追求轻盈，而追求可读、可辨、可长期注视。以下令牌与五个视图中使用的完全一致 —— 切换明暗，整页会同步换算。

01

栏线优先于卡片

结构由 1px 线与留白建立，不用阴影堆叠浮层。阴影只留给真正脱离纸面的东西：弹层、抽屉、inspector。

02

双声部排版

衬线承担内容与标题，无衬线承担界面骨架，等宽承担数字与标识。三种字体各司其职，不互相借用。

03

朱砂只有一个用法

标记「此刻正在发生的事」：光标、当前项、选中行、未保存的动作。整屏只允许出现一到两处朱砂。

06

列表 + 抽屉

表格不是唯一用法，这是一个可复用范式
01
列表保持完整
列表宽度保持不变；详情浮在右侧，不挤动行内容。
02
抽屉从右侧展开
抽屉覆盖列表右侧；关闭后回到原表格位置。
03
就地编辑
属性、正文、备注都在抽屉里原位编辑，不跳页也不重排表格。

适用：表格行、收件箱条目、文档列表、搜索结果。宽屏从行号入口打开覆盖式详情；表格列宽不因抽屉开合变化。

内容已写入此设备。云端同步状态独立显示，不用“已同步”替代本地保存反馈。

保存状态与同步状态分开呈现；离线时仍可继续编辑。
A

锁定内容

隐藏正文、属性值、摘要、附件缩略图和搜索片段；只显示允许公开的标题与加密标识。解锁入口明确说明作用范围，锁定期间不产生明文恢复副本。

B

编辑态保留未保存提示与 Ctrl/⌘+S 反馈；离开前有未保存内容时先保存或留在当前页。崩溃恢复提示说明副本仅在本机，且加密笔记副本仍加密。
