四个可落地的视觉方向

同一套信息架构在四套 token 下的呈现：侧栏（Memo 输入 → 新建笔记 → 收件箱/草稿箱 → 最近/收藏 → 主题树 → 私人空间）、 笔记清单（穿透聚合）、文档区（标题 → 属性区 → 正文）。四张界面共用同一个结构骨架，差别只在颜色、字体、形状与密度—— 这也是需求 C-5「主题与逻辑解耦」的验证方式：定稿后换主题等于换一层变量，不重写组件。

分支 · 产品 模式 · 编辑型知识工作区 共识约束 · 克制、低饱和、无装饰渐变 默认浅色，B 为深色向

A

纸白 · 墨

把编辑器做成一本可以长期写的书
谱系 · 中文书籍排版 + iA Writer 字体 · 宋体正文 密度 · 舒适偏疏 强调 · 靛青唯一
画布 #FAF8F3 侧栏 #F6F2E9 正文 #1D1A14 强调 #3B5C7A 描边 #E6DED0 圆角 2 / 3px 正文 14px / 1.85
适合长文写作与阅读为主的场景：Note 是主体，Memo 当便签。纸色 + 宋体让「内容解耦」（C-1）在观感上也成立——写出来的就是一篇 md 文档。
代价中文宋体需自托管 Noto Serif SC 子集（约 1–2MB），否则 Windows 回退 SimSun 在 14px 下发虚。深色态需另调一套纸感，不能直接反转。
B

石墨 · 仪器

高频使用者的工作台，信息密度优先
谱系 · Linear / Raycast 字体 · 无衬线 + 等宽元数据 密度 · 紧凑 强调 · 冷蓝唯一
画布 #16181A 文档 #1B1E21 正文 #E7EAEC 强调 #7C9CFF 描边 #2A2F33 圆角 3 / 5px 正文 13.5px / 1.85
适合每天多次进出、以检索与整理为主：等宽字承载时间、字数、属性键名，三栏割据清晰，扫读快。也是最容易做成「专业感」的一版。
代价深色是主场，浅色态才是兼容工作；长文阅读舒适度低于 A/C。对「私人笔记」的情感温度偏冷，需要靠 Memo 区做软化。

先是一本自己的本子，其次才是工具
谱系 · Bear / Things 的触感 字体 · 全部无衬线 密度 · 松弛 强调 · 砖红唯一
画布 #F5EDE2 侧栏 #F2E8DA 正文 #2C2218 强调 #B4502B 描边 #E9DCC8 圆角 6 / 10 / 14px 正文 13.5px / 1.85
适合私人记录占主导的用法：Memo 时间线、生活主题、todo 面板在这一版最自然。大圆角与大点击区也最适合未来 Android 端沿用。
代价暖色 + 圆角容易滑向「可爱」，需要靠克制的字重和留白压住；截图缩小时层次会比 A/D 弱，密集清单页要额外加分隔。

净白 · 网格

结构自己说话，几乎不装饰
谱系 · 瑞士网格 / 编辑设计 字体 · 无衬线，强字号对比 密度 · 中等偏疏 强调 · 电蓝仅用于焦点
画布 #FFFFFF 清单 #FCFCFC 正文 #0A0A0A 强调 #1B4DFF 结构线 #111 圆角 0 / 2px 正文 13.5px / 1.85
适合相信「少即是多」、并且愿意接受高对比的一版。1px 黑线划分三栏，标题 37px 拉开层级，界面几乎没有彩色，加密/锁定这类状态反而更醒目。
代价零圆角在深色模式和高分屏上偏硬；对 Memo 这种「随手写」的轻量感有冲突，需要单独定义 Memo 区的软处理。

你定一个方向后，我会做的是：
  1. 写 DESIGN.md（九节：定位 / 谱系 / 排版 / 色彩 / 形状与层级 / 组件规则 / 交互不变式 / 禁止项 / 验收清单），把颜色、字号、间距、圆角全部落成 CSS 变量。
  2. 补关键组件的完整状态：悬停 / 选中 / 禁用 / 加载 / 空状态 / 错误 / 锁定与解锁 / 私人空间锁屏。
  3. 做可点击原型：Memo 展开、属性区点击编辑、列表↔网格切换、todo 侧板拖拽，跑 375 / 768 / 1024 / 1440 四个宽度。
也可以组合：例如「A 的正文排版 + B 的三栏密度 + C 的 Memo 区」，或「C 为主、私人空间转 D 的硬结构」。告诉我倾向与理由，我按组合再出一版。
