Menote V2 · Direction 08 · 2026-10-31

结构定了，剩下的是细节

“太像模板”通常不是审美不够，是处处均匀：每个日期都写成同一种格式、每档字号都精确到半像素、每个图标都同一个尺寸。 设计感往往来自“不均匀但合理”——该紧凑的地方紧凑，该松的地方松，同一类信息在不同情境下用不同形态。

这一版在 v7 的结构上做两件事：把标签改成胶囊（侧栏与属性区统一），以及一轮针对“看起来像模板”的细节校准—— 时间格式混排、按基线对齐、图标与字号同视重、收窄字号档位。

01

五个区段

从上到下，重要度递减

判断顺序的标准只有一条：用户一天里最常伸手去够的东西，必须在最短的鼠标路径上。

段内容为什么在这
1 工具品牌 · 搜索全局检索，不属于任何一类内容；放最高处，随时可达
2 记录Memo 输入 · 新建笔记 · Memo 时间线／最近编辑／收藏最高频的动作在最上；写完的入口紧接着“回看”的入口
3 待整理收件箱 / 草稿箱（并排）两个“收进来还没归类”的入口，等权并置；紧贴主题树，因为它们下一步就是归类到树里
4 结构主题（＋新建）· 主题树 · 私人空间树是结构主体；新建主题跟着标题走，不再沉到底部；私人空间是树里的固定节点
5 标签材质 8 · 光照 5 · 全部标签跨主题检索，低频但必备；放最下，不抢结构的注意力
为什么收件箱草稿箱并排它们是同一件事的两个入口（“待归类”），不是两条独立导航。并排成两个小块后，纵向省下 30px，主题树整体上移，结构更靠近视觉中心。
为什么私人空间在树里它不是导航项，是一个不可排序的固定主题。放进树的最末位，既保持“主题”的语义，也不会和收件箱这类功能入口混在一起。
02

两个输入入口

同形相邻 = 必然混淆

搜索和 Memo 都是“输入”，但一个是检索工具（得到结果就离开），一个是内容生产（写进库里）。两者相邻且同形，用户会先点错一次。

做法改前改后
位置紧挨 Memo 上方上移到工具区，与 Memo 之间加一条分隔线
形态带边框的输入框无边框的一行入口，hover 才出底色
距离8px分隔线上下各 10–11px
形态不同比距离更有效即使把两者拉开 40px，两个都是带边框的输入框仍然会被读成“两个搜索”。搜索改成无边框的行、Memo 保留虚线输入面，一眼就能分开。
Memo 保留虚线框的原因它是“待填写”的状态，虚线在视觉上天然表达“这里可以写”。搜索是“去找已有的”，不需要这个暗示。

05

细节校准

去掉“生成物”的痕迹

看起来像模板，通常不是因为不好看，而是因为处处均匀：同样的日期格式、同样精确的间距、同样的图标比例。下面八处都是“不均匀但合理”的调整。

细节改前改后
列表时间全部「10-30」14:02 / 昨天 / 周二 / 10-24 混排
日期与标题顶部对齐，基线差 2px按基线对齐
图标比例14px / 1.5 描边13px / 1.4
段间距11px（段距 : 行高 ≈ 0.44）14px（≈ 0.56）
字号档位9 / 9.5 / 10 / 11 / 11.5 / 12 / 12.5 / 13.5 / 14收敛到 10 / 11 / 12 / 13 / 14 / 17 / 32
主按钮一块纯橙顶部 1px 高光 + 底部 1px 压边
选中底色#FDF3EA，整行发橘#FEF6EE
标签列表行（像项目）胶囊（可并置的短词）
时间为什么混排真实的笔记列表不会把所有日期写成同一种格式：今天显示时刻、昨天写「昨天」、一周内写周几、更早写月日。一整列同格式的日期是数据库导出的样子。
为什么收窄字号档位9 / 9.5 / 10 / 11 / 11.5 这种半像素级阶梯，是“逐项生成”留下的指纹。人做设计会用少量档位，靠字重和颜色做中间层。
刻意没做的加投影、加渐变、做毛玻璃、给每个区块加圆角卡片——这些是“看起来高级”的捷径，恰恰是最容易被认成模板的处理。
判断标准把截图缩到 40% 看整体骨架是否还站得住；再把某一处放大到 200%，看有没有一处是“抠过”的。
06

需要联动改文档

这五条改动了基线

侧栏顺序在产品基线里是有明确写法的，这次调整有两处与它不一致，需要同步修订，否则开发和验收会打架。

FR-IA-4 原文：「侧边栏顺序：Memo 快速输入框 → 新建笔记按钮 → 收件箱/草稿箱 → 最近编辑/收藏 → 主题与分组树（含固定「私人空间」）」。 本次调整为：搜索 → Memo 输入 → 新建笔记 → Memo 时间线／最近编辑／收藏 → 收件箱／草稿箱（并排）→ 主题树（含私人空间）→ 标签。 差异是「回看类入口」提到「待整理类入口」之前，并新增了 Memo 时间线与标签两个入口。建议连同 FR-IA-2（固定入口两个）与 FR-IA-8（标签）一起更新措辞。
我没动的地方Memo 输入仍在新建笔记之前、主题树仍是结构主体、清单与文档的分工不变——这三条是基线的骨架，重排不应该碰。
建议的验收标准侧栏从顶到底可数出五个区段；任意两个相邻入口不属于同一类（工具／记录／待整理／结构／标签）。
越常伸手的东西，越靠上。
