## 1. 资源现状盘点

`wrangler.jsonc` 当期实际使用：

| 资源 | 用途 |
| --- | --- |
| Workers + Static Assets（`ASSETS` 绑定，`/api/*` run_worker_first） | 应用宿主与 API |

## 2. 规划内服务的接入方式（13.2 逐项）

### 2.1 Workers AI（近期引入，13.6 归 M4）

- **接入方式**：`wrangler.jsonc` 增加 `[ai]` 绑定（`binding = "AI"`），部署时自动预配，无密钥，不破坏「仅 `AUTH_PEPPER`」的一键部署承诺。
- **模块归属**：worker 侧新建 `services/aiService.ts`（新模块须在工程结构设计登记）；调用只由用户手动触发（Note 工作栏按钮），不做编辑/保存自动推理。
- **首期范围（13.3 已定）**：Note 摘要 + 标签推荐；结果先会话内预览，确认后写入属性区（复用文档更新链路）；按 `content_hash` 复用未过期结果；候选模型 Qwen3-30B-A3B / GLM-4.7-Flash，部署时核验目录可用性与 Neurons 定价。
- **前置阻塞**：加密内容 × AI 的授权流程与结果存储边界（开放项 #1）必须在验收前定稿，本任务包不定稿此项。
- **监控联动**：Neurons 用量进监控（见 §5 方案 D）。

### 2.2 Workers Logs（近期引入，纯配置）

- **接入方式**：`wrangler.jsonc` 增加 `observability: { enabled: true }`，无绑定、无密钥；免费档按日事件额度使用（核验义务 ①）。
- **收益**：错误排查、同步与 jobs 定时任务异常分析；与 `job_runs` 表（M2 G4）互补——表记录执行结果，Logs 记录过程细节。
- **红线**：任何日志不得出现主密码、明文恢复码、内容密钥、API Token；接入后对现有日志语句做一次红线走查。

### 2.3 D1 FTS5（M4，服务端/跨设备检索）

- **接入方式**：新迁移建 FTS5 虚表 + 触发器（或写入时同步）维护索引；SQL 全部在 db 层新文件；查询并入现有 items 查询按可见性谓词过滤。
- **索引边界（13.2 已定）**：只收非加密正文；加密笔记标题为明文可索引；加密正文一律不入索引（安全红线：密文边界覆盖检索）。
- **分工**：离线检索仍走本地 IndexedDB（M3 已接入）；FTS5 承担服务端/跨设备检索。
- **前置 PoC**：FTS5 `unicode61` 对中文按字切分、`trigram` 对中文子串匹配，两者检索质量与索引体积需 PoC 对比后再定实现。

### 2.4 D1 Time Travel（零开发，灾难恢复补充）

- **接入方式**：免费自带（时间窗口核验义务 ②），无需绑定与代码；恢复通过 D1 REST API 整库回滚。
- **定位（13.2 已定）**：不能替代 6.2 应用级备份；动作仅是在备份/恢复文档与 G11 恢复演练中登记 Time Travel 恢复流程（何时用 Time Travel、何时用备份快照、恢复后增量如何重放）。

### 2.5 Images Transformations（体验优化阶段）

- **接入方式**：URL 变换（`/cdn-cgi/image/...`）或 Worker 内绑定；**需自定义域名（zone）承载，workers.dev 子域不适用**（核验义务 ③），且可能存在账号级开通（类比 R2 例外，FR-DEP-9 平台前置限制提示）。
- **前置 PoC**：与 V1 自产缩略图方案对比（质量、CPU 消耗、额度），PoC 结论出来前不实现。

### 2.6 Queues（按需引入）

- **核验义务 ④**：免费计划可用性（历史上需 Workers 付费计划）；不可用时以 D1 队列表 + Cron 等价实现（jobs 框架已具备，V1 推送状态机已验证该模式）。
- **现状**：当期异步场景（备份推送）单步即可完成，暂无引入紧迫性；引入前先有真实的批量/重试需求。

### 2.7 Web Analytics（可选，默认关闭）

- **接入方式**：前端 beacon snippet（无 binding、无密钥）；默认关闭，设置页提供开关；数据只在 Cloudflare 仪表盘查看，不入库、不与账号关联。

### 2.8 Vectorize（远期）

不提前建设（13.2 已定）。

## 3. 资源监控现状问题

当前实现分两层（M1 基础模式 + M2 G12 增强模式）：

| # | 问题 | 依据 |
| --- | --- | --- |
| 1 | 基础模式仅 1% 随机采样统计 Worker API 请求数一项：无 D1 读写行、R2 操作、CPU、AI Neurons 维度；低流量日样本稀少导致估算方差大；采样落 D1 本身消耗写配额 | `services/monitorService.ts`（`REQUEST_SAMPLE_RATE = 0.01`） |
| 2 | 增强模式每次打开面板实时发起 3~4 个 GraphQL 查询 + 1 个 Billable Usage REST 调用：无查询缓存、无定时采样、无历史留存，违背 13.5-3「低频采样、查询缓存和适量历史存储」 | `services/monitorCloudflareService.ts`（`loadMetrics` 串行 4 次 fetch） |
| 3 | 额度常量仅 Workers 100k 请求/日；D1、R2、AI 的免费额度未进估算与分级预警 | `shared/contracts/monitor.ts`（`dailyQuota: 100_000` 一项） |
| 4 | `monitor_samples` / `monitor_hourly` 无过期清理 | M2 G10 遗留（开发记录-管理线 2026-11-01） |
| 5 | 增强模式真实账户联调未执行 | M2 G12 遗留（开发记录-管理线 2026-11-01） |

## 4. 更准确的监控方案（候选）

> 三类口径（官方 / 估算 / 本地）与「监控自身不造成明显负担」（13.7）是验收底线，以下方案均在其内。

### 方案 A：Workers Analytics Engine 精确计数（基础模式升级）

- **原理**：Worker 内 `env.MONITOR.writeDataPoint()` 原生写入，indexes 携带路由、blobs 携带方法/状态码/CPU ms/D1 读写行/R2 操作数；查询走 SQL API。
- **收益**：把「1% 采样估算」升级为全量精确计数，且将 CPU 与 D1/R2 维度纳入；写入免费、独立额度、不占 D1 写配额（现状采样写 D1 反而耗配额）；绑定自动预配，一键部署承诺不破。
- **代价与边界**：读取需 API Token（SQL API），无 Token 时基础模式看不到精确值——需保留极简本地聚合（内存计数 + 低频落 D1 单行）或明确提示「配置 Token 后可查精确用量」；三类口径中「本地」标签含义需同步更新为「应用内全量计数」。
- **核验义务 ⑤**：Analytics Engine 免费档写入额度与数据保留期；SQL API 免费调用额度。
- **结论**：推荐做小 PoC 核验后再定是否替换现有采样。**待负责人确认。**

### 方案 B：增强模式 Cron 定时采样 + D1 快照缓存

- **原理**：jobs 框架注册 `monitor-pull` 任务（建议每 6 小时），用库内已存凭据拉一次 GraphQL + Billable Usage，结果写入官方快照表（新迁移，如 `monitor_official_snapshots`）；面板默认读缓存并显示数据时点，手动刷新才实时查询。
- **收益**：面板打开成本从「每次 4 个外部查询」降为 0；官方数据自然积累历史趋势；采样时点透明，符合 13.5-3 已定原则；凭据解密逻辑复用 G12 既有实现。
- **代价**：新增一张表与清理策略；快照粒度（周期起点累计值）需与现有日/周/月视图对齐。
- **结论**：纯增量、无新绑定、无核验阻塞，**建议最先落地**。快照表保留期清理并入 G10 遗留的 monitor 清理缺口一并解决。

### 方案 C：免费额度常量补齐 + 可更新配置

- **内容**：在 shared 建集中常量表（Workers 100k 请求/日与 10ms CPU、D1 读/写行与存储、R2 Class A/B 与容量、AI Neurons），全部标注「以官方当期文档为准」，进基础模式估算与 70/85/95 分级预警。
- **口径差提醒（需负责人裁定）**：主文档 13.5-6 定「免费额度与价格使用可更新的配置，不写死」，资源监控设计 v0.1 §2 建议「写死 + 界面声明以官方为准」。两者可调和为「集中常量模块便于随官方调整更新 + 界面保留声明」，但按文档纪律先提请负责人确认，不自行定稿。

### 方案 D：AI Neurons 计量（随 M4 Workers AI 引入）

- 基础模式按「调用次数 × 模型单价」估算；增强模式查询 AI 分析数据集（dataset 名称与可用性核验义务 ⑥）。
- 依赖 13.5-2 的应用内预算：接近预算暂停自动/批量推理（保护动作 FR-MON-6）。

### 建议落地顺序

1. **方案 B**（无阻塞，直接做）；
2. **方案 A PoC**（半天核验，结论回填本文档后再定去留）；
3. **方案 C**（与 B 同批或紧随，常量表先行）；
4. **方案 D**（M4 与 Workers AI 同批）。
