### Workers AI 实现（FR-AI-2 / 主文档 13.3）

- **绑定与基础设施**：`wrangler.jsonc` 新增 `ai` 绑定（`AI`）与 `queues`（生产者绑定 `AI_TASKS_QUEUE` → `ai-tasks`，消费者 max_batch_size 5、max_retries 3）。`worker-env.d.ts` 手工补 `AI?` / `AI_TASKS_QUEUE?` 可选类型（本地与测试缺绑定时 fail-closed；重新生成类型文件会变回必选，测试夹具需同步提供桩）。
- **异步任务管道（Queues 的实际用途）**：Note 编辑器「AI 助手」提交任务（`POST /api/ai/tasks`）→ 校验（启用开关 → 条目守卫 → 复用 → 在途去重 → 每日预算）→ 入 `ai_tasks` 表（status=queued）→ 队列消息（携带正文，正文上限 32k 字符以保证 128KB 消息限制）→ 消费者（`index.ts` queue 入口 → `dispatchAiQueue` 逐条显式 ack/retry）→ `env.AI.run` 推理 → 结果落库 → 前端轮询（1.5s，上限 90s）。重试语义：attempts < 3 时 `message.retry()`；终态失败落库后 ack。
- **模块分层**：`shared/contracts/ai.ts`（设置/模型/任务/用量契约 + `normalizeAiSettings` 双端共用）→ worker `db/ai.ts`（SQL 独占）→ `services/aiService.ts`（业务）→ `routes/ai.ts`（三端点）→ `index.ts` 装配（45 行，含 queue 入口）；web 侧 `services/aiSettingsService.ts`（user_settings `ai` 键，随账号同步，与外观偏好同链路，同步引擎 `applyPulledAiSettings` 挂接）+ `services/aiService.ts`（REST）+ `features/ai/`（对话框，经 `index.ts` 公共入口 import）。
- **可开关可配置（负责人指示）**：
  - 开关：设置 → AI 助手 → 启用（默认关闭；关闭时端点 409、对话框显示指引，编辑功能完全不受影响）。
  - 模型切换：候选表 `AI_MODEL_OPTIONS`（`@cf/zai-org/glm-4.7-flash`、`@cf/qwen/qwen3-30b-a3b-fp8`，**目录 ID 已核验**，当期目录两候选均在；先走通 GLM-4.7-Flash 为默认）。设置存任意合法 `@cf/...` 模型 ID，保留 FR-AI-2 的替换能力；GLM 系运行参数用 `max_completion_tokens`（max_tokens 已废弃），其余用 `max_tokens`。
  - 额度计费：`dailyCallLimit`（1–500 次/日，默认 50）应用内预算，提交与消费端双重闸门，达限 429；`ai_usage_daily` 按 UTC 日精确累计调用与输入/输出 tokens（来自模型 usage 字段）；设置节与 AI 对话框显示「今日 X/N 次 · tokens」；监控面板「本项目资源」表新增 Workers AI 行，**显式标注「本应用计数（非官方）」**，Queues 行标注操作量以官方仪表盘为准（三类口径不混淆，FR-MON-5）。
- **确认后写入（13.3 已定机制）**：摘要先会话内预览，采用 = `writeValue(markdown, "summary", text)` 写入 YAML 属性区并走统一文档更新链路（saveFullMarkdown，rev+1）；标签推荐勾选确认后 `saveItemMeta` 合并（不改动已有标签）。`force` 参数支持忽略缓存重新生成（仍受预算与在途去重约束）。同内容结果按 (user, item, kind, content_hash) 复用，不重复计费。
- **加密边界（安全红线）**：`readAiEligibleItem` 在 SQL 侧一次判定 `enc_self = 0 AND in_enc_space = 0 AND deleted_at IS NULL`，加密条目（含私人空间）404 拒绝且不入队；前端加密分支本就不渲染入口。**开放项 #1（授权流程与结果存储边界）未动**——v1 采取「加密内容整体排除」的保守默认，授权流程仍待专项设计。

## 2026-11-03：方案 A（Analytics Engine）代价核验（核验义务 ⑤ 关闭）

负责人询问方案 A 代价，按官方当期文档核验（pricing/limits/get-started/SQL API 四页）：

| 维度 | 免费档 | 对 Menote 的实际影响 |
| --- | --- | --- |
| 写入额度 | 100,000 data points/日（超出 $0.25/百万，官方注明当期尚未实际开账单） | 每请求 1 个数据点，本应用量级远低于上限；额度为账户级共享，与 Workers 请求同口径展示 |
| 读取额度 | SQL API 10,000 次/日（每次 POST 计 1） | 真正的设计约束：必须低频拉取（随方案 B 的 monitor-pull，~4 次/日）而非面板实时直查；即使用户高频手动刷新也差两个数量级才触顶 |
| 数据保留 | 3 个月 | 长期历史仍需 D1 快照（方案 B）兜底，A 不能单独承担趋势回看 |
| 性能 | fire-and-forget：不需 await、不需 waitUntil，runtime 后台写，不阻塞响应；不占 D1 写行、不算 subrequest、CPU 微秒级（官方未给数） | **比现状更省**：1% 采样每次命中要一条 D1 INSERT（占 D1 写额度 + ledger 校验查询），AE 写入零本地资源 |
| 结构 | 1 index（≤96B）+ 20 blobs（单点共 ≤16KB）+ 20 doubles；单次调用 ≤250 点 | 放路由/方法/状态/CPU/D1/R2 计数足够；不能当日志用 |
| 抽样 | 高流量写入侧自动降采样，查询按 `_sample_interval` 加权 | 本应用量级不会触发，但查询 SQL 必须按官方公式写，否则结果失真 |
| 读取鉴权 | SQL API 需 `Account Analytics Read` Token | **最大的实际代价**：与 G12 增强模式同权限（可复用同一 Token），但意味着 AE 数据不能服务「零配置基础模式」——无 Token 用户看不到，需保留轻量本地兜底或接受「无 Token 无精确数据」 |

**结论**：性能代价 ≈ 0（优于现状），写入额度充裕；真实约束是读取要 Token（破坏零配置口径）+ 保留仅 3 个月。因此维持调研文档建议：A 与 B 组合（AE 精确写入 + monitor-pull 低频落 D1 快照），是否替换现有 1% 采样及零配置兜底形态，仍待负责人裁定（开发计划 §3-1）。核验结论已回填调研文档 §6。

## 2026-11-03（续）：Token 能否首部署自动获取 —— Analytics SQL Binding 修正方案 A 论据

负责人追问「Account Analytics Read Token 能否首次部署时自动获取」，核验结论分两层：

1. **AE 查询：不需要 Token 了（方案 A 关键论据修正）。** 2026-10 Cloudflare 上线 Analytics SQL API Workers Binding（Beta）：`wrangler.jsonc` 声明 `{ "analytics": { "binding": "ANALYTICS_SQL" } }`（Wrangler ≥4.145，当前 4.156 满足）→ Worker 内 `env.ANALYTICS_SQL.query({ query, params })` 直查自账户数据集，**隐式鉴权、无 Token、无 HTTP 外呼**，可查 `events.analyticsEngine."<dataset>"`（受账户 AE entitlement 约束）；Log Explorer 数据集不支持；错误带 `retryable` 标记但不自动重试。绑定随部署创建，真正「首次部署自动获得」。**未核**：binding 免费计划可用性、调用是否计入 SQL API 10k 次/日 或独立计量、Miniflare 本地支持 → 新增核验义务 ⑨，并入 W4 PoC。
2. **GraphQL 官方数据（D1/R2 用量、Billable Usage、Workers 请求/CPU）：不能自动获取。** 根因是鸡生蛋：创建 API Token 需要已具 `API Tokens Write` 权限的凭据调 API；Worker 运行时无任何环境凭据可自证；Deploy to Cloudflare / Workers Builds 只自动预配资源绑定（D1/R2/Queue/AI/Analytics SQL）并让部署者填 Secret 值，不铸造带权限的 API Token。故 13.4 定稿「增强模式 Token 用户自愿配置、不作为一键部署前置」维持不变——平台模型决定，非实现取舍。

**影响**：方案 A 从「推荐 PoC 后再定」升级为「推荐方案」（调研文档 §4 已同步修订）：AE 写入（免费 10 万点/日）+ binding 零 Token 查询 → 基础模式即可「本应用精确计数」零配置可用；GraphQL 官方账户数据仍走可选 Token。原「形态 2 保留极简本地兜底」不再必需，但 3 个月保留期限制仍由方案 B 的 D1 快照兜底。

## 2026-11-03：概述和标签一起失败（0.1.9）

默认模型 `@cf/zai-org/glm-4.7-flash` 的 `enable_thinking` 默认为 true。调用只给了 512 个 `max_completion_tokens`，思考会把额度用完，正文为空，概述变成「模型未返回内容」、标签变成「无法从模型输出解析标签」。现对 GLM 传入 `chat_template_kwargs.enable_thinking: false`，并丢掉残留的 `<think>` 段。另外两处会让两个按钮显示同一句「AI 任务提交失败」：响应体被读了两次，服务端文案丢失；开启开关后 `requestSync` 抢不到锁就跳过，服务端仍认为未启用或笔记不存在。提交前改为 `flushSync` 等锁跑完一轮，失败文案改为已读到的 `error`。版本 `0.1.8 → 0.1.9`。线上要这次修复，仍须合并 main 后由 Workers Builds 部署。
