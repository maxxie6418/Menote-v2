# EdgeEver 其余规则可迁移清单（TP14 P4）

基于固定 commit `c0668ebeff327c5dc6d17128bb59df7190c7f5f0` 的 `apps/extension/src/` 盘点。形态判定依据 TP14 讨论的三档准入：静态 DOM 可表达 → 声明式模板；需展开交互/JSON 状态/格式重写/身份校验 → 命令式管线（capture+clip）。

## A. 适合声明式模板（建议下批批量，热更新可维护）

| 平台 | 上游依据 | 成本 | 备注 |
| --- | --- | --- | --- |
| V2EX | `v2ex-clip.ts`（2.6KB，静态帖子页） | 低 | 可直接手写 ClipTemplate（importer 只解析 article-clip.ts，不覆盖独立 reader）；含「楼主/多层回复」结构，模板剪主楼即可 |
| Hacker News | `hacker-news-clip.ts`（2.3KB） | 低 | 标题/正文/分数/时间均静态；URL+ID 二次确认逻辑模板层无（损失可接受） |
| 少数派 sspai | `article-clip.ts` 分支 | 低-中 | importer 可转存（曾以 sspai 为示例）；「更新块引用排版」丢失，正文 80 分可用 |
| 掘金 juejin | `article-clip.ts` 分支 | 低 | 同上，静态 article 页 |
| 豆瓣 douban | `douban-clip.ts`（6.5KB） | 中 | 影评/书评/日记多形态，建议按路径拆多条模板 |

## B. 适合命令式管线（第二批/第三批）

| 平台 | 上游文件 | 成本 | 备注 |
| --- | --- | --- | --- |
| 微信公众号文章 | `article-clip.ts` wechat 分支 + `wechat-headings.ts`/`wechat-picture-state.ts` | 中-高 | 用户高频；Menote 已有懒加载图修复；需搬「关注引导清理/代码块修复/图片消息态」逻辑（`cleanWechatContent` 约 60 行），建议第二批 |
| Reddit | `capture-reddit.ts` + `reddit-clip.ts`（8.6KB）+ target | 中 | 同四平台三件套形态，含 MAIN world 状态；建议第二批 |
| 即刻 Jike | `jike-clip.ts`（15.5KB）+ `jike-web-state.ts` | 中-高 | 动态信息流卡片，需 MAIN world 状态；建议第二批 |
| Medium | `medium-content.ts`（5.5KB）+ `article-platform.ts` | 低-中 | 正文为主，paywall 降级已有上游逻辑 |
| Substack | `substack-content.ts`（2KB） | 低 | 同上 |
| 雪球 xueqiu | `xueqiu-clip.ts`（4.8KB）+ feed | 中 | 动态帖；金融场景对 Menote 用户或有需求 |
| 小宇宙 xiaoyuzhou | `xiaoyuzhou-clip.ts`（5.4KB） | 中 | 播客页，MAIN world 状态（show notes） |

## C. 暂缓/不迁（附理由）

| 对象 | 上游文件 | 理由 |
| --- | --- | --- |
| Facebook/LinkedIn/Threads/Bluesky | `social-clip.ts`（39.5KB）+ `capture-platform.ts` | 大块社交管线，登录墙普遍，维护成本高；按需再评估 |
| Instagram | `instagram-clip.ts`（2KB） | 强登录墙 + 图片签名，投入产出比低 |
| BOSS 直聘 | `boss-clip.ts`（4.4KB） | 笔记场景价值低 |
| 图片剪藏/区域划选 | `capture-image.ts`/`region-selection.ts` | Menote 已有附件与选区 Memo，形态不同不必对齐 |
| 视频笔记（B站/YouTube） | `video/`（目录空壳） | 上游本体未实现；产品形态（字幕/时间轴）待定，不追 |

## 建议下批顺序

1. **声明式批量**：手写 V2EX / Hacker News 模板 + importer 转存 sspai / juejin（enabled:false 入模板管理列表，人工审核启用）——全部走 ② 层，零代码发版。
2. **命令式第二批**：微信公众号文章（高频）→ Reddit → 即刻。
3. **第三批**：Medium / Substack / 雪球 / 小宇宙（按用户需求取舍）。
4. **暂缓**：社交大杂烩、Instagram、Boss、视频。

## 依赖与纪律提醒

- 每批命令式迁移沿用 TP14 流程：上游文件 verbatim 进 `src/capture/upstream/edgeever/`、UPSTREAM_NOTICES 逐文件登记、`docs/adapters/` 记录 + 样本断言、registry 注册即自动登记到应用模板管理列表。
- 声明式批量的 importer 产出均 `enabled:false` + 转译报告，审核通过再启用（既有流程）。
- 微信公众号若迁移，`cleanWechatContent` 等清理逻辑属上游派生代码，须登记；Menote 现有懒加载修复保留为 wrapper 层能力。
