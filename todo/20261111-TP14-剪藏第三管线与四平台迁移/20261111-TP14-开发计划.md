# TP14 开发计划：剪藏第三管线与四平台迁移

日期：2026-11-11 ｜ 状态：进行中 ｜ 前置：TP3（浏览器剪藏插件，扩展 0.1.32）

## 1. 目标

为剪藏扩展接入第三条提取管线（`capture-*.ts` + `*-clip.ts` 命令式三段式，源自 EdgeEver 架构），迁移四平台结构化剪藏（GitHub README、知乎、推特/X、小红书），并将迁移产物登记进应用模板管理列表（显示管线类型）。产出 EdgeEver 其余平台规则调研清单。

## 2. 范围与非目标

**范围内**：
- 扩展：background 分流 dispatcher、快照消息协议、MAIN world 状态读取助手、per-entry IIFE 构建；四平台 capture+clip 对（上游 EdgeEver 源文件近原样引入 + wrapper 收口）。
- Menote-v2：`ClipTemplateV1` 增加 `pipeline` 与 `adapter` 元数据（零 D1 迁移，`template_json` 为 JSON 列）；MCP 新工具 `register_capture_adapters`（扩展幂等上报内置适配器元数据）；ClipTemplateManager 管线徽标列 + 命令式条目只读展示与启停。
- 其他规则调研清单（文档交付，供负责人勾选下批）。

**范围外（本轮明确不做）**：剪藏笔记 frontmatter 透传 extractor（负责人定：管线标注只进模板管理列表）；简单站批量转存；Reddit/即刻等更多命令式平台；target 右键标记（时间线存单条）。

## 3. 关键设计决策（已与负责人确认）

1. **统一「剪藏规则」注册表**：管线是规则的属性。命令式条目只存元数据（id/版本/匹配站点/上游 commit）+ 启停开关，不假装可编辑代码；声明式条目维持现有编辑体验。
2. **同步协议**：扩展沿用 15 分钟 TTL 同步，拉规则之外幂等上报适配器元数据；`enabled` 存服务端，网页停用下发扩展 dispatcher 生效。
3. **出口契约不变**：三段式收口到 `CaptureResult` → 现有队列/outbox/MCP `clip_page` 管线零改动。
4. **AGPL 纪律**：上游源文件进 `src/capture/upstream/edgeever/`（逐文件登记 UPSTREAM_NOTICES.md，含固定 commit 与变更日期），扩展子树 AGPL-3.0-only 发行；wrapper 放 `src/capture/platform/`。
5. **三档准入**：新站点默认声明式模板；出现展开交互/JSON 状态/格式重写/身份校验需求才升命令式。四平台全部过线。

## 4. 实现顺序

| 序 | 工作项 | 交付 |
| --- | --- | --- |
| P0 | 扩展骨架：dispatcher、快照协议、MAIN world 助手、构建 | 平台管线可注册、可分流 |
| P1 | GitHub README 对（README 全文 + 相对 URL 重写，与上游「摘要卡」格式分歧按 Menote 需求） | 四平台首个全链路贯通 |
| P2 | 契约 + Worker + Web：pipeline 字段、register_capture_adapters、模板管理列表徽标 | 迁移规则进应用列表 |
| P3 | 知乎 → 推特/X → 小红书（登录墙/签名图降级策略见 §5） | 四平台齐 |
| P4 | EdgeEver 其余规则调研清单 | 文档 |
| P5 | 测试、文档联动、版本与提交 | DoD |

## 5. 验收与降级边界

- 每平台：`docs/adapters/` 记录（上游 commit、支持范围、提取契约、已知限制）+ 脱敏样本断言 + UPSTREAM 登记。
- 知乎：未登录折叠态剪藏不全时，`domComplete=false` 应有可感知提示。
- 推特/X：未登录页面基本不可用——明确「需登录」限制，时间线/多推线程不在本期。
- 小红书：正文以 `__INITIAL_STATE__` 为主、DOM 兜底；签名图转存失败保留原 URL（现有降级），产品接受此边界。
- 性能：静态路径全同步无等待；展开交互的等待发生在注入脚本内部，不拖慢普通站。

## 6. DoD

四平台可在登录态下剪藏并进入收件箱；模板管理列表可查全部规则及管线类型并可启停命令式规则；扩展与应用测试基线全绿；AGPL 登记完整；调研清单交付。
