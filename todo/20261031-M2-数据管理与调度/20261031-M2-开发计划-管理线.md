## G1 认证会话与用户隔离

- **状态**：实现完成（2026-10-31），待负责人复核；内容接口越权回归随 G5/G6 补测
- **需求与输入**：FR-USR-1～3/5、C-7；[工程设计第 4 章](../../wiki/Menote_V2_工程结构与组件设计_v0.2.md)（middleware：session/csrf）；M1 交接记录「公开监控接口为安装级聚合，M2 接入会话鉴权前不得接正式数据」。
- **依赖**：无（M1 骨架、迁移框架与自检已就绪）。

**范围与实施**：

1. 登录会话：用户名+密码登录，`AUTH_PEPPER` 参与口令哈希（不写入日志、响应与页面）；会话 cookie（HttpOnly/SameSite）+ session 中间件 + CSRF 保护；登出与会话过期处理；**登录失败次数限制（D1 持久：10 次/15 分钟 + isolate 洪峰守卫，负责人指定为主防线）**。
2. **首个 owner：初始化引导页创建（负责人 2026-10-31 选定）**——库中无任何用户时首次访问显示引导页，部署者创建 owner 后引导页永久不可重入、注册自动关闭；首用户创建须原子化（事务/唯一约束，防并发抢注出双 owner）；之后注册默认关闭，owner 可开启（开关+有效期控制，FR-USR-1）。用户停用/删除细则属开放项 #13，M2 仅落地开关与账号存储，不做未定稿的管理 UI。
3. 用户隔离落地（FR-USR-2/3）：worker services/db 全部业务查询按 `user_id` 过滤（服务端查询层隔离，非 UI 过滤）；监控与用户设置接口接入会话鉴权与用户归属（消除 M1 安装级测试模式）；越权访问统一拒绝响应。
4. 前端：初始化引导页（零用户时可达）、登录页、会话状态与失效引导；UI 经 services 访问会话，不直连网络与密钥。

**验收与交付**：

- 引导页仅在零用户时可达，创建 owner 后不可重入（防后来者经引导页夺权）。
- 双账号实测：A 无法读取/写入/枚举 B 的内容、附件、设置、监控配置；未登录访问敏感接口被拒；服务端查询层隔离。
- 注册关闭时新注册被拒；owner 开启后可注册第二个账号并完成隔离实测。
- 缺 `AUTH_PEPPER` 时认证功能 fail-closed（复用 M1 自检语义）；密码、凭据与密钥材料不出现在日志/响应。

## G7 加密与恢复码（G4 定稿后实施）

- **状态**：未开始
- **需求与输入**：FR-ENC-1～8、C-7。
- **依赖**：G4 定稿；体验线 E2；G5（附件加密）。

**范围与实施**：

1. 密钥实现：私人空间主题密钥包装单篇密钥；普通主题单篇独立内容密钥；AES-GCM + 定稿 KDF；封装版本字段（FR-ENC-1/2/8）。
2. 三凭据分离（登录 ≠ 空间密码 ≠ 单篇密码，互不连坐）；解锁 ≠ 分享（本机解锁不放宽服务端访问控制，FR-ENC-3/7）。
3. 锁定策略（FR-ENC-4）：新会话默认锁定 + 不活动超时（默认 15 分钟、可配置）+ 手动锁；单篇默认离开即重锁（未保存改动的安全处理）。
4. 标题明文（FR-ENC-5）：锁定态列表可辨识、可按标题检索；正文/附件/缩略图/历史/缓存只处理密文；体验线 E5 检索与列表适配锁定态。
5. 恢复码（FR-ENC-6）：启用（展示一次）、凭码解锁/重设密码、换码统一重包装（含中断恢复与多设备旧包装）；遗失=永久不可解的强提示；单码泄漏爆炸半径 UI 明示。
6. 附件加密：密文入 R2；解锁后随行明文导出，未解锁不导出或明确提示（与 G5 导出联动，FR-SYNC-9）。

**验收与交付**：三凭据互不影响；未授权不能经任何接口取得正文/附件明文；锁定态检索/缓存/缩略图/历史均为密文；恢复码解锁/重设/换码全链路可用。

## 专项设计 — 同步契约与边界（G2 评审稿，待负责人确认后定稿）

依据：主文档 6.1（存储分工、单条记录 outbox）、需求说明书 FR-SYNC-3/4/5、NFR-1/4、归档《平台能力功能设计 v0.2》第 0.3/2 章（主文档第十章认可的功能级设计）与 M1 数据契约。本设计关闭需求开放项 #7；实现归属 G6，清理归属 G10。

### 1. 版本字段与不变量

| 字段 | 位置 | 语义 |
| --- | --- | --- |
| `rev` | items.rev | 正文乐观并发；每次正文写 +1 |
| `meta_rev` | items.meta_rev | 标题/标签/归属/状态等元数据并发；每次元数据写 +1 |
| `content_hash` | items.content_hash | 正文 sha256；重放判定与附件引用对齐 |
| `last_device` | items.last_device（0022 新增） | 服务端记录最近写入设备，用于「别处改过」与 session 封存触发 |
| `sync_log.seq` | 0022 新增表 | 服务端单库单调递增；**拉取游标唯一基准**（主题/条目/墓碑统一） |
| `operation_id` | 客户端生成 UUID | 幂等去重；UI 业务命令与 MCP（M4）共用 |
| `deviceId` | 客户端常量（localStorage 生成 UUID） | 设备标识，随推送携带 |

不变量：`rev`/`meta_rev` 只增不减；单操作 = 单 D1 batch 事务（校验、写入、sync_log、operations 记录同生共死）；`sync_log` 只追加不改写；服务端全部查询按 `user_id` 隔离（G1 语义）。

### 2. 服务端数据结构（0022 迁移，G6 实施）

1. `sync_log (seq INTEGER PK AUTOINCREMENT, user_id, entity IN ('item','topic'), entity_id, op IN ('upsert','delete'), rev, meta_rev, created_at)` + 索引 `(user_id, seq)`——每次成功写操作追加一行。
2. `sync_operations (user_id, operation_id, entity, entity_id, result, rev, meta_rev, content_hash, created_at, PRIMARY KEY(user_id, operation_id))`——幂等重放依据；随清理期滚动删除。
3. `items` 加 `last_device TEXT`；`attachments` 加 `orphaned_at INTEGER`；`user_settings` 加 `rev INTEGER NOT NULL DEFAULT 0`、`updated_at INTEGER`（设置与条目同用乐观并发）。
4. 墓碑 = `sync_log` 中 `op='delete'` 的行；软删本体（`deleted_at` 非空行）保留至清理期。

### 3. 推送协议

- `POST /api/sync/push`：`{deviceId, operations[]}`，单请求 ≤ 10 操作。操作携带 `operationId / entity / entityId / action(upsert|delete) / baseRev / baseMetaRev / contentHash?（正文操作必带）/ payload / attachmentRefs?`（`attachmentRefs` 缺省 = 不动引用表；批量路径同样携带，防断网重连引用漂移）。
- **单操作独立 D1 batch 事务**：幂等检查 → `baseRev/baseMetaRev` 前置检查 → 应用写入 → 追加 `sync_log` → 记录 `sync_operations`。**操作间互不回滚**：批内某操作冲突不影响其余操作，逐操作返回结果；未应用的操作由客户端随下次推送重试。
- 响应逐操作：`applied | duplicate | conflict` + `rev/metaRev`；`conflict` 附 `detail {rev, metaRev, contentHash}`（服务端当前值）。
- outbox 行结构（本地）：`seq 自增 / entity / entity_id / op / base_rev / base_meta_rev / retries / next_retry_at / last_error / queued_at`；**正文不复制进队列**，指向本地草稿（编辑中约 2 秒落盘），上传成功且与草稿一致才清除；队首同实体同动作的连续操作可合并（自动保存多 tick 合一）。
- 失败分派：可重试（网络/5xx/429）指数退避 1/2/4/8s…±20% 抖动封顶 60s；不可重试（403/404/422）进「上传失败」列表，不阻塞队列、界面可见 `last_error`。
- 触发时机：应用打开、写入成功后 300ms 防抖、标签页重新可见、网络恢复、前台每 5 分钟；不做实时推送。

### 4. 拉取协议

- `GET /api/sync/pull?cursor=<seq>` → `SyncPage`（M1 类型保留）：`{items, topics, tombstones, settings, nextCursor, hasMore, fullResync}`。
- 每页 ≤ 200 实体，按 `sync_log.seq` 升序；客户端循环推进至 `hasMore=false`，**每页落库即持久化游标**；单轮防御上限 50 页。
- 落库顺序：**先墓碑、再条目/主题**（防同页既删又更新残留旧行），设置最后；设置不参与游标、每页附带，本地有未上传改动或服务端 rev 未变时跳过。
- `cursor` 早于 `sync_log` 最老保留 seq → `fullResync=true`：服务端按当前表状态直接生成分页（不经 sync_log），客户端**清空已同步内容重拉、游标归零；outbox 队列与未上传草稿保留**。

### 5. 冲突裁决（FR-SYNC-5 细化）

1. **重放判定**：正文操作的 `contentHash` 与服务端当前 `content_hash` 一致且 `baseRev` 落后 → 判定为响应丢失的重放，返回 `duplicate` + 服务端当前 rev，不产生新版本。
2. **Note 正文真冲突**：hash 不一致 → 409 + detail；客户端将本地稿另存**冲突副本**（命名含日期时间与设备、记录与原条目关联），原条目采纳服务端版本并失效正文缓存——「当前 + 冲突副本」人工裁决，不静默覆盖、不自动文字合并。
3. **元数据冲突**：服务端胜出、不生成副本，客户端按 detail 重拉该实体回填 `meta_rev`。
4. **Memo 结构化字段**：字段级 last-writer-wins（以服务端接收时序为准）；Memo 无冲突副本形态。
5. **删改并发（复活）**：编辑胜——软删行收到合法正文/元数据写时恢复 `deleted_at=NULL`、`rev/meta_rev` 继续 +1，`sync_log` 追加 `upsert`；版本历史保留。
6. **主题软删不级联条目**（默认口径，待确认）：条目保留归属字段，主题删除仅影响树显示与可选性；主题恢复后条目重现。永久删除主题时其下条目按「无归属 → 草稿箱」处理（另见决策点）。

### 6. 幂等

- 服务端按 `(user_id, operation_id)` 去重：重放返回原结果 `duplicate` + 记录的 `rev/metaRev/contentHash`。
- `sync_operations` 记录保留期与墓碑一致（90 天）；客户端 operation_id 一次本地状态变更一个 UUID（outbox 合并不改变 operation_id——合并后的操作沿用队首 op 的 operation_id）。

### 7. 墓碑与清理（G10 cleanup 实施）

- `sync_log`、`sync_operations` 保留 **90 天**；游标落后超过保留期的端拉取时触发 `fullResync`。
- 软删条目/主题本体保留 **90 天**后物理删除（回收站「永久删除」即提前走同一路径：删行 + 追加 delete 墓碑传播）。
- 孤儿附件：`ref_count=0` 时置 `orphaned_at`，**30 天**后真删 R2 对象与行（FR-SYNC-8 定稿值）。

### 8. 多标签页与广播

- Web Locks 主锁（`ifAvailable`，抢不到不排队）：所有标签页都可写本地库与 outbox，**仅持锁者推送与拉取**；不支持 Web Locks 的环境退化为直接执行。
- BroadcastChannel 事件不带内容：`item-updated`、`cursor-advanced`（各页收到后只重读本地库）；隐私锁状态事件归 encryption 模块订阅；无 BroadcastChannel 环境降级为空实现。

### 10. 时序案例清单（G6 实测验收用例）

1. 断网编辑 → 恢复后按 outbox 顺序补传，附件引用不漂移（`attachmentRefs` 随操作上报）。
2. 双端并发改同一 Note 正文 → 一端获 `conflict`，产生冲突副本、原稿采纳服务端版本，无静默丢失。
3. 双端并发改元数据 → 服务端胜、无副本、`meta_rev` 回填。
4. 一端删、一端编辑并发 → 编辑胜（复活），历史版本保留，两端最终一致。
5. 同 `operation_id` 重复提交（响应丢失重放）→ 返回 `duplicate`，不产生双份记录。
6. 正文 hash 相同的重放（服务端已应用但响应丢失）→ `duplicate` 落账，不新增版本。
7. 长期离线（游标超过保留期）→ `fullResync`，outbox 与未上传草稿保留，清空重拉后一致。
8. 多标签页并发 → 仅持锁标签页推送/拉取，其余标签页经广播重读本地库。
9. 拉取分页中途服务端有新写入 → 游标按 `sync_log.seq` 严格推进，不重不漏。
10. 删除主题 → 条目不级联（按确认口径），树与清单表现一致。
11. 设置并发修改 → rev 乐观并发，服务端胜，无双写。
12. 推送批内混合（部分冲突部分成功）→ 成功者生效、冲突者返回 detail，队列续传不阻塞。
