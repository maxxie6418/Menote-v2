### ① 加字段不再用浮层

- 根因：`.mn-tabledoc-addform` 是 `position: absolute` 的浮层，锚点是表头最右的 `.mn-tabledoc-addcol`，而它的父级 `.mn-tabledoc-scroll` 是 `overflow: auto` 的滚动容器——浮层超出就被裁掉（截图里只剩一截）。
- 改法：去掉表头尾部的「+」列与占位列（`.mn-tabledoc-addcol` / `.mn-tabledoc-addspacer`），加字段统一由工具条「添加字段」触发，表单作为**工具条下方的整行**常驻（`.mn-tabledoc-addform` 改为静态 flex 行：字段名输入 + 类型胶囊 + 添加/取消）；类型选项在表单里改成胶囊描边（选中橙边 + 浅橙底），不再是裸文字。
- 脚手架态（历史空白表格）同样把表单移到按钮下方，宽度撑满，不再挤在 `.mn-tabledoc-addanchor` 里。

### ② 转表格默认「名称」列

- `contentService.setItemForm` 增加种子：空白笔记 → 表格时写入 `fields: 名称: {type: text}` 与只有表头 `| 名称 |` 的空表；表格种子 → 笔记时把正文清回空白。
- 新增 `defaultTableSeed()` 与 `isDefaultTableSeed()`：后者用「正文只有一张单列空表且列名为名称」判定，使种子不触发 FR-TBL-9 的形态锁，来回切换不会卡住。
- 内容变更同步：`rev + 1`、重算 `contentHash`、outbox 带 contentHash 入队；不改变则维持原样。

### ③ 设置窗口放宽

- `--app-settings-dialog` 40.5rem(648) → 46rem(736)，`--app-settings-height` 33.125rem(530) → 38rem(608)；内容区由约 442 增到约 530，备份表单稳定两列。

## 2026-11-02：第三批（阅读宽度三档）

- **来源**：负责人看过版心后提出——把现有宽度定义为「窄」，再出「加宽」「撑满」两档，可在设置里选。
- **实现**：
  - 新增 `src/web/src/lib/measurePreference.ts`（`narrow | wide | full`，localStorage `menote.measure`，写 `<html data-measure>`；`narrow` 视为默认、不写属性），与 `lib/fontPreference.ts` 同模式。
  - `index.html` 引导脚本补一段解析，首屏直接落属性，避免切到宽版后闪一下窄版。
  - `tokens.css` 末尾新增 `:root[data-measure="wide"] { --app-doc-measure: 56rem }` 与 `:root[data-measure="full"] { --app-doc-measure: var(--app-full-size) }`；默认仍是 42rem。
  - 表格形态的版心从固定 56rem 改为 `max(版心, 56rem)`，即窄档下表格仍拿 896、宽档与撑满跟随设置。
  - 设置·外观新增「阅读宽度」下拉（窄 / 加宽 / 撑满），即时生效并持久化。
- **顺带修正**：`.mn-setrow > div:first-child` 改为 `flex: 1 1 var(--app-field-width)`，说明文字自己折行、控件留在右侧同一行——原来文字一长，下拉就被挤到下一行左侧。
- **已知边界**：文档栏宽度 = 视口 − 248（侧栏）− 340（清单）− 68（内边距）。窗口越窄，`加宽` 与 `撑满` 越会重合——文档栏本身只有那么宽。按 1440 视口（文档栏内容区 784）实测：窄 672 有留白，加宽/撑满都是 784；按 1624 视口估算为 672 / 896 / 968，三档才能拉开。设置项提示文案已写明这一点。
- **验证**：无 `node_modules` 未跑 build；用真实样式表在 1440×520 下渲染三档截图核对（`data-measure` 分别取 narrow / wide / full），属性与预期一致、无样式错乱。
- **版本**：仍与并行中的 `0.0.36` 同批，未单独递增。
