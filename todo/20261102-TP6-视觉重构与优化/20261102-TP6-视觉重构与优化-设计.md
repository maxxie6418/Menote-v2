# TP6 视觉重构与优化 · 设计

- **定位**：M2 体验线收尾 → M3 的界面视觉专项。只处理"看起来和读起来难受"的版式问题，不改业务逻辑、不动数据结构、不动 Memo 既有形态。
- **触发**：负责人 2026-11-02 反馈"编辑器和表格模式页面布局很差：要么弹窗内容被裁剪，要么工具栏样式不明显，而且文章左右挤满了不方便预览"，要求先出方案再执行。
- **对照页**：[preview/index.html](preview/index.html)（左 0.0.34 / 右 0.0.35，同一 mock 结构 + 各自真实样式快照）。

## 1. 诊断

诊断方式：本机无 `node_modules`（`pnpm install` 因 registry 超时失败），运行中的应用起不来，因此用仓库真实样式表做静态复现——同一份 mock 结构分别套新旧样式渲染，再逐条回到代码里确认根因。

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | 弹窗内容被裁剪 | `.mn-dialog` 宽度沿用登录卡的 `--app-auth-card-width`（352），且没有 `max-height`；`.mn-overlay` 只是 `position: fixed` 不带滚动，弹窗高于视口就上下被切且滚不到 |
| 2 | 弹窗主次失衡 | `.mn-dialog-actions` 不换行，`.mn-auth-submit` 带 `flex: 1`，主按钮被拉满整行 |
| 3 | 表格 6 列只能看 2～4 列 | 同上窄宽度 + 单元格最小宽 176，横向滚动条几乎不可见 |
| 4 | 工具栏样式不明显 | `.mn-formatbar` 是 16 个 11.5px 纯文字按钮，无图标、无分组边界；`.mn-formatbtn[aria-pressed]` 底色等于页面底色，**选中态实际不可见** |
| 5 | 工具栏滚走 / 滚轮不跟手 | `.mn-docbody` 与 `.mn-editor-host` 都是 `overflow-y: auto`，双层滚动 |
| 6 | 文章左右挤满 | 文档区没有版心上限，1440 宽时每行约 55 汉字、1920 更差；标题 32 与属性区几乎贴合 |
| 7 | 预览与编辑排版不一致 | 预览根类名是 `.md-body`，而 `markdown.css` 写的是 `.markdown-content`——**预览态此前完全没有排版**，退回浏览器默认样式 |
| 8 | 表格页缺信息层级 | 没有字段/行计数与顶层操作；行号列 30 像素塞不下拖拽+序号+删除；表头 `sticky` 挂在不滚动的容器上，长表滚动就丢表头 |

## 2. 决策（负责人 2026-11-02 确认）

| 决策点 | 结论 |
| --- | --- |
| 正文版心 | **672**（`--app-doc-measure`），14px 字号约 48 汉字/行；表格形态放宽到 896（`--app-doc-measure-wide`） |
| 弹窗 | **三段式 + 宽度档位**：标题固定 / 中段滚动 / 操作固定；480 / 640 / 864 三档，最高 `100dvh - 48` |
| 格式栏 | **图标化 + 分组 + 吸顶**：16 个 lucide 图标，中文留在 title/aria-label，行内｜块级分隔，橙底选中态 |

## 3. 规范落点

- 版心与标题：`--app-doc-measure` / `--app-doc-measure-wide` / `--app-doc-title-size`（36），`.mn-docbody > *` 统一限宽居中；表格形态由 `data-form="table"` 切换宽档。
- 弹窗：`--app-dialog-width-md/lg/xl`、`--app-dialog-max-height`；`.mn-dialog-head` / `.mn-dialog-body` / `.mn-dialog-actions` 三段。
- 格式栏：`--app-formatbtn-size`（24）；选中态 `--app-accent-subtle` + `--app-accent-fg`（DESIGN §2 允许的强调色文字用法，非正文）。
- 表格页：`--app-table-cell-min`（7.5rem）、`--app-tabledoc-rownum-width`（46）、`--app-tabledoc-max-height`（62dvh）。
- 滚动条：新滚动区（`.mn-dialog-body`、`.mn-tabledoc-scroll`）登记进 `scrollbar.css` 的 `scrollbar-gutter: stable` 清单，与清单/文档区同一套发丝线滚动条。

## 4. 验收标准

1. 1440 / 1280 / 1024 三档下，正文行宽落在 45–50 汉字，标题、属性、标签、格式栏、正文同一条左边缘。
2. 1024×600 下表格结构化编辑弹窗完整可见：标题与操作行常驻，中段可滚，任何一列都能滚到。
3. 格式栏在 1440 下不折行、在窄栏按整按钮折行，滚动时吸顶；选中态可辨。
4. 表格页：6 列在 896 版心内不产生横向滚动；长表滚动时表头不丢。
5. 预览与编辑的标题字号、正文行高、列表缩进同源（md-* token）。
6. 样式全部走 tokens；`src/shared/test/structure.test.mjs` 的样式字面量门禁通过。

## 5. 边界

- 不引入新的设计语言：只用既有 tokens 与 DESIGN.md 已定的形态（版心是新增约定，已回写 DESIGN §5.1）。
- 不改 Markdown 解析、表格写回、加密流程等业务路径；改动仅限样式表、弹窗包裹结构、图标映射与表格页工具条。
- Memo 视图的排版不在本任务包内（TP5 负责），移动端只做必要的触控尺寸与横向滚动适配。
