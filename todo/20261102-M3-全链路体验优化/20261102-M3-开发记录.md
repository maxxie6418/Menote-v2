## 2026-11-03：原生下拉弹层跟应用主题

- **现象**：设置里的「每小时 / 每 6 小时 / 每天」以及页面上其他 `<select>`，收起态是深色，展开的选项列表却是系统浅色。
- **原因**：`:root` 写的是 `color-scheme: light dark`，Windows 弹层跟系统走，不跟 `data-theme`。
- **改法**：`data-theme="light|dark"` 把 `color-scheme` 收成单一值，并写到 `select` / `option` 上。选项背景用表面色，选中用 `--app-selected`。不改各处下拉的业务选项。版本未再升。

## 2026-11-04：属性区候选值编辑（单选/多选）

- **来源**：负责人反馈表格属性里把类型设成「单选」时，只能加一个候选值：回车不能换行，中英文的逗号分号都不认，只能一次填一个。问能不能改成空格或中英文分号，看哪个方便。
- **分隔符取舍**：**空格不作分隔符**——候选值本身常带空格（"In Progress"、"待评审 重要"），按空格切会把值切碎；**分号最合适**——一次键入、视觉上与值内可能出现的逗号分得开，中文输入法直接打「；」即可。最终口径是**换行、中英文分号、中英文逗号都认**（逗号保留是为了不破坏既有的「逗号分隔」写法与老数据），解析统一走 `lib/frontmatter.ts` 的 `parseOptionList`：去首尾空格、滤空、去重。
- **实现**：属性区的候选值编辑器从单行 `<input>` 改成多行 `<textarea rows={3}>`（回车即另起一行，与表格列设置里的候选编辑一致），候选回显改为每行一个；新增样式 `.mn-proptextarea`（走 tokens），`.mn-proptype` 允许换行，候选框独占一行铺满。表格列设置那侧原本就是「每行一个」的 `<textarea>`，本轮不动——它每次键入都会写回定义，若在那里把分号当分隔符，输入中途会被改写、光标跳位。
- **验证**：新增 `parseOptionList` 用例 8 项（换行/中英文分号/中英文逗号/空格不作分隔符/空项与重复项）。`pnpm -r typecheck` 全过；`pnpm test` 全绿（shared 3 / web 99 / worker 86）。另用 `draft/props-candidate-preview.html` 做静态渲染核对：编辑态属性行里类型下拉与候选框分两行、候选框铺满宽度、回车可另起一行。
- **遗留**：①候选值里不能出现逗号（逗号是分隔符）——属性区多选写回是 YAML 原生数组，本可容纳带逗号的值，但为与表格侧「禁含逗号」口径一致，本轮统一不支持；②属性区候选编辑仍是失焦提交，输入过程中不实时落库，与表格侧的逐键写回口径不同；③真实浏览器内的输入体验仍待负责人走查（静态渲染只核对了布局）。

## 2026-11-04：修复空白文档转多维表格后缺少首行首列

- **反馈与复现证据**：负责人截图显示转换后的文档落入「空白表格文档」脚手架，字段定义与 Markdown 表格均为空；此前只确认了 defaultTableSeed()，没有检查组件状态链。
- **根因**：形态切换更新了 IndexedDB 中的表格种子，但 NoteDocument 仍持有转换前的空 draft；表格组件优先读取该旧草稿，自动保存又会把它写回，覆盖已生成的种子。卸载保存 effect 还随 Item 对象变化执行，存在同类旧快照写回风险。
- **修复**：编辑器卸载保存仅在文档标识/账号变化时执行并读取最新 Item；自动保存只响应未保存的脏计数；切换表格时将服务返回的种子回填草稿；打开历史空白表格时按当前默认补成一列一行，避免已受影响的新文档继续停留在空脚手架。
- **验证**：`pnpm --filter @menote/web typecheck` 与 `pnpm --filter @menote/web build` 通过；未运行测试。
- **文档 / 版本**：对应 FR-TBL-9（口径不变）；项目版本 0.2.0 → 0.2.1。
