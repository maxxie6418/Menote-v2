## 设计方案

### 1. MCP Token 管理方案（待负责人确认）

#### 产品入口与界面

- 从账户菜单「设置」打开现有 `SettingsDialog`，左侧增加独立「MCP 接入」栏目；复用现有 `features/settings`，不另建主导航入口。
- 栏目顶部显示当前实例 MCP 服务地址（规范路径：`{当前实例 origin}/api/mcp`）并提供复制按钮。地址不含 Token，不写入 Token 数据行；在同一处可显式查看/复制已有 Token，使浏览器插件或远端 Agent 配置丢失时可恢复连接信息，不必重新创建 Token。该路径作为稳定协议端点，后续 MCP 工具服务在此挂载。
- 栏目展示 Token 列表：前缀/标识、创建时间、权限摘要、范围摘要、有效期、撤销状态、最后调用时间。当前表无名称和创建时间字段；本方案不新增自定义名称，增加 `created_at` 供列表排序/识别。
- 提供创建、查看/复制、编辑权限与范围、撤销操作。查看凭据需用户显式点击；返回响应 `Cache-Control: no-store`，前端不持久化 Token 明文。
- 创建表单可配置内容读取、创建 Note/Memo、编辑、移入回收站、附件、范围、Memo 是否纳入、URL 携带、限速、有效期。默认关闭所有读写权限；用户逐项授予。回收站仅为软删除，不提供永久删除。
- `lastUsedAt` 用“从未调用”或本地化时间展示；撤销/降权在服务端下一次请求即时生效。

#### API 与分层

| 方法 / 路径（提案） | 用途 | 身份与保护 |
| --- | --- | --- |
| `GET /api/mcp/tokens` | 列出当前登录用户自己的 Token 元数据，不回传密文或明文 | Session + `Cache-Control: no-store` |
| `POST /api/mcp/tokens` | 创建 Token 并配置权限/范围 | Session + same-origin；创建结果返回一次元数据，明文只经显式复显接口获得 |
| `PATCH /api/mcp/tokens/:id` | 更新权限、范围、有效期、限速等配置 | Session + same-origin；按 `(user_id,id)` 更新 |
| `POST /api/mcp/tokens/:id/reveal` | 显式解封并返回该用户自己的 Token | Session + same-origin；no-store；不得写日志 |
| `POST /api/mcp/tokens/:id/revoke` | 设置 `revoked_at`，立即失效 | Session + same-origin；按 `(user_id,id)` 更新 |

- 前端 `features/settings/TokenManager` → `services/mcpTokenService.ts` → Worker token-management routes → `services/mcpTokenManagementService.ts` → `db/mcpTokens.ts`；路由只做 session、same-origin、输入与 HTTP 状态映射，SQL 仅在 db 层。
- Worker 入口仅装配路由；MCP 协议调用路由与网页登录管理路由分开。协议端以 Bearer Token 鉴权，不能依赖 Web 登录 Cookie。
- 前后端共用的权限、scope、Token 元数据及 API payload 定义放在 `src/shared`；不在 UI/Worker 两侧复制类型。Token 密文明文不进入 shared Token 列表模型。

#### 数据与鉴权

- 在后续迁移中增补 `created_at`、`last_used_at` 和唯一 `token_hash`；保留现有 `token_ciphertext` 以支持 C-7 事后复显。`token_hash` 用于 Bearer 鉴权查找；明文仅在创建响应/显式复显时短暂返回，数据库仍保存 AUTH_PEPPER 派生密钥保护的密文。
- 权限名采用稳定、可审查的枚举（提案）：`content:read`、`item:create`、`item:edit`、`trash:move`、`attachment:access`。附件上传还需创建/编辑权限；附件读取/下载还需 `content:read`；不提供附件永久删除权限或工具。
- Token 创建时生成不可预测的 `mn_` 前缀随机凭据；只保存前缀、SHA-256 查找摘要及可逆密文。摘要仅用于查找，不替代授权；权限、scope、撤销、过期在每次 MCP 请求都从 D1 读取并检查。权限更新无需重签 Token。
- 鉴权成功后即更新 `last_used_at`，工具执行失败也记为调用；无效、撤销、过期 Token 不更新。管理 API/显式复显不作为 MCP 最后调用时间。
- `AUTH_PEPPER` 缺失、密文无法解开、schema 未就绪时 fail-closed；任何 Token/正文/附件明文不得进入 Worker 日志、错误响应或审计 payload。
- 保留现有审计表，所有写操作与附件上传/读取/下载按 FR-MCP-6 记操作和结果；权限变更与复显是否进入独立管理审计表，当前不作为 TP3 最小闭环要求。

#### 安全授权顺序

1. MCP 请求按 hash 查 Token，并检查有效期/撤销；成功认证后更新 `last_used_at`。
2. 每次调用读取当前 permissions 与 scope；先做工具级权限判定，再检查用户归属、条目范围、条目类型和软删除状态。
3. 私人空间及任何加密条目拒绝所有 MCP 写入/正文读取/附件访问；单篇加密内容按产品基线最多只暴露允许的标题与加密标记。附件授权不能绕过。
4. `content:read` 关闭时，不返回任何现有内容列表、正文、搜索或历史；协议发现和服务端完成授权所需的内部读取不向调用方泄露。
5. 修改权限/范围和撤销在后续请求立即生效；当前在途请求按开始授权时读取到的状态继续完成，不承诺取消已经授权执行的请求。

#### 验收门

- 设置中可创建、列出、显式复显/复制、动态修改和撤销 Token；账号间不能互见或操作。
- Token 默认无权限；关闭内容读取仍可完成 MCP 初始化与被授权的创建；降权/撤销后的下一次 MCP 调用被拒绝。
- 附件上传/读取分别受附件与内容权限约束；所有加密内容请求拒绝；最后调用时间仅在有效 Token MCP 认证后更新。
- API 失败不泄露密文/明文或内容；所有管理操作使用 no-store 和 same-origin 防护。
- 完成 migration、shared contract、Worker 路由/服务/db、设置 UI 及其单元/集成验证后，才进入浏览器扩展剪藏实现。
