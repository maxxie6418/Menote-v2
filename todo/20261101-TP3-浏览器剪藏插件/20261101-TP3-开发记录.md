## 2026-11-01：负责人追加 MCP Token 管理为前置任务

- **新增范围**：先于扩展实现 MCP Token 管理；每个 Token 独立维护相应权限，包含附件权限；权限可动态调整，并持久化展示该 Token 最后一次调用时间。计划按逐请求读取最新授权实现，使撤销/降权即时生效；`lastUsedAt` 初步按认证成功后的调用时间更新。
- **当前契约差距**：`McpToken` shared 类型与 `0012_mcp_tokens.sql` 已有 permissions/scope/有效期/撤销/加密 Token 等字段，但无最后调用时间；尚无 Token 管理 API/UI、权限更新流程或 MCP 鉴权服务。需要新增迁移字段与共享契约，并完成管理界面和逐次授权检查。
- **需求冲突待解**：现行 FR-MCP-7 明确排除附件工具。负责人已要求 Token 有附件权限；需确定附件权限实际控制的工具（上传、读取/下载、删除等）与加密附件行为，随后同步修订 FR-MCP-2/7、主文档 MCP 边界和工程设计。TP3 计划暂按“权限预留但工具范围待确认”登记，不在冲突未收口时擅自放开附件接口。
- **计划调整**：工作顺序改为附件工具边界确认 → Token 管理 → 剪藏所需最小 MCP 写入服务 → 插件骨架与通用剪藏。通用 Agent MCP 工具仍留在 M4；TP3 只提前其必要的管理面和剪藏接口。
- **保留的开放项**：记录 Note 的唯一寻址方式、来源 YAML 字段、剪藏图片/选区与首批站点仍待负责人确认。

## 2026-11-01：负责人确认 Token 读取权限与附件边界

- **产品决策**：逐 Token 的内容读取权限可关闭；关闭后不允许其知晓/列举/搜索或读取既有内容。MCP 协议和授权运行必需的内部读取不属于内容读取权限，仍可执行且不得向调用者泄露既有内容。
- **产品决策**：新增独立附件权限与附件 MCP 能力。TP3 按上传及读取/下载设计；对应操作还必须具备条目的创建/编辑或内容读取权限，受用户范围与条目可见性检查；不提供独立附件永久删除。
- **加密硬边界**：加密内容不开放 MCP 授权；无论 Token 如何配置，MCP 始终不得创建到加密空间、读取或编辑加密内容及其附件。私人空间维持完全不可见。
- **动态授权与时间**：Token 权限可动态调整，下一次调用立即采用最新配置；服务端记录最后一次认证成功的调用时间，工具执行失败仍记一次调用，无效 Token 不刷新时间。
- **规格联动**：需求说明书升至 v1.9，新增 FR-MCP-10（Token 管理）与 FR-MCP-11（附件工具），修订 FR-MCP-1/2/3/4/5/6/7/9 与 M2/M4 映射；主文档升至 v0.10，工程结构设计升至 v0.3。完整 MCP 通用 Agent 工具仍在 M4，TP3 提前实现其 Token 管理、剪藏创建和附件子集。
- **待负责人确认仍保留**：剪藏来源属性键名/可选字段、选区剪藏及首批站点；阶段二记录 Note 的唯一地址语义，以及单一 Note 追加与 FR-EXT-2 表格写入的范围调整。
