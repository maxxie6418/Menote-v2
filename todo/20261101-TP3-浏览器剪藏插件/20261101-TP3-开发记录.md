## 2026-11-01：负责人确认 Token 读取权限与附件边界

- **产品决策**：逐 Token 的内容读取权限可关闭；关闭后不允许其知晓/列举/搜索或读取既有内容。MCP 协议和授权运行必需的内部读取不属于内容读取权限，仍可执行且不得向调用者泄露既有内容。
- **产品决策**：新增独立附件权限与附件 MCP 能力。TP3 按上传及读取/下载设计；对应操作还必须具备条目的创建/编辑或内容读取权限，受用户范围与条目可见性检查；不提供独立附件永久删除。
- **加密硬边界**：加密内容不开放 MCP 授权；无论 Token 如何配置，MCP 始终不得创建到加密空间、读取或编辑加密内容及其附件。私人空间维持完全不可见。
- **动态授权与时间**：Token 权限可动态调整，下一次调用立即采用最新配置；服务端记录最后一次认证成功的调用时间，工具执行失败仍记一次调用，无效 Token 不刷新时间。
- **规格联动**：需求说明书升至 v1.9，新增 FR-MCP-10（Token 管理）与 FR-MCP-11（附件工具），修订 FR-MCP-1/2/3/4/5/6/7/9 与 M2/M4 映射；主文档升至 v0.10，工程结构设计升至 v0.3。完整 MCP 通用 Agent 工具仍在 M4，TP3 提前实现其 Token 管理、剪藏创建和附件子集。
- **待负责人确认仍保留**：剪藏来源属性键名/可选字段、选区剪藏及首批站点；阶段二记录 Note 的唯一地址语义，以及单一 Note 追加与 FR-EXT-2 表格写入的范围调整。

## 2026-11-01：准备并接入 MCP 剪藏前置服务

- **协议与运行时**：Worker 引入官方 `@modelcontextprotocol/server` v2 `createMcpHandler`，在 `/api/mcp` 提供无状态 HTTP MCP；按请求构建工具集，并在每次请求重新认证 Token，因此工具列表、权限与撤销状态采用当前 D1 值。使用 `Authorization: Bearer mn_…` 的 Menote 静态访问 Token，不使用登录 Cookie；协议发现/初始化只暴露当前 Token 可用工具，不返回既有笔记。`connection_status` 为固定无内容诊断响应，确保即使 Token 没有业务工具权限时仍可正常完成标准 `tools/list`。
- **剪藏契约与业务路径**：`src/shared` 新增版本化 `McpClipRequest` / `McpClipResult`。`clip_page` 仅需 `item:create`，将网页正文与页面元数据 YAML 一起创建为未归类明文 Note，来源为 `clipper`；将 operationId 作为稳定条目 ID 并调用现有 `applyOperation`，复用服务端冲突/幂等、同步日志和附件引用对齐。内容读取关闭时仍可剪藏；剪藏创建不读取已有内容，固定写收件箱。
- **附件能力**：新增 `upload_attachment` 与 `read_attachment`，没有永久删除工具。上传同时要求 `item:create` 和 `attachment:access`；读取同时要求 `content:read` 和 `attachment:access`，并通过服务端 SQL 检查引用条目未删除、非私人空间、非单篇加密、符合 Memo 与 Token 范围后才返回附件字节。剪藏仅能附加由同一 Token 通过上传工具登记过的附件哈希。MCP 上传首版限制约 5 MiB（base64 载荷 7,000,000 字符），低于应用普通附件 20 MiB 上限。
- **审计与限速**：新增逐 Token 固定分钟窗口 D1 工具调用限速计数（协议初始化/发现/工具列表不占调用额度）；新增审计资源 ID 字段，记录剪藏、附件上传与读取结果及资源/条目 ID，不记录正文和附件字节。认证成功后记录 `last_used_at`，超限请求仍属于认证成功调用。
- **跨域边界**：只给 Chrome/Firefox 扩展 Origin 返回 CORS 授权，不带 Cookie 凭据；允许 MCP POST 和所需协议头。浏览器扩展连接实现需使用实例可选 host permission，不请求全站访问权限。
