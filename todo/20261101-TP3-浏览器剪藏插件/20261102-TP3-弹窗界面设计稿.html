弹窗重设计：一次点击完成剪藏

把六个平级按钮收成两个平级操作，状态不再靠猜。主界面只回答三个问题：这是什么页面、我有没有存过、现在能做什么。预览拆成独立页，设置收进二级。

尺寸 360 × 560 固定 头部 主页 / 主题 / 设置 主操作 2 个平级 状态 chip 只显示最重动作 预览 独立标签页 标签 / 备注 一次填写 图标角标 色 + 形双编码
01

主界面

顶部是品牌与连接状态，中部一张页面卡说明「我在哪」，三枚 chip 回答「存没存过」，两个操作回答「做什么」。站点规则默认收起，不占视线。

02

设置页

三项配置、四行能力测试。测试全程只读：查 MCP 工具清单判断剪藏、收藏、模板三项权限，收藏目标只做 ID 解析，不往后台写任何记录。

03

独立预览页

点复合按钮的眼睛区，在新标签页打开。左栏 Markdown 可直接编辑，提交的是编辑后的内容；右栏只列提取结果里真实存在的字段，不虚构封面与标签。

顺手修掉一个既有问题：现在 popup/index.html 的 #markdown 带 readonly，而 clipCurrentPage() 提交的是 currentCapture.markdown。README 里写的「之后也可编辑 Markdown」实际上没有接通——预览页改为提交编辑后的文本。
04

工具栏图标角标

页面存在本地记录时，工具栏图标右下角出现状态角标。色与形双重编码：蓝色圆形星标 = 已收藏，绿色圆角方对勾 = 已剪藏；两者都有时只显示剪藏角标，不叠加。角标直径 40%，外圈白色描边保证在任何工具栏底色上都清晰。蓝色是为了和品牌橙拉开对比，刷新页面后由后台脚本按本地记录重打角标。

改造前（0.1.16 旧角标）绿方块 = 已剪藏，绿圆点 = 已收藏
为什么要改：旧角标是纯色几何块，直径占 42%，48px 时直接压在笔记本主体上；方块和圆点在 16px 下几乎无法区分，也用不了语义。新方案保留「色 + 形」双通道，并给 16px 单独退化：图案省略，只留形状与颜色。
已落地：构建脚本 scripts/build.mjs 的 statusMarker() 已按此规范重绘，pnpm build 会生成 16/32/48/128 × 三状态共 12 张新图标。
05

交互与状态

两个操作互不阻塞；所有失败都在原位给一句话原因和一个下一步，不弹 alert，不整页遮罩。

01
点「剪藏此页」

校验连接 → 注入提取（模板 → 站点适配 → Readability）→ 有图且已授权时上传附件 → clip_page 写入。

02
成功

chip 变为「已剪藏 · 刚刚」，提示条给「已剪藏到收件箱」+ 查看入口。再点一次会新建一篇文档，不覆盖旧文档。

03
失败

提示条一句话原因（Token 失效 / 无权限 / 超时 / 无正文）+ 重试或前往设置，页面其余部分保持可用。

04
点眼睛区

新标签页打开预览，正文不进 URL 参数。预览页可编辑并提交编辑后的文本；提交成功后回写本地记录，主界面下次打开即显示已剪藏。

05
状态来源

三枚 chip 全部来自本地 menotePageActions（上限 500 条，按 URL 去 hash）。清扩展数据、换设备或超出上限后状态即丢失，这是刻意的取舍。

06
标签与备注

弹窗打开即可见，两个操作共用同一份内容，也可以留空直接提交。收藏走契约里现成的 tags / note；剪藏需要给 McpClipRequest 加可选字段并写进 YAML，正文 Markdown 保持干净。
