# TP3 MCP 剪藏与附件服务设计

- **任务包**：TP3 浏览器剪藏插件
- **创建日期**：2026-11-01
- **状态**：实现中；Worker 类型检查与 dry-run 构建通过，HTTP/D1 端到端联调待完成
- **需求基线**：[FR-MCP-1～7、FR-MCP-10～11 与 FR-EXT-2](../../wiki/Menote_V2_需求说明书_v1.2.md)
- **相关设计**：[MCP Token 管理设计](20261101-TP3-MCP管理设计.md)

## 1. 目标与边界

为 Menote-clients 浏览器扩展提供最小远程 MCP 通道：用户在扩展中配置 Menote `/api/mcp` 地址与 Token 后，能创建一篇收件箱 Note，并在授权后上传网页图片附件。该能力使用既有 Token 管理和权限系统，不读取 Menote 登录 Cookie，不开放一般笔记列表、正文或搜索工具。

阶段一仅实现网页剪藏。链接收藏仍是独立的第二阶段，不在本设计中实现。EdgeEver 只作为公开架构观察对象；Menote Worker 仅依赖稳定 MCP 协议和 `src/shared` 契约，不依赖 EdgeEver 或浏览器扩展代码。

## 2. 传输与认证

- 单一 Streamable HTTP 端点：`POST {instance-origin}/api/mcp`；Menote 设置中显示并复制此地址。
- 使用官方 MCP TypeScript SDK v2 `createMcpHandler`，由 Cloudflare Worker 的 Web 标准 `Request` / `Response` 接入。按每个 HTTP 请求新建 MCP Server，不持有跨请求会话状态。
- Token 通过 `Authorization: Bearer mn_…` 传输。MCP 路由只用 Token；不接受登录 Cookie，也不降级为匿名或会话授权。`AUTH_PEPPER` 未配置时拒绝请求。
- 每个请求先从 D1 重新认证 Token 并读取最新 permissions/scope/includeMemos/ratePerMinute；更新 `last_used_at` 后再执行请求。因此 Token 撤销、到期和权限变更对下一次请求生效。工具发现仅列出当前权限允许的工具。
- 工具调用限速以 Token 为单位，在 D1 中用单语句递增固定分钟窗口计数；协议初始化/发现/工具列表不占用户配置的调用额度，超限返回 HTTP 429 和 `Retry-After`。
- 浏览器扩展请求的 CORS Origin 限定为 `chrome-extension://` 与 `moz-extension://`；不开放 Cookie 凭据。无 Origin 的 MCP 客户端仍可通过 Bearer Token 请求。

官方 SDK 文档说明 `createMcpHandler` 每请求创建无状态 server，且适用于 Cloudflare Workers；它本身不验证 Origin 或 Token，所以本项目必须在路由层先完成 Origin 策略与 Bearer Token 验证。支持的协议版本随 SDK 固定，插件依赖 MCP 客户端 SDK 进行版本协商，不自行构造 JSON-RPC。

## 3. 工具与权限矩阵

| MCP 工具 | 暴露条件 | 服务端约束 | 输出 |
| --- | --- | --- | --- |
| `connection_status` | 有效 Token | 固定响应，不读取项目内容；供连接诊断使用 | 服务可用状态 |
| `clip_page` | `item:create` | 只创建明文 `note`；固定 `topicId/groupId = null` 收件箱；`source = clipper`；不读取既有项目内容；以 `operationId` 实现重试幂等 | 新 Item ID、版本与 applied/duplicate 状态 |
| `upload_attachment` | `item:create` + `attachment:access` | 服务端重算 SHA-256；最大约 5 MiB；通过既有附件服务写 R2/D1；不支持删除 | SHA-256、大小、MIME、文件名 |
| `read_attachment` | `content:read` + `attachment:access` | 必须能找到至少一篇当前可见、未删除、非私人空间、非单篇加密且符合 Memo/范围设置的引用条目；只返回附件本身，不返回正文或条目列表 | 附件 SHA-256、MIME、Base64 字节 |

剪藏固定进收件箱，没有主题/分组目标；因此 `item:create` 不需要枚举或读取现有内容，内容读取权限关闭仍可剪藏。Token 的选定主题/分组范围约束对既有附件的读取；阶段一没有通用编辑、搜索、列表、历史或回收站工具。

上传产生的附件需在同一 Token 下完成上传并由后续 `clip_page.attachmentHashes` 引用；不能仅凭任意哈希把已有附件挂到剪藏条目上。MCP 不提供附件永久删除。所有通过附件工具返回的既有文件均经过可见性判定；加密正文、加密附件和私人空间没有授权例外。

## 4. 剪藏契约与落库路径

共享契约位于 `src/shared/src/types/integrations.ts`，由 `src/shared/src/index.ts` 导出：

- 请求：`McpClipRequest`，`schemaVersion: 1`、`operationId`、标题、Markdown、页面 URL、ISO 剪藏时间、可选附件哈希和页面元数据。
- 响应：`McpClipResult`，包含 Item ID、服务端 rev 和 `applied/duplicate`。
- 扩展现有 `CaptureResult` 是提取器内部载荷；MCP 连接器负责映射，不让 DOM/站点适配器调用 MCP。
- Worker 把页面标题、来源 URL、剪藏时间及存在的作者/发布时间/站点/描述/canonical URL 编码为 YAML 1.2 双引号 scalar，再拼接正文；哈希针对最终完整 Markdown 计算。
- `operationId` 同时作为初始 Item ID。Worker 将构造出的 plain Note 交给同步 `applyOperation` 服务，复用冲突检查、sync log、`sync_operations` 幂等和附件引用计数维护，不直接 SQL 写 `items`。

## 5. 审计、错误与数据最小化

- MCP Token 每次成功认证后更新最后调用时间；包括工具发现和失败工具调用。无效/撤销/过期 Token 不更新。
- `mcp_audit` 记录 Token、工具名、Item ID 或附件 resource ID、版本（适用时）、结果、operation ID、时间。正文、Markdown、Token 原文和附件字节不写审计或日志。
- 无效凭据返回 401；速率超限返回 429；协议/工具参数由 MCP SDK 校验；授权或业务拒绝作为 MCP 工具错误返回。扩展不得将 Token 或页面正文写入诊断日志。
- 附件读取输出可能较大；服务端遵守上传上限。扩展应避免上传超过限额的图片，并在失败时保留原页面 URL 或提示部分剪藏。

## 6. 迁移、文件边界与验证

- 新增 0031 `mcp_rate_limits`、0032 `mcp_audit.resource_id`；已发布迁移保持不可变。
- MCP 传输位于 Worker route，工具编排位于 MCP Clip service，SQL 位于 DB helper；共享载荷只定义在 `src/shared`。插件仓库独立维护提取/连接器，不 import 主应用私有实现。
- 当前实现已完成 Worker 类型检查和 Wrangler dry-run 构建；尚未应用本地 D1 迁移或执行真实 HTTP/MCP 调用，所以不能据此宣称端到端通过。
- 端到端验收前应覆盖：Token 无效、仅创建权限、读取关闭时剪藏、动态撤权、限速、operationId 重试、附件权限缺失、跨范围附件、加密/私人条目附件拒绝、真实 Chromium 页面提取并保存进收件箱。
