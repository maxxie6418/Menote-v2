## 1. 目标

提供一个浏览器扩展，通过 Menote MCP 管理创建的访问 Token 连接实例。TP3 先完成 MCP Token 管理，再完成扩展；用户在扩展中填写 Menote MCP 地址和 Token 后，能够将网页正文提取为 Markdown，并创建一篇进入 Menote 收件箱的 Note。每个 Token 可独立配置、动态调整权限，并记录最后调用时间。页面标题、来源 URL 与剪藏时间写入 Note YAML；页面能提供时，再附带作者、发布时间、站点名、描述与 canonical URL 等可选字段。

扩展与 Menote 主应用、Worker、MCP 工具实现保持松耦合：通过有版本的 MCP 协议与稳定剪藏载荷契约通信；正文提取器和站点适配器仅依赖扩展自身定义的接口，不导入 Menote UI/DB 模块，也不依赖 EdgeEver 的内部框架。

## 2. 分期范围

### 前置任务：MCP Token 管理与剪藏所需服务端能力

- Token 管理界面放在应用「设置」菜单内，增加独立的「MCP 接入」栏目，与远程备份、附件、恢复码等栏目并列。
- 在 Menote 设置中管理各自独立的 MCP Token：创建、列表、查看/复制、撤销；每个 Token 支持独立名称和重命名，留空时按 `menote1`、`menote2` 等序号自动命名；动态调整每个 Token 的权限和范围，不需重新生成 Token，修改在后续调用立即生效。
- Token 权限遵循最小授权：内容读取、创建、编辑、回收站、附件权限逐 Token 独立配置；内容读取可关闭，但 MCP 初始化、工具发现、鉴权和范围判定所需的协议/内部读取仍正常工作且不暴露既有笔记内容。范围、Memo、URL 携带开关、限速与有效期按 FR-MCP-2 管理。
- 展示并持久化每个 Token 的最后一次有效调用时间；建议以认证成功的 MCP 请求时间更新，工具执行失败也记作调用。时间戳不得随 Token 更新权限而清空。
- 提供网页剪藏所需的 MCP 写入工具与来源标记；其余通用 Agent 工具仍按 M4 MCP 计划推进，避免把完整 MCP 扩围并入 TP3。
- Token 与权限变更需服务端逐次读取最新授权状态；不得使用 Token 签发时缓存的旧权限绕过撤销或变更。
- MCP Token 管理与剪藏服务提前至 TP3；完整的通用 Agent MCP 工具仍按 M4 推进。
- 附件工具开放上传与读取/下载；上传/附加要求附件权限及对应条目的创建或编辑权限，读取/下载要求附件权限、内容读取权限和条目可见性。所有附件工具服从用户范围，私人空间与加密条目一律拒绝，不提供独立附件永久删除。
- 加密内容没有可配置的 MCP 授权入口；即使 Token 具备创建、编辑、读取、附件等权限，MCP 也不得创建到、读取或编辑加密内容及其附件。

### 阶段一：网页剪藏（本任务当前范围）

- 浏览器扩展配置 Menote 实例 MCP 地址和访问 Token；提供连接校验与清晰的鉴权/网络错误提示。
- 从当前页面提取标题和正文，转换为 Markdown；首版不支持选区剪藏。未来若增加选区剪藏，默认将选中内容保存为 Memo。
- 网页剪藏创建 Note，固定进入收件箱；不提供主题选择或链接收藏。
- 建议正文中可访问的图片经 MCP 附件工具复制到新 Note 并改写为 Menote 附件引用；受限、失效或不支持的图片保留原 URL，并明确提示部分剪藏。Token 缺少附件权限时仍允许保存文字，图片保留原 URL。
- 将页面标题、来源 URL、剪藏时间写入 Note YAML；页面提供时附带作者、发布时间、站点名、描述、canonical URL 等可选字段，缺失字段省略。来源标识与 MCP 审计可区分浏览器剪藏和 Agent 写入。
- 页面提取按用户站点模板 → 代码站点适配器 → 结构化文章数据 → Readability 通用提取 → 主内容区/可见文本兜底执行；模板未匹配、无效或提取失败均继续 fallback。模板与 EdgeEver 上游实现解耦，具体设计见[剪藏模板规则设计](20261101-TP3-剪藏模板规则设计.md)。
- 剪藏黑名单按网页 origin 保存 CSS selector 规则；剪藏前在文档副本中移除匹配节点，适配器与通用提取统一生效。首轮提供存储与应用机制；通过页面点选广告节点生成规则、预览命中结果及管理 UI 作为后续扩展。

### 阶段二：链接收藏（本次开始实现）

- 复用 MCP 地址与 Token；收藏链接与网页正文剪藏是两个独立动作。
- 按负责人 2026-11-01 最新确认，收藏目标同时支持普通文档和多维表格，用户填写文件链接或文件 ID；表格可作为优先目标及后续 Raindrop 推送的数据源。
- 多维表格按字段映射追加行；普通文档按固定、可解析的 Markdown 结构追加。两种目标都不创建剪藏 Note，也不进入收件箱。
- 收藏元数据参考 Raindrop，首批字段包括标题、网址、摘要、备注、标签、类型、封面、采集时间和重要标记。表格目标自动补齐缺少的标准列；同 URL 可以重复收藏，操作 ID 用于网络重试幂等。
- Raindrop 官方单条创建/更新接口接受 `created` 字段，技术上可把表格采集时间映射为 Raindrop 创建时间；Raindrop UI 的实际展示需后续真实账号验证。
- 建议新增窄化的收藏写权限和专用 MCP 追加工具：服务端可内部读取目标以安全追加，但不向 MCP 返回既有内容；该权限不要求开启内容读取，且应限制在指定目标范围。现有权限系统暂未实现此项。
- 详细字段、写入和同步路径见[网址收藏与 Raindrop 推送可行性](20261101-TP3-网址收藏与Raindrop推送可行性.md)。需求说明书 v1.20 与主文档 v0.18 已按负责人最新决策修订。

## 3. 解耦与站点适配设计

扩展内部规划分为四层，细节以实现前的技术设计为准：

1. **浏览器壳层**：Manifest、权限、弹窗/右键入口、配置存储、后台消息。
2. **提取核心**：统一 `CaptureResult`（标题、Markdown、页面 URL、时间、可选元数据、提取器标识/版本）；管理通用提取、选区提取和错误降级。
3. **站点适配器**：按站点独立模块匹配 URL 并读取页面 DOM，输出同一 `CaptureResult`；适配器不可直接调用 MCP、改写主应用数据或依赖某站点以外的浏览器壳逻辑。
4. **Menote MCP 客户端**：只处理 MCP 连接、Token、工具调用、协议错误和版本协商；不解析页面 DOM。

每个站点适配器配套可脱敏的 HTML 固定样本和转换断言，记录支持 URL 形态、提取字段、已知限制与最近实测日期。长期参考 EdgeEver 的对应站点适配器，并记录固定上游文件链接、commit、参考日期和借鉴点；将提取逻辑落到 Menote 自身 `CaptureAdapter` 契约，不把 EdgeEver 的目录结构、UI、状态管理、API 或运行时引入剪藏核心。新适配器代码骨架与来源记录模板见 Menote-clients `browser-extension/docs/adapters/`。站点适配器未匹配或失败时回落 Readability，再回落主内容区及可见文本。

**黑名单边界**：规则按网页 origin 隔离，存储 `{id, origin, selector, createdAt}`；只对剪藏文档副本执行 CSS selector 移除。规则应用发生在适配器之前，因此专用适配与通用提取均不会重新带回被排除节点。后续页面点选交互负责生成/预览 selector 并写入此规则契约；DOM 选择和规则管理不耦合到提取适配器。

## 4. Menote 侧依赖与安全边界

- 访问必须通过 MCP Token；不读取 Menote 登录 Cookie，不要求用户在剪藏网站上登录 Menote。
- 剪藏需要 `item:create`；网址收藏需要独立 `bookmark:write`，均沿用同一 Token 且可动态调整。收藏授权只允许范围内指定明文 Note/Table 追加，不返回目标正文，不要求 `content:read`；不需要回收站/删除权限。
- Token 管理仅允许已登录用户操作自己名下 Token；查看/复制凭据遵循 C-7 可逆加密存储与事后查看规则。撤销立即生效；权限、范围、期限等修改无需重发 Token。
- `lastUsedAt` 在服务端验证 Token 成功后更新；无效凭据不改变它。时间采用 UTC epoch 与现有时间戳契约一致。
- MCP 写入创建的 Note 进入固定收件箱，来源标记和审计标识须能区分 `clipper` 与 Agent；不能把剪藏误记为 Agent。
- 内容读取权限关闭时，扩展仍可完成协议发现与剪藏写入；MCP 不向该 Token 返回已有笔记/正文/版本。其它必须的协议读取只供服务端执行，不成为内容浏览入口。
- 附件上传与读取/下载走单独 Token 附件权限；上传新剪藏所需权限为创建 Note + 附件，读取既有附件还需内容读取权限。附件接口仅触达该 Token 有权访问的明文条目；私人空间和单篇加密条目的附件始终拒绝，不提供独立附件删除。
- MCP 逐次读取最新 Token 权限；权限降级/撤销在后续请求立即生效。`lastUsedAt` 在 Token 认证成功后更新（调用工具失败仍记为有效调用；无效 Token 不更新）。
- Token 在扩展内采用浏览器安全存储能力；提供移除/替换操作，不写入日志或错误上报。具体浏览器权限与跨浏览器存储方案在技术设计阶段确认。

详见 [MCP Token 管理设计](20261101-TP3-MCP管理设计.md)。该设计已获负责人确认并完成基础实现；名称设置作为本次增补纳入管理界面。

### 5.1 阅读器、摘录、剪藏与收藏的产品边界

扩展提供四种可分别启动的操作。一个操作不应隐式执行另一个操作；阅读器里可由用户主动发起剪藏。

| 操作 | 输入与呈现 | 输出/副作用 | 规则范围 |
| --- | --- | --- | --- |
| 阅读器 | 当前网页提取结果，在独立阅读页展示；不改写原网页 | 默认只影响扩展阅读页；浮动工具调整预览样式 | 阅读器站点规则 |
| 摘录 | 当前网页标题与来源 URL | 依 FR-EXT-6 写入时间线 Memo，并添加结构化「摘录」标签 | 复用页面标题/来源信息；不调用剪藏正文规则 |
| 剪藏 | 当前网页或阅读页显式发起 | 依 FR-EXT-2 保存 Markdown Note 到收件箱 | 剪藏模板/站点规则 |
| 收藏 | 当前网页链接与收藏元数据 | 依 FR-EXT-2 追加到指定 Note/Table | 收藏目标与字段规则；不创建剪藏 Note |

阅读浮动工具固定显示在阅读页底部，支持字号、版心宽度（窄/标准/宽）、行距（紧凑/标准/宽松）和阅读主题（纸色/浅色/深色）即时切换。当前仅作用于本次阅读页会话，不写入原文或账号偏好。

### 5.2 模块化站点规则工作说明

- 建立独立的 `reader` 与 `clipper` 规则模块及稳定输入/输出契约。两者可共用底层 URL 匹配、DOM 安全处理和规则管理基础设施，但各自的规则数据、执行入口、结果和开关保持隔离。
- 按站点选择规则；用户可在网页规则编辑界面创建、查看、修改、启停和删除相应规则。修改规则前后可辨认适用站点及所属模块；不得让剪藏规则改变阅读器结果，反之亦然。
- 阅读器规则用于适配阅读页所需正文提取/呈现；剪藏规则用于生成剪藏内容和元数据。剪藏现有模板库维持兼容，实施设计需明确它与新增剪藏站点规则的关系，避免同一页面出现隐含的重复/相互覆盖。
- 规则未命中、停用、校验失败或执行异常时，分别走对应模块的通用提取/呈现 fallback，并给出可理解的失败状态；不修改原网页、不执行不受信任的任意脚本。
- 规则实现只依赖扩展定义的接口，不调用 MCP、不访问 Menote 主应用数据层。网页规则首版仅存于扩展本机，不跨设备同步；剪藏模板库仍通过既有 MCP 模板接口同步，两类规则分开维护。
- 已定实现口径：规则数据带 schemaVersion；按精确 origin 匹配；剪藏站点规则先于同步模板；CSS 选择器在保存时校验；旧剪藏排除规则迁移入 clipper 模块；运行异常回退通用提取。规则测试样本与站点清单在真实验收时补充。

### 5.3 Memo 快速输入

- 扩展弹窗提供轻量 Memo 输入框与明确的提交动作；关闭或提交失败时不得静默丢弃尚未成功发送的文本。成功后明确提示已保存，并清空本次输入；失败保留原文，可重试。
- 写入复用扩展现有 MCP 客户端与 `create_memo`，不引入新的 Worker 写入工具，也不要求打开 Menote Web 应用。Memo 固定写入时间线，沿用服务端幂等与审计路径。
- 权限沿用 `item:create` 且 Token 必须允许「包含 Memo」。缺少权限时在提交前说明原因；服务端拒绝仍需显示明确失败状态，不得误报成功。
- 每次草稿提交生成稳定 operationId；网络结果不确定时重试沿用同一 operationId，防止重复创建。离线时保留待发送草稿；若后续实现自动排队，须复用同一 operationId，并提供可见的待发送/失败状态及用户可控重试。
- 本功能默认只发送用户输入文本；当前网页标题/URL 是否可选附加，须在交互稿确认后实现，不得未经用户明确操作隐式附加浏览页面信息。

## 6. 验收

- 配置 MCP 地址与 Token 后，扩展能识别连接失败、无效 Token、权限不足和服务版本不兼容；Token 可替换/移除。
- 在受支持的通用文章页面执行剪藏后，标题、Markdown 正文与来源属性正确，生成的 Note 位于收件箱；刷新/同步后内容仍在，剪藏正文不写入 MCP 审计或扩展诊断日志；写入遵守 MCP 幂等与权限契约。
- Token 关闭内容读取后，内容类列表/搜索/正文/历史读取均拒绝，协议发现、鉴权与剪藏创建仍可用；逐 Token 权限修改和撤销在下一请求生效，最后调用时间准确更新。
- 授权的明文条目可按权限上传并读取/下载附件；缺少附件/内容权限、跨用户/范围访问及所有加密内容请求均拒绝；不存在 MCP 附件永久删除工具。
- 首版不提供选区剪藏；图片按可读性和 Token 附件权限尽力上传，权限不足或部分图片不可读时保留原 URL 并明确提示；未支持页面能回落或明确提示，不能伪报成功。
- 未匹配站点能经通用提取或主内容/可见文本兜底产出内容；适配器失败不得阻止 fallback。黑名单规则只影响对应 origin，且需在适配器和通用提取前统一排除。
- 至少一个通用网页与每个首批站点适配器有固定 HTML 样本测试；真实浏览器验证权限、连接、提取和创建闭环。
- 结构检查与扩展构建通过；主应用仅依赖 MCP 契约，不依赖插件实现；站点适配器遵守稳定接口。
- 阶段二链接收藏不计入阶段一验收。
- 阶段二验收：Note 与 Table 均可接收记录；Table 缺列自动补齐；关闭 `content:read` 仍可收藏且响应不含目标正文；加密/私人/软删除/越范围目标拒绝；同 URL 可单独重复收藏、相同操作 ID 重试不重复写入；扩展错误态不误报成功。
- 用户模板被停用/删除后，下一次成功全量同步应移出扩展缓存；同步失败保留上次快照并继续离线剪藏。
- `clip:templates:read` 仅暴露启用模板，`clip:templates:write` 只允许保存模板；两者均不得隐式授予 `content:read` 或条目范围读取。
- EdgeEver 导入模板为独立快照；上游撤下/修改规则不影响已有模板。任意 JS、无法安全映射的状态逻辑须报告不支持，不能静默输出错误模板。
