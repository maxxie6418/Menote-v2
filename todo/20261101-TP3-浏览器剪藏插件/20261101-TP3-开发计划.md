## 1. 目标

提供一个浏览器扩展，通过 Menote MCP 管理创建的访问 Token 连接实例。TP3 先完成 MCP Token 管理，再完成扩展；用户在扩展中填写 Menote MCP 地址和 Token 后，能够将网页正文提取为 Markdown，并创建一篇进入 Menote 收件箱的 Note。每个 Token 可独立配置、动态调整权限，并记录最后调用时间。页面标题、来源 URL 与剪藏时间写入 Note YAML；页面能提供时，再附带作者、发布时间、站点名、描述与 canonical URL 等可选字段。

扩展与 Menote 主应用、Worker、MCP 工具实现保持松耦合：通过有版本的 MCP 协议与稳定剪藏载荷契约通信；正文提取器和站点适配器仅依赖扩展自身定义的接口，不导入 Menote UI/DB 模块，也不依赖 EdgeEver 的内部框架。

## 2. 分期范围

### 前置任务：MCP Token 管理与剪藏所需服务端能力

- Token 管理界面放在应用「设置」菜单内，增加独立的「MCP 接入」栏目，与远程备份、附件、恢复码等栏目并列。
- 在 Menote 设置中管理各自独立的 MCP Token：创建、列表、查看/复制、撤销；动态调整每个 Token 的权限和范围，不需重新生成 Token，修改在后续调用立即生效。
- Token 权限遵循最小授权：内容读取、创建、编辑、回收站、附件权限逐 Token 独立配置；内容读取可关闭，但 MCP 初始化、工具发现、鉴权和范围判定所需的协议/内部读取仍正常工作且不暴露既有笔记内容。范围、Memo、URL 携带开关、限速与有效期按 FR-MCP-2 管理。
- 展示并持久化每个 Token 的最后一次有效调用时间；建议以认证成功的 MCP 请求时间更新，工具执行失败也记作调用。时间戳不得随 Token 更新权限而清空。
- 提供网页剪藏所需的 MCP 写入工具与来源标记；其余通用 Agent 工具仍按 M4 MCP 计划推进，避免把完整 MCP 扩围并入 TP3。
- Token 与权限变更需服务端逐次读取最新授权状态；不得使用 Token 签发时缓存的旧权限绕过撤销或变更。
- MCP Token 管理与剪藏服务提前至 TP3；完整的通用 Agent MCP 工具仍按 M4 推进。
- 附件工具开放上传与读取/下载；上传/附加要求附件权限及对应条目的创建或编辑权限，读取/下载要求附件权限、内容读取权限和条目可见性。所有附件工具服从用户范围，私人空间与加密条目一律拒绝，不提供独立附件永久删除。
- 加密内容没有可配置的 MCP 授权入口；即使 Token 具备创建、编辑、读取、附件等权限，MCP 也不得创建到、读取或编辑加密内容及其附件。

### 阶段一：网页剪藏（本任务当前范围）

- 浏览器扩展配置 Menote 实例 MCP 地址和访问 Token；提供连接校验与清晰的鉴权/网络错误提示。
- 从当前页面提取标题和正文，转换为 Markdown；首版不支持选区剪藏。未来若增加选区剪藏，默认将选中内容保存为 Memo。
- 网页剪藏创建 Note，固定进入收件箱；不提供主题选择或链接收藏。
- 建议正文中可访问的图片经 MCP 附件工具复制到新 Note 并改写为 Menote 附件引用；受限、失效或不支持的图片保留原 URL，并明确提示部分剪藏。Token 缺少附件权限时仍允许保存文字，图片保留原 URL。
- 将页面标题、来源 URL、剪藏时间写入 Note YAML；页面提供时附带作者、发布时间、站点名、描述、canonical URL 等可选字段，缺失字段省略。来源标识与 MCP 审计可区分浏览器剪藏和 Agent 写入。
- 通用网页由 Readability 类提取器兜底；重点站点通过独立适配器扩展。先选少量站点验证接口，不承诺一次覆盖 EdgeEver 支持列表。

### 阶段二：链接收藏（仅作后续接口预留，不在本阶段实现）

- 复用 MCP 地址与 Token；收藏链接与网页正文剪藏是两个独立动作。
- 所有收藏链接追加到用户指定的一篇记录 Note；不创建剪藏 Note，也不进入收件箱。
- 按负责人明确指示及需求说明书 v1.12，所有收藏链接追加到用户指定的一篇记录 Note；此方向已替代旧版 FR-EXT-2 的通用表格写入。用户在扩展中填写文件链接或文件 ID。现有 `Item.id` 可作为文件 ID；文件链接格式、追加格式和目标不存在时的处理仍待技术设计。
- 若用户提供文件链接，服务端/扩展需按约定从链接解析目标 Item ID；MCP 只在授权范围内确认该 ID 指向可编辑的明文 Note，不向 Token 返回条目正文或额外项目内容。

## 3. 解耦与站点适配设计

扩展内部规划分为四层，细节以实现前的技术设计为准：

1. **浏览器壳层**：Manifest、权限、弹窗/右键入口、配置存储、后台消息。
2. **提取核心**：统一 `CaptureResult`（标题、Markdown、页面 URL、时间、可选元数据、提取器标识/版本）；管理通用提取、选区提取和错误降级。
3. **站点适配器**：按站点独立模块匹配 URL 并读取页面 DOM，输出同一 `CaptureResult`；适配器不可直接调用 MCP、改写主应用数据或依赖某站点以外的浏览器壳逻辑。
4. **Menote MCP 客户端**：只处理 MCP 连接、Token、工具调用、协议错误和版本协商；不解析页面 DOM。

每个站点适配器配套可脱敏的 HTML 固定样本和转换断言，记录支持 URL 形态、提取字段、已知限制与最近实测日期。适配器契约单独成文并版本化；未来若要接入 EdgeEver 的新站点适配，可将独立适配器实现到该契约上，不把 EdgeEver 的目录结构、UI、状态管理或 API 引入剪藏核心。站点适配器失败时回落通用提取，并显示提取质量/失败原因。

## 4. Menote 侧依赖与安全边界

- 访问必须通过 MCP Token；不读取 Menote 登录 Cookie，不要求用户在剪藏网站上登录 Menote。
- Token 至少需要创建 Note 权限；若阶段二以追加方式写入记录 Note，则还需要编辑权限。阶段二沿用同一 Token 时可动态增授编辑权限。按 FR-MCP-2 最小权限设计，禁止为了扩展授予回收站/删除能力。
- Token 管理仅允许已登录用户操作自己名下 Token；查看/复制凭据遵循 C-7 可逆加密存储与事后查看规则。撤销立即生效；权限、范围、期限等修改无需重发 Token。
- `lastUsedAt` 在服务端验证 Token 成功后更新；无效凭据不改变它。时间采用 UTC epoch 与现有时间戳契约一致。
- MCP 写入创建的 Note 进入固定收件箱，来源标记和审计标识须能区分 `clipper` 与 Agent；不能把剪藏误记为 Agent。
- 内容读取权限关闭时，扩展仍可完成协议发现与剪藏写入；MCP 不向该 Token 返回已有笔记/正文/版本。其它必须的协议读取只供服务端执行，不成为内容浏览入口。
- 附件上传与读取/下载走单独 Token 附件权限；上传新剪藏所需权限为创建 Note + 附件，读取既有附件还需内容读取权限。附件接口仅触达该 Token 有权访问的明文条目；私人空间和单篇加密条目的附件始终拒绝，不提供独立附件删除。
- MCP 逐次读取最新 Token 权限；权限降级/撤销在后续请求立即生效。`lastUsedAt` 在 Token 认证成功后更新（调用工具失败仍记为有效调用；无效 Token 不更新）。
- Token 在扩展内采用浏览器安全存储能力；提供移除/替换操作，不写入日志或错误上报。具体浏览器权限与跨浏览器存储方案在技术设计阶段确认。

详见 [MCP Token 管理设计](20261101-TP3-MCP管理设计.md)。该设计待负责人确认；确认前不进入实现。

## 6. 验收

- 配置 MCP 地址与 Token 后，扩展能识别连接失败、无效 Token、权限不足和服务版本不兼容；Token 可替换/移除。
- 在受支持的通用文章页面执行剪藏后，标题、Markdown 正文与来源属性正确，生成的 Note 位于收件箱；刷新/同步后内容仍在，剪藏正文不写入 MCP 审计或扩展诊断日志；写入遵守 MCP 幂等与权限契约。
- Token 关闭内容读取后，内容类列表/搜索/正文/历史读取均拒绝，协议发现、鉴权与剪藏创建仍可用；逐 Token 权限修改和撤销在下一请求生效，最后调用时间准确更新。
- 授权的明文条目可按权限上传并读取/下载附件；缺少附件/内容权限、跨用户/范围访问及所有加密内容请求均拒绝；不存在 MCP 附件永久删除工具。
- 首版不提供选区剪藏；图片按可读性和 Token 附件权限尽力上传，权限不足或部分图片不可读时保留原 URL 并明确提示；未支持页面能回落或明确提示，不能伪报成功。
- 至少一个通用网页与每个首批站点适配器有固定 HTML 样本测试；真实浏览器验证权限、连接、提取和创建闭环。
- 结构检查与扩展构建通过；主应用仅依赖 MCP 契约，不依赖插件实现；站点适配器遵守稳定接口。
- 阶段二链接收藏不计入阶段一验收。
