## 完整范围与实施顺序

### TP12-1：全局视觉系统与页面外壳

- 建立 v3 令牌到生产 `--app-*` 的映射，复用现有 design token 规则，不将原型像素值直接复制进业务组件。
- 并入 v3 全局令牌、浅/深主题、对比度、排版、表面层次、边框/阴影、动效、焦点环、减少动态效果与三档响应式行为。
- 页面外壳完整实现 v3 侧栏、清单栏/书脊形态、账号区、视图导航及窄屏抽屉；所有视图保持稿件中定义的空间关系。
- 不改写原型自身的像素规格；生产样式全部使用 `src/web/src/styles/tokens.css` 中的令牌。

### TP12-2：首页与导航视图

- 首页完整按稿实现布局、最近记录、统计、搜索入口、交互反馈与空/加载状态；快捷 Memo 支持标签和图片附件，最近随记默认展开且可折叠；所有实际值来自本地真实数据，不把稿件样例数值当作内容数据。
- 全局导航、主题树、标签、最近/收藏/回收站、收件箱/草稿箱、加密空间等在各视图中的状态、切换与反馈按原型完整呈现。
- 桌面侧栏完整/书脊两种模式均提供可选设置；模式切换按稿移动导航内容，不丢入口。沿用稿中明确的同步归属和响应式覆盖规则。

### TP12-3：Note 清单与编辑/阅读视图

- 完整并入 Note 列表/网格、搜索与过滤入口、分类/标签导航、文档栏、正文编辑区、属性、大纲、格式工具栏、源码/预览、专注与全屏、历史/加密/导出/回收站等原型展示的完整页面结构和交互；按负责人 2026-11-09 指示移除 A4 纸张容器模式，柔纸主题继续保留。
- 实现稿中规定的编辑、阅读、切换、菜单、键盘、焦点返回、离页保护及条件状态；保证 Markdown 与附件内容仍经现有服务链路保存。
- 属性位置、工具栏位置、主题皮肤、版心及稿件中展示的组合偏好可按设计选择，并遵循稿件明确的设备范围与账号/本机存储归属。

### TP12-4：多维表格视图

- 完整并入表格标题区、视图/筛选/排序、批量操作、列显示菜单、固定槽位行号区、表格、行详情覆盖抽屉、空/编辑/选择状态及窄屏形态；末尾提供开放式添加列格，底部序号槽以加号按钮添加行。
- 按稿实现选择、拖动、列设置、详情开合、撤销及键盘交互；数据操作复用既有本地保存/同步服务，原型样例数据不写入用户数据。

### TP12-5：Memo 时间线、图册与互动

- Memo 的时间轴、侧记栏、日期筛选、标签筛选、热力图、随机漫步、那年今日、统计、卡片、任务状态、图册、互动及空/异常状态全部按稿实现。
- 侧记栏位置、显示状态及 Todo 侧板形态按稿提供用户可选偏好；Todo 不遮挡内容。图册实现原比例瀑布流、懒加载、回到来源及密文排除。
- 卡片评论与引述面板按稿完整实现线程展示、一级回复、排序、增删改、快照、理由、标签、发布反馈、数量同步、空态、键盘操作与焦点管理。

### TP12-6：设置、弹层与状态规范页

- 完整并入设置导航、所有原型展示的设置分类与设置内容、外观组合预览、偏好归属说明、应用内菜单、确认框、Popover、状态演示与帮助/规范视图。
- 控件的样式、键盘与关闭/焦点行为按稿实现；设置项必须实际生效并持久化。稿件中的占位功能若展示了明确交互，也实现相应生产行为；纯演示说明区转为适合产品的说明内容，不呈现虚假可操作控件。
- 所有互斥视图组合须由用户设置选择；设置的账号同步或本机保存范围严格按稿件标示。

### TP12-7：数据契约与跨层链路

- 为实现 v3 的完整功能补齐所需 shared 契约与服务能力，包括 `MemoComment` 父评论关联（限一级）、各项布局偏好和表格/Note/Memo 交互所需设置；类型仅在 `src/shared` 定义。
- 串接本地库、同步 API、Worker/D1、备份与恢复链路；历史平铺评论读取为根评论，旧备份/远端数据缺字段时兼容为根评论。
- 删除根评论时明确处理其回复，避免孤立回复；权限与可见性沿用 Memo 评论边界，不扩大 MCP 内容读取范围。
- 所有数据仍从本地库读取并经 services 写入；同步、备份/恢复、加密与可见性覆盖新增字段和设置。评论作者显示依据有效用户信息，不造出演示账号身份。

### TP12-8：全量验收与旧文档回写

- 对首页（含移动端）、Note 清单、Note 编辑/阅读、Memo、表格、设置、状态/规范页及所有弹层做视图清单逐项对照。深浅主题和桌面/平板/手机断点均检查，无缺视图、遮挡、横向溢出或不可达交互。
- 核对全部偏好组合、设置持久化及同步归属；检查真实内容、评论回复、附件、锁定/解锁、保存/同步状态、表格编辑与撤销等完整数据路径。
- 按项目结构门禁检查文件行数、feature 公共入口、UI/数据层分层和样式 token；运行 typecheck、相关测试与 build，并做可部署版本的核心路径冒烟。
- 全量并轨验收后更新旧需求说明书、主文档、`DESIGN.md`、工程结构设计与 TP6 设计/记录，使其准确反映最终设计与实现；更新 M3 开发记录与 M0 状态表。

## 执行原则与边界

- **完整一致**：不以当前生产界面或旧文档裁剪 v3 的页面范围、布局、样式或交互。实现按原型的所有视图、组件状态、弹层、菜单、设置和响应式稿逐项验收。
- **用户选择**：视觉稿明确提供的互斥模式均保留为用户可选设置，不自行合并或删除其中一种。
- **数据安全**：不改变已有加密与 MCP 安全边界；新增交互必须保持本地优先、服务层写入和密文边界。
- **样例与真实数据**：设计稿示例只用于布局/文案状态展示；生产数据与统计必须绑定真实本地数据，不能把样例内容或数字写入用户库。

## 交付与完成判据

- 生产全部视图和状态与 v3 最新视觉稿完整一致；所有互斥布局可以由用户设置选择，并按稿件指定范围保存/同步。
- v3 定义的完整交互和数据路径落地；一级评论回复在本地、同步、备份/恢复中往返正确，旧评论数据向前兼容。
- 上述验收通过，需求/设计文档与计划记录同步更新，M0 状态表登记完成版本。
- 完成开发前不提前改写旧需求与设计结论；以本计划和最新原型推进。

## 风险与处理

- **评论模型跨层改动**：先确认字段兼容策略，再按 shared → 本地/同步 → Worker/备份 → UI 的顺序接线，避免只完成界面。
- **布局设置兼容**：新增值采用有默认值的可选字段；未知值归一化到完整侧栏与 v3 默认 Memo 布局，确保旧设置不会导致界面空白。
- **与当前工作区未提交改动重叠**：开工前先检查负责人现有修改，按最新原型和其工作区状态增量合并，不覆盖未提交工作。
