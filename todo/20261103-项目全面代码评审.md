## 2. P0（会丢数据或不可逆损坏，均已核验）

### 2.1 网页端附件引用计数恒为 0

保存路径把 `attachmentHashes` 写成空数组，从不从正文提取引用：

- `src/web/src/services/contentService.ts` 创建条目时 `attachmentHashes: []`。
- `extractAttachmentRefs` 在 `src/web/src/services/attachmentService.ts`，只被附件面板的「引用文章」列、zip 导出和断链提示调用，保存和入队都不调用。
- 服务端 `src/worker/src/services/syncService.ts` 用载荷里的 `attachmentHashes` 对齐引用，因而 `ref_count` 恒为 0。MCP 剪藏是唯一正确填写该字段的入口。

后果：

- `src/web/src/features/attachments/AttachmentListPanel.tsx` 的「一键清理」按服务端 `refCount === 0` 过滤。界面上「引用文章」是前端实时解析 markdown，显示正确；清理按钮却会把正在使用的网页端附件全部物理删除。
- 备份按 `attachment_hashes_json` 收集附件（`src/worker/src/db/backup.ts`），快照不含这些文件，恢复后图片全丢。
- 30 天自动清扫要求 `orphaned_at` 非空，这些行从未被 realign 触碰，自动清扫暂时不会误删。会引爆的是手动清理和备份。

修法：保存时用 `extractAttachmentRefs(markdown)` 回填 `attachmentHashes` 并写入同步载荷；备份改为「正文引用 ∪ 元数据表」。

### 2.2 全量重同步只返回前 200 条，客户端先删本地

- `src/worker/src/services/syncService.ts` 的 `buildSyncPage`：游标早于保留窗口时调用 `readAllItemsPage(db, userId, 0, PULL_PAGE_LIMIT)`，offset 恒为 0，却返回 `hasMore: items.length === 200` 和 `nextCursor: oldestSeq - 1`。
- `src/worker/src/db/sync.ts` 的 `readAllItemsPage` 支持 offset，调用方从未传入大于 0 的值。
- `src/web/src/services/syncEngine.ts` 的 `pullUpdates`：收到 `fullResync` 后，先删除本地所有不在 outbox pending 集合里的条目、主题、评论，再写入本页。

触发：新设备游标为 0 且日志已被 90 天清理裁剪，或离线超过保留期。超过 200 条时，本地先被清空，只剩前 200 条；下一轮走增量，90 天内没改过的老笔记不会再出现在 `sync_log` 里，本地永久缺失。服务端数据仍在。

修法：全量重同步使用独立分页参数，循环拉完；客户端确认快照完整后再按差集删除。

### 2.3 备份恢复把密钥包装写成垃圾

- `src/worker/src/db/keyWraps.ts` 以 BLOB 写入 `kdf_salt` / `iv` / `ciphertext`。
- 备份收集是 `SELECT *` 后 `JSON.stringify`。`Uint8Array` 变成 `{"0":..,"1":..}`。
- `src/worker/src/services/restoreService.ts` 的 `toB64`：JSON 解析后的普通对象不是 `Uint8Array`，走 `String(value)`，得到 `"[object Object]"`，再写回包装表。
- `topic_key_wraps` 进了备份，恢复路径不读它。

后果：任意一次「备份到 WebDAV/S3 → 导入恢复」之后，单篇加密条目的包装块被固定垃圾替换，永久无法解锁。明文条目的 `content_ciphertext` 以文本存储，往返未坏，这是存储形态碰巧，不是序列化设计。

修法：收集备份时把 BLOB 显式编成 base64；恢复端对非法编码拒绝而不是静默转码；补上 `topic_key_wraps`；加一条加密条目备份往返测试。

## 3. P1（功能错误或静默分歧）

同步：

- `src/worker/src/services/syncService.ts` 把非业务异常收成 `rejected`。客户端对 `rejected` 标 `Number.MAX_SAFE_INTEGER`，永不重试。D1 抖动会让该操作死信：本地已保存，其他设备永远收不到。
- 同一次 item upsert 的写行、包装块、`sync_log`、幂等记录、附件对齐是多次独立 SQL，没有 `db.batch`。中途失败会留下「行已更新、日志没有」。
- `src/web/src/db/itemsRepo.ts` 的 `bulkPutItems` 不比较 `rev`。拉取会用服务端旧稿覆盖尚未推送的本地新稿。
- 幂等重放时，先前的 `rejected` 被返回成 `duplicate`，客户端当成已成功。
- `SYNC_CURSOR_KEY = "syncCursor"` 是全局单键；登出只调接口，不清 IndexedDB。同浏览器换账号会从别人的游标接着拉。
- AI 设置入队 key 为 `ai`，服务端 `applySetting` 只接受 `appearance`，改一次即死信，且本机因 pending 永远跳过拉取应用。
- 加密条目冲突不留副本（`saveConflictCopy` 对非 plain 直接返回），后推的编辑被静默丢掉。明文条目有副本。冲突副本本身不入 outbox，下次全量重同步会被清掉。
- 恢复旧备份时 `rev` 取较大值，内容字段无条件用备份行覆盖，版本号与正文不再对应。

加密与前端：

- `src/web/src/services/keyringService.ts` 的 `touchActivity()` 没有任何调用方。15 分钟锁定实际是解锁后的绝对超时；锁定替换编辑器时，最后一次防抖窗口内的输入丢失。
- `src/web/src/features/notes/EncryptedNoteView.tsx` 对 `readPlain` 的 `null`（解密失败或无密钥）使用 `?? ""`。空串会进入自动保存，用「加密的空串」覆盖原密文。解除加密若在明文尚未读完时确认，会把整篇转成空明文。旧版在版本历史里，界面无提示。
- 加密笔记可以上传附件，`attachmentService` 把文件明文 POST 到 R2。需求 FR-ENC-5 要求附件始终密文。M2 管理线记录既未声称完成，也未列为遗留。
- `encryptionCommandService` 的启用加密与解除加密绕过 `enqueueWrite`。与自动保存交错时，可能把刚加密的内容再推成明文，或反过来。
- `src/web/src/services/versionService.ts` 永久删除的网络失败被 `.catch(() => {})` 吞掉。本地已硬删，服务端软删行仍在，之后同步会把条目拉回。
- 回收站保留 90 天，孤儿附件 30 天物理删除。条目进回收站后唯一附件引用归零，第 31 至 90 天恢复时附件已 404。

安全口径（需负责人裁定，不是已证实的漏洞）：

- `sessions.id` 存的是 cookie 原值（`src/worker/src/db/auth.ts`）。密码、MCP token、备份凭据、Cloudflare token 都做了哈希或密封，会话凭证没有。若「登录密钥不明文入库」包含会话令牌，改为存 SHA-256 即可，查找协议不变。若不包含，应在纪律或开发记录里写明。

其余已核查、未发现越权：附件、同步、回收站、备份、恢复、AI 任务、MCP token、监控、剪藏模板的资源访问都带 `user_id`。MCP 读面在 SQL 层排除加密条目与私人空间。会话 cookie 为 HttpOnly + Secure + SameSite=Strict，变更路由有同源守卫。

## 4. P2（精选，不阻塞）

- cron 入口对 `AUTH_PEPPER` 只做类型强转，缺失时靠下游解密失败兜底，与路由层显式 503 不一致。当前效果仍是失败关闭。
- AI 队列 `max_retries: 3` 与代码里 `attempts < 3` 组合，实际比重试配置少一次。
- 恢复导入 `slice(0, 5000)` 静默截断，响应不报 skipped。
- 空白草稿注释写「种子永不上传」，实现会在约 300ms 后的自动同步里推走；24 小时后本地删除且不发墓碑，其他设备留下无标题条目。
- `upsertTopicRow` 冲突时不更新 `parent_id` / `depth` / `is_enc_space`。当前 UI 不能移动主题，尚未爆发。
- 附件先写 R2 再写 D1，D1 失败会留下无元数据对象，清理任务扫不到。
- `cryptoService.toB64` 用展开运算符，超长正文（大约超过 100KB）加密可能 `RangeError`。
- `EncryptSetupDialog` 确认路径无 try/catch，异常时按钮永久忙碌。
- 源码与所见即所得切换不先 flush，可能丢掉 800ms 内的输入。编辑/预览切换有 flush。
- 开放注册与附件上传无限流。登录有节流。
