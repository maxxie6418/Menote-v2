# Menote V2 开发计划

- 状态：执行规划，2026-10-31；里程碑以验收门推进，不预估日历日期。
- 权威顺序：产品结论以 [主文档](../wiki/Menote_核心重设计方案_讨论汇总_v0.7.md) 为准；需求与验收见 [需求说明书](../wiki/Menote_V2_需求说明书_v1.2.md)，模块与分层见 [工程设计](../wiki/Menote_V2_工程结构与组件设计_v0.2.md)，开发纪律见 [AGENTS.md](../AGENTS.md)。本文安排工作，不另行确定产品需求。
- [总计划](PLAN.md) 是状态唯一总表；M1 的计划和记录集中在 `todo/20261031-M1-部署与工程基线/`；M2～M4 下列工作项是规划草案，进入里程碑前在对应计划中细化，不代表已经完成。
- 视觉参照：[视觉规范](../DESIGN.md)与[界面原型](../wiki/design.html)。功能与信息架构仍以产品基线为准；视觉样稿不自动成为新需求。

## 执行规则

1. 每个任务先对照对应 FR、依赖和里程碑开发计划，补齐设计后实现；发现需求缺失、冲突或需要更改定稿，记录并请产品负责人确认，不自行裁决。
2. 开发在 `dev`，Workers 正式部署跟踪 `main`，合并 `main` 需产品负责人明确指示；未授权合并时，以隔离环境验证，不能将其当成正式部署已通过。
3. 每个任务及时更新本里程碑开发记录 和总表，记录实现、决定、验证证据、失败与遗留；里程碑结束按 AGENTS.md 进行分层、结构、样式、安全和冒烟检查。
4. 正式数据进场之前只使用可丢弃的测试数据；实际依赖云端账号、R2 服务开通、外部备份目标的验收须记录环境、操作和结果，不以模拟测试替代实测。
5. 按已有设计 tokens 实现视觉；正文渲染与应用外壳分别使用 `md-*` / `app-*`。以 1080p 桌面视口为重点，并按视觉规范检查响应式、深浅色、键盘与对比度；未完成项明确记录。

## 全局依赖与关键路径

```text
M1 骨架 → 迁移/契约 → 配置自检与部署验证 → 样式基础与监控挂载
    ↓
M2 认证隔离 + 本地数据/内容闭环 → 附件、加密、版本/回收站
    → 同步边界专项工作 → 备份快照/恢复 → 正式数据进场门
    ↓
M3 编辑器往返 PoC → WYSIWYG → 交互、视觉、性能和恢复体验
    ↓
M4 MCP / AI / 检索 / 监控增强 / 样式编辑 → 发布候选验收
```

图中表示主要前置关系，M1 各包和 M2 的独立设计可交错；同步专项在核心内容闭环后细化，但影响正确性的设计和实现必须在对应功能及正式数据进场前完成。M1 契约仅为可演进初版，未决同步或加密细节不得伪装成已定稿。

## M1：部署与工程基线（能部署）

执行现有七项工作，详细说明统一见 [M1 开发计划](20261031-M1-部署与工程基线/20261031-M1-开发计划.md)：

| 顺序 | 工作项 | 依赖及交付 | 验证重点 |
| --- | --- | --- | --- |
| 1 | [仓库骨架](20261031-M1-部署与工程基线/20261031-M1-开发计划.md) | workspace、web/worker/shared、构建入口与结构 | 安装、开发、构建；目录白名单 |
| 2 | [迁移框架](20261031-M1-部署与工程基线/20261031-M1-开发计划.md)；[数据契约](20261031-M1-部署与工程基线/20261031-M1-开发计划.md) | 均依赖骨架；共享实体和初版 SQL、版本化迁移及加密预留 | 重复执行、失败停止、两端共用类型；列出待定项 |
| 3 | [部署配置](20261031-M1-部署与工程基线/20261031-M1-开发计划.md)；[自检](20261031-M1-部署与工程基线/20261031-M1-开发计划.md) | 部署依赖骨架；自检依赖迁移，联合验证资源、Secret 和 schema | 隔离账号一键导入；缺 Secret fail-closed；失败可诊断；预览与生产隔离 |
| 4 | [样式基础](20261031-M1-部署与工程基线/20261031-M1-开发计划.md) | 依赖骨架；按视觉规范建立浅/深色 tokens、基础组件和布局壳 | 外壳/正文 token 分离；桌面样式、键盘及可用的响应式检查；记录未覆盖状态 |
| 5 | [基础监控](20261031-M1-部署与工程基线/20261031-M1-开发计划.md) | 依赖迁移及数据契约；独立采集、配置、视图 | 当前可采集数据注明应用内统计或估算；不可获取指标标明不可用；阈值、采样与开销可检查 |

**M1 验收门**：全新或隔离账号验证一键导入、自动资源和唯一 Secret，workers.dev 空应用可访问；自检及监控基础可用；首次启用预览前验证其不写生产 D1/R2；工程纪律检查与必要冒烟通过。平台权限或账号级开通导致无法实测时，记录阻塞与证据，不标记通过。

## M2：数据管理与调度（能管理）

以下工作在 M2 里程碑计划内按主题细化，并按依赖交错推进。核心路径采用 Markdown 源码编辑，正式数据只在本里程碑验收后进场。

| 拟定工作包 | 主要需求 | 实施与验收重点 |
| --- | --- | --- |
| 认证、会话与用户隔离 | FR-USR、C-7 | 首个 owner、注册控制、会话与安全边界；双账号对内容、附件及配置做服务端越权测试。 |
| 本地数据和内容闭环 | FR-IA、FR-EDT-1/2、FR-PROP、FR-MEMO、FR-SYNC-1～3 | IndexedDB 与服务层、Note/Memo、主题/分组、收件箱与草稿箱、源码编辑及自动保存、本地检索；刷新和断网后仍可使用。 |
| 属性与表格 | FR-PROP、FR-TBL | YAML 与 GFM 往返、无类型及类型化编辑、候选值和转义；用含未知语法的样本验证不丢内容。 |
| 附件与导出 | FR-SYNC-6～9 | 本地/云端附件引用、上传读取与鉴权、zip 和纯 Markdown 导出；外部工具打开并核对附件。清理依赖同步专项。 |
| 加密及恢复码 | FR-ENC、C-7 | 先设计密钥层级、封装版本、换码中断恢复、多设备处理；实现私人空间、单篇、恢复码，验证正文及附件密文边界和三凭据分离。 |
| 版本与回收站 | FR-VER | 封存、对比、恢复前保留当前稿、软删/恢复/永久删除；加密版本只存密文，验证分享失效。 |
| 同步与清理专项 | FR-SYNC-3～5/8、NFR-1/4 | 核心内容闭环后拆包：定义版本/事务、幂等、长离线与全量同步、墓碑保留、删改复活、历史与分享、附件引用及清理；按时序案例实测断网、多设备冲突和重复提交。 |
| 备份、调度与恢复 | FR-BAK、FR-DEP、FR-ENC | 先设计快照一致性、分片与 manifest、COMPLETE 发布和续传；实现 S3/WebDAV、调度与恢复；凭据保护满足已定基础安全边界。 |
| 可选剪藏启动 | FR-EXT-2 | 是否启动视进度决定，不改变核心验收门。 |

**M2 验收门**：双用户隔离、内容和附件闭环、离线补传及冲突/墓碑行为、加密与恢复码、版本和回收站、调度与备份均通过相应需求验收。正式数据进场前，从远端取回备份并校验，在干净环境至少一次使用恢复码重建，核对 Note/Memo、主题、附件及加密内容；分别测试 S3 与 WebDAV 的连接、推送及失败处理。记录测试数据、步骤和结果。

## M3：全链路体验优化（好用）

1. **编辑器 PoC**（FR-EDT-1/3/4/5）：以 YAML、GFM 表格、代码块、附件和未知 Markdown 为语料，往返对比，保留无法安全处理的内容；记录选型与失败情况。PoC 通过后接入 WYSIWYG，源码编辑移至更多操作。
2. **交互与视觉**（FR-IA、FR-MEMO、FR-PROP、NFR-8）：参照视觉基线完善三栏、列表/网格、时间线、属性和锁定态；检查加载、空、错误、焦点与键盘操作，不凭视觉稿改变需求。
3. **性能与恢复体验**（NFR-10、FR-BAK-9）：先记录设备、数据规模和输入/滚动基线，再确定并验证目标；检查后台保存、同步、加解密、封存对编辑的影响；完善恢复提示与异常路径。
4. **跨视口验证**：除 1080p 桌面，覆盖 375、768、1024、1440 宽度、深浅色、200% 缩放、触控与键盘；记录截图、浏览器和未通过项。视觉规范标注未执行的项目不视为已验收。

**M3 验收门**：WYSIWYG 往返安全复验、全功能体验走查、流畅性量化基线达标，恢复与异常路径可理解；核心数据与安全问题不得以体验优化名义延期。

## M4：扩展能力（发布候选）

| 拟定工作包 | 主要需求 | 前置与验证 |
| --- | --- | --- |
| MCP | FR-MCP | 复用统一业务命令、服务端权限与可见性；测试只读/写权限、私人空间不可见、单篇加密仅标题与标识、幂等、冲突与审计，完成主文档六条验收。 |
| AI 摘要与标签 | FR-AI | 手动触发、用户确认后写入、预算与不可用降级；加密内容授权粒度及结果密文边界先定稿，再验收。 |
| 服务端搜索 | FR-IA-10 | FTS 及本地分工、加密标题检索方式与权限过滤先设计；加密正文不进入明文索引。 |
| 监控增强与日志 | FR-MON、NFR-9 | 可选只读 Token、官方数据与估算区分、缺指标降级；监控不影响核心功能。 |
| 样式后台 | FR-STYLE-2/3 | 基于 `md-*` 编辑并保存方案，实时作用预览和阅读，样式不写入 Markdown。 |
| 发布候选 | FR-DEP-11、主文档 11.4 | 隔离账号重新实测导入、初始化、内容与附件、重复部署、更新保留数据、MCP 与备份入口及平台例外；汇总遗留风险。 |

**M4 验收门**：需求覆盖及 MCP 六条、完整一键部署验收通过；外部授权仅在使用对应功能时需要；发布和合并 main 仍遵循负责人明确指示。

## 记录与交付

里程碑开发计划至少包含目标、FR、依赖、范围、实现顺序、验证与 DoD；记录按日期追加操作、结果和遗留。阶段验收汇总应链接测试记录，区分自动测试、人工走查与外部服务实测，并注明不可执行的原因。新模块先登记工程设计；超出范围的产品变更经确认后再更新基线。
