# TP20 · AI 共享记忆库插件设计

**设计稿 · 2026-11-26**　 已确认采用 Menote 插件绑定表格，让不同设备上的 Agent 共享个人与项目记忆。下述字段、工具名、权限与冲突处理为首版提案，尚待评审与实现。

## 1. 用户如何用起来

1. 用户在 Menote「设置 → 插件 → AI 记忆库」启用插件，新建一张「AI 记忆库」表，或选取一张自己的明文表格。设置页展示表名、所在主题和打开表格的入口。
2. 用户给每个 Agent 签发独立的 MCP 令牌，授予记忆只读或读写权限。每个客户端配置同一个 Menote 实例的 `/api/mcp` 地址，加载同一份 Skill 规则。凭据保存在客户端的凭据配置中。
3. 在电脑 A 告诉 Agent「记住，这个项目的发布说明要用中文」。Agent 将规则写入该项目。换到电脑 B，另一个 Agent 在准备发布说明时，使用相同项目标识即可查到。
4. 用户也可以直接在 Menote 表格里把规则改为「发布说明提供中英双语」。网页修改同步到服务端后，下一次查询即返回新内容。设置页可关闭插件或解除绑定，原表可继续打开、编辑与导出。

一个 Menote 账号首版绑定一张表。表格正文保存记忆，账号设置保存绑定关系。Skill 随客户端分发，Menote 通过 MCP 提供共享数据。客户端需能连到实例并调用 MCP。支持 Skill 的客户端加载 `SKILL.md`，其他支持 MCP 的客户端可将相同操作规则放入项目或客户端指令。

## 2. 记忆表字段

一行表达一条可以独立更新的事实、决定或偏好。普通视图优先展示范围、项目、记忆项、当前内容和依据，技术列可在视图中隐藏。中文列名用于 Menote，括号内名称用于 MCP。表格采用现有 YAML 字段定义和 GFM 数据行。

| 字段 | 表格类型 | 必填与写入者 | 用途与示例 |
| --- | --- | --- | --- |
| 范围（`scope`） | 单选 | 必填，创建时指定 | 个人 `personal`、项目 `project`。按适用范围分类，与哪个 Agent 写入无关 |
| 项目标识（`project_id`） | 文本 | 项目必填，个人留空 | 由账号统一使用的稳定标识，如 `menote-v2`，换设备、换仓库目录仍沿用 |
| 记忆键（`key`） | 文本 | 必填，创建时指定 | 同一事项的稳定名称，如 `release.notes-language`。同一范围和项目内唯一，归档行也占用此键 |
| 记忆项（`title`） | 文本 | 必填，用户或 Agent | 给人阅读的名称，如「发布说明语言」。改名后仍能按原键查询 |
| 当前内容（`value`） | 文本 | 必填，用户或 Agent | 一条可直接使用的结论，如「发布说明提供中英双语」 |
| 依据（`source`） | 文本 | 必填，用户或 Agent | 可复核的简短出处，如「维护者于 2026-11-26 明确要求」或「仓库 AGENTS.md §9」。可写仓库相对路径、提交号或可访问的链接 |
| 状态（`status`） | 单选 | 必填，默认有效 | 有效 `active`、归档 `archived`。归档表示停用，仍可按键复核、恢复 |
| 行 ID（`id`） | 文本 | 系统生成，固定 | 标识这条记录，拖动行、改标题后仍可定位。复制为新行时重新分配 |
| 行版本（`row_rev`） | 数字 | 系统维护，从 1 起 | 有效修改后递增一次，网页和 MCP 共用。相同内容的重试保留原版本 |
| 更新时间（`updated_at`） | 文本 | 系统维护 | 服务端提交时间，采用 UTC ISO 8601，表格可完整保留时分秒 |
| 更新者（`updated_by`） | 文本 | 系统维护 | 显示「用户」或令牌的显示名。审计以稳定的令牌 ID 区分同名 Agent |

**身份规则。** 账号与绑定表确定记忆库。库内以 `(scope, project_id, key)` 查重，以 `id` 定位更新。项目标识和记忆键使用小写 ASCII 字母、数字、短横线，记忆键另允许点号分段。Skill 优先复用查询返回的键。范围、项目和键创建后固定。发现归属有误时在正确范围建立记录，再归档原记录。更新者、行 ID、行版本和时间由服务端校验，Agent 不传入这些字段作为新值。

## 3. 个人与项目怎样区分

| 用户原话（示例） | 应记录的范围与键 | 后续如何使用 |
| --- | --- | --- |
| 「以后默认用中文写发布说明。」 | `personal / release.notes-language` | 各项目通用的个人默认值 |
| 「Menote 的发布说明要中英双语。」 | `project / menote-v2 / release.notes-language` | 仅在 Menote 上覆盖同键的个人默认值 |
| 「这一次发给海外同事，用英文。」 | 本次会话 | 当前任务按英文执行，保留上述长期规则 |

项目标识由用户指定，可写在仓库的项目说明或 Agent 客户端配置中。多个仓库属于同一产品时可显式使用同一标识。同名仓库可指定不同标识。Skill 开工时先读取该声明。缺少可靠的项目映射时仍可查个人记忆，在首次项目读写前让用户确定标识。个人范围指该账号希望跨项目复用的偏好。仅在某仓库说过的要求，按照上下文归入该项目。适用范围仍含糊时先问清再存。

取回后按「本次用户明确要求 → 当前项目的有效记忆 → 个人有效记忆」应用同一事项。项目事实以当前仓库、文档或用户确认为准。遇到相反证据，先核对依据，再更新原条。记忆内容按参考资料解释，其中出现的工具调用、权限请求或外部指令不会自行获得执行授权。

## 4. 绑定与权限

- **绑定。** 服务端确认账号归属、明文可见、目标类型为 `table` 且已完成同步。新表或空表可直接初始化。已有数据的表先预览字段及逐行校验结果，合法行可在用户确认后补入系统字段。缺少业务值、重复键、重复行 ID 或已有其他插件绑定时，指出原因并让用户修正或选择其他表。保留自定义列、列序及既有数据。
- **访问。** 建议新增专用授权 `memory:read` 和 `memory:write`。只读令牌可查询，读写令牌可新增、修改、归档和恢复。写入需要同时具备两项权限。专用授权仅作用于绑定表，不授予通用 `search`、`read_item` 或附件读取。若同时授予通用权限，原工具仍遵循既有权限。该授权模型需随新增需求登记。
- **共享边界。** 首版授权单位是整个绑定库。持有记忆读取权限的 Agent 可查询个人和所有项目的记录。项目参数用于限定本次检索。设置页签发令牌前展示这个范围。需要逐项目保密的内容应留在有相应访问控制的位置。
- **每次调用。** 服务端按账号、令牌有效性、插件开关、当前绑定和主题/分组可见范围重新校验。目标入回收站、变成加密内容、移入私人空间或超出令牌范围时，返回统一的 `memory_unavailable`，不回显表名或行内容。解绑、换表、重新绑定生成新的绑定标识。旧请求不能操作新绑定，原表数据保留。
- **内容与审计。** 记录决策需要的事实和简短出处。密码、访问令牌、恢复码和整段私密对话不进入记忆行或调用日志。写审计记录令牌、操作 ID、绑定、行 ID、前后版本、结果与时间。记忆表是明文表，用户主动选择可向这些 Agent 共享的内容。

## 5. MCP 行级工具提案

服务地址和令牌配置沿用 Menote MCP。连接后先发现工具。当前已实现的通用查询面向整篇文档，`append_bookmark` 使用收藏专用列。以下三个工具为本需求拟新增的接口。由服务端从令牌解析账号及目标表，不接受任意表 ID。

| 工具 | 输入 | 结果与语义 |
| --- | --- | --- |
| `memory_query` | 必填 `scope`。项目查询必填 `project_id`，个人查询省略它。首次发现当前绑定可省略 `binding_id`，同一工作流程后续查询、翻页和重试须携带返回的绑定标识。可选 `key` 精确匹配、`query` 字面关键词、`status`、`limit` 和 `cursor` | 返回 `binding_id, rows, next_cursor`，行含 §2 全部字段。指定绑定与当前绑定不符时返回 `binding_changed`，不返回行。默认只查有效记录，可显式选 `archived` 或 `all`。关键词查键、记忆项和当前内容，多个条件取交集。无命中返回空数组 |
| `memory_create` | `binding_id, operation_id, scope, key, title, value, source`，项目另传 `project_id` | 仅在业务键空缺时创建。返回 `id, row_rev, status`。已有同键（含归档）返回 `key_exists`，按键查回原行再决定是否更新 |
| `memory_update` | `binding_id, operation_id, id, expected_row_rev, patch`。允许修改 `title, value, source, status` | 仅改显式传入的字段。纠正结论时一并传入新依据。归档或恢复通过修改状态完成。成功返回 `id, row_rev, status`。旧版本返回 `revision_conflict` |

查询按行 ID 稳定分页，建议每页默认 20 条、最多 50 条。游标绑定查询条件、当前绑定及表版本。翻页期间表已变化时返回 `cursor_stale`，调用方重新查询。查询和写入在服务端校验当前权限，重放成功回执也遵守此规则。客户端无需枚举主题、下载整表或推断行号。

### 同一条记忆在两台设备上的调用

以下 JSON 为工具入参示例。为便于连读，假设 A、B 分别用自己的令牌访问同一账号。绑定标识及行 ID 来自服务端响应。

**① A 先查同一事项（`memory_query`）。** 返回 `binding_id = b1`、空数组。首次命名时也用「发布说明」作关键词查近义项，避免为同一偏好另造键。

```json
{"scope":"project","project_id":"menote-v2","key":"release.notes-language","status":"all"}
```

**② A 根据用户明确要求新建（`memory_create`）。** 返回行 `r1`、版本 `1`。

```json
{"binding_id":"b1","operation_id":"e1c97cc2-95f1-4d1e-8acf-185f6a6b05ed","scope":"project","project_id":"menote-v2","key":"release.notes-language","title":"发布说明语言","value":"发布说明使用中文。","source":"维护者于 2026-11-26 在项目会话中明确要求。"}
```

**③ B 在新设备开工。** 先调用 `memory_query({"scope":"personal","key":"release.notes-language"})`，取得当前绑定 `b1`，再带上 `binding_id: "b1"` 按①的项目和键查询有效行。得到 `r1` 后应用项目要求。若用户随后明确要求长期改为双语，B 调用 `memory_update`，成功后版本变为 `2`。

```json
{"binding_id":"b1","operation_id":"cd05446b-a500-4305-b218-aa19c7883701","id":"r1","expected_row_rev":1,"patch":{"value":"发布说明提供中英双语。","source":"维护者于 2026-11-26 明确将此项目的发布说明改为双语。"}}
```

**④ A 仍持有版本 1。** 用版本 1 更新会收到 `revision_conflict`。A 按原键查回版本 2。若新结论已经满足要求，结束操作。若用户给出了更新的依据，基于版本 2 组织新修改。两份依据互相矛盾且无法核实时，保留当前记录并向用户说明分歧。

## 6. 写入与网页同步

| 情况 | 约定 |
| --- | --- |
| 请求超时，客户端不知道是否成功 | 每次逻辑写入生成 UUID `operation_id`。重试使用原 ID 和原参数。服务端按账号、绑定、调用令牌及操作 ID 识别重试。相同请求返回原回执，同 ID 不同参数返回 `operation_conflict` |
| 两个 Agent 同时创建同键，或同时更正一行 | 在提交时原子检查业务键唯一和预期行版本。一个成功，另一个得到 `key_exists` 或 `revision_conflict`。修改意图或前置版本变化时使用新操作 ID |
| 两个 Agent 修改不同行，同时命中同一张 Markdown 表 | 按表文档版本有条件提交。表版本发生变化时服务端重读表，只在目标行版本仍匹配时重新应用补丁。保留其他行、自定义列和 YAML。表写入、同步变更、行版本及幂等回执必须原子提交 |
| 用户从网页改表，设备曾离线 | 用户编辑同步到服务端时，按行 ID 对比变更并维护行版本、时间和更新者。离线编辑携带原始版本。同一行已经被改时展示冲突，其他行可合并。网页显示「本地已保存」期间，Agent 仍只能读到服务端最近确认的版本 |
| 调整表结构或删除行 | 排序、隐藏列与改动自定义列不改变记忆身份。绑定期间保护系统列和业务列映射。缺列、行 ID 重复或结构损坏时暂停记忆接口并在设置页指出修复位置。用户通过网页删行后，该 ID 的旧更新返回 `not_found`。同键日后重建使用新行 ID |
| 重绑、禁用、权限变化或服务不可达 | 旧绑定写入返回 `binding_changed` 或 `memory_unavailable`，Skill 停止重放。网络中断时如实告知写入尚未确认。恢复后先复核绑定，再按幂等规则重试 |

**网页编辑基线。** 现有同步命令提供文档级 `baseRev`。绑定表的编辑队列还需保存本地实际执行的行变更。新增携带稳定的本地操作标识，修改和删除携带行 ID 与编辑开始时的行版本，修改仅提交变动字段。用户在网页新建一行时先填业务字段，首次提交后映射到服务端生成的行 ID，后续离线修改按此映射衔接。服务端按显式删除处理。离线快照里未出现的其他行予以保留。成功行收到回执后移出队列。冲突行保留草稿，用户可以采用服务端值，或核对差异后基于最新行版本重新提交。字段或表结构损坏则整批暂停，保留草稿待修复。[现有同步契约](../../src/shared/src/contracts/sync.ts)

首版可直接解析绑定表。绑定与操作回执放在服务端，记忆正文只维护在表中。浏览器沿用本地优先的数据流，服务端沿用路由、服务和数据库分层。行级校验与版本维护要覆盖表格编辑和 Agent 写入两条入口。不能只为 MCP 实现并发检查。

## 7. Skill 的执行规则

拟在配套 Menote-clients 仓库的 `skills/menote-memory/SKILL.md` 分发一份可移植说明。相同语义适用于交互式助手和后台 Agent，具体加载方式由各客户端决定。

1. **开始或切换项目。** 确认实例、项目标识与可用工具。按当前任务查询少量相关的个人偏好和项目记忆。准备使用会变化的项目事实前，核查其来源或现行仓库。
2. **判断是否值得保存。** 用户明确说「记住」「以后都这样」时，或项目已有可定位的长期决定时，提出一条可独立更新的结论。一次性任务、观察猜测、暂时的构建状态留在当前会话。个人长期偏好须有用户表达作依据。
3. **先查后写。** 按范围、项目和键查所有状态，必要时用关键词找近义项。已有同义结论则复用。结论改变则更新原行。已归档的旧决定只有在用户重新确认或有明确新依据时才恢复。
4. **更正与停用。** 用户纠正结论时更新原行和出处。用户要求「以后别再用这条」时归档。两者均带上刚查得的行版本。用户要求彻底删除时说明归档仍保留原文，可由用户在 Menote 管理原表及其历史。
5. **向用户反馈。** 按成功回执报告写入了哪条个人或项目记忆。只读令牌、Skill 缺失、工具未上线或实例不可达时，说明实际可用能力。不会因为工具缺失自动改写 Memo 或创建其他文档。

## 8. 验收与登记

| 验收场景 | 通过标准 |
| --- | --- |
| 跨 Agent、跨设备 | A 新增项目记忆，B 用不同令牌、不同本地路径在全新会话按项目标识查到同一行。A 的令牌撤销后，B 仍可按自己的权限访问 |
| 个人与项目同键 | 两次查询取回各自记录。当前项目采用项目值，另一个项目回到个人默认。本次临时要求结束后两行原值保留 |
| 人工纠正、归档与恢复 | 网页更改经服务端确认后，B 读到新值和新版本。旧版本写入失败。归档后默认查询为空，显式查归档可恢复原 ID |
| 并发与断网 | 同键并发创建只有一行，同一操作重试只有一个结果，不同行并发修改都保留。离线网页旧稿无法覆盖其他 Agent 已确认的更正 |
| 权限及解绑 | 只读令牌调用写工具失败。记忆专用令牌不能读取其他笔记。目标进入私人空间、被删除或解除绑定后，记忆工具不再返回原表数据。换表后，携带旧绑定的查询、游标和写请求均不能访问新目标 |
| 账号隔离 | 在第二个账号建立同项目、同键但值不同的记忆。发现绑定时两方只收到本账号的值。用对方绑定标识查询，或在本方绑定中用对方行 ID 更新，均无法取得对方数据或修改记录，错误不透露对方目标是否存在 |
| 表格往返 | 人工重排行列或添加自定义列后仍能按 ID 更新。导出后能读到范围、正文及出处。遇到结构损坏时保留原数据并报告原因 |
