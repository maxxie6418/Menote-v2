## 2026-11-01

### 做了什么

- **属性不再被卸载保存写丢。** `joinFrontmatter` 收口到 `lib/frontmatter.ts`。卸载保存、插入附件、启用加密前取正文三条路径都先拼回 frontmatter。此前卸载 effect 直接把编辑器里的纯正文交给 `saveItemContent`。
- **编辑态图片可见。** `features/editor/attachmentRefs.ts` 在喂进编辑器前把 `attachments/<sha>--name` 换成鉴权 URL，取出时按哈希还原成相对路径。对照表记在 `NoteEditor`，两个适配器共用。
- **光标处插入。** `markdownEdit.ts` 的 `insertAttachment` 按光标偏移插入。格式栏「图片」、粘贴图片、拖入文件都走它。拖入时正文区加虚线轮廓。文档栏「插入附件」仍追加到文末，未改。
- **格式栏。** `FormatBar` 放在正文上方，仅所见即所得编辑态出现。行内五项加块级十项（含图片）。行内再点一次取消。按下态只覆盖行内。
- **「/」菜单。** `SlashMenu` 与格式栏同一份清单，行首或空段落触发，支持前缀过滤、上下键、Enter、Esc。执行后先删掉触发文字。
- **文档栏收纳。** 常驻只留插入附件、导出、移入回收站、更多、编辑/预览。更多内为源码切换、版本历史、启用单篇加密、整理到主题。表格结构化编辑的文档栏入口和 `TableBlockDialog` 调用已去掉，组件文件未删。`onExtractDoc` 参数保留，避免改 AppShell。
- **样式。** 编辑态 H2、H3 按 `--md-h2-size` / `--md-h3-size` 分开，补了链接色和分隔线。格式栏、菜单、更多菜单的样式都走已有 token。

### 决策

- 格式变换不走 Milkdown 命令。适配器只多了 `getSelection` / `setSelection`，变换在纯字符串上做完再整篇载入。这样源码态以后也能复用，Milkdown 类型不出 `features/editor/`。
- WYSIWYG 的选区换算用序列化长度近似，不是精确的文档位置。光标恢复落在最近的文本块，不保证落在字符级。

- `node --test src/web/test/markdown-edit.test.mjs src/web/test/frontmatter-table.test.mjs`：10 项通过。

## 2026-11-02：Note 格式栏选区错位修复

- **现象与原因**：Milkdown 所见即所得操作先把 ProseMirror 文档序列化为 Markdown，再以 Markdown UTF-16 字符偏移修改并整篇重载。序列化文本偏移与编辑器原生位置不等价，导致选区错位、Markdown 标记/`<br/>` 暴露在正文，以及格式变换破坏原生选择行为。
- **修复**：WYSIWYG 格式栏和「/」菜单改用 ProseMirror 原生事务作用于当前选区，不再整篇重载；行内格式、链接、标题、列表、引用、代码块、分隔线和表格均保留在编辑器模型内。源码 textarea 继续使用纯 Markdown 文本变换。
- **版本**：项目 `0.0.36 → 0.0.37`。
- **验证**：`pnpm --filter @menote/web typecheck` 通过；`pnpm --filter @menote/web build` 通过。构建有已有依赖 `use client` 指令、动态/静态导入及大 chunk 提示。真实浏览器拖选、复制、删除和工具栏逐项走查仍待完成。

### 2026-11-03 · W1 往返保真校验层

- **版本**：项目 `0.1.19 → 0.1.20`。
- **做了什么**：
  - `src/web/src/features/editor/roundtrip.ts`（新增）：往返保真内核。以 **mdast 结构**为等价判据，序列化器的 8 类规范化（列表符号、表格填充与分隔行宽度、setext→ATX、缩进代码块→围栏、硬换行风格、转义等）在 mdast 上不可见，因此结构相同即判「未变」。切分粒度：顶层块；无序列表切到列表项、表格切到行；**有序列表保持整块**（项序号随位置变化，逐项回填会写错编号）。未变单元回填原文，改动单元用新文本；空隙（空行、表格分隔行）只在形状一致时沿用原文，避免分隔行错位。
  - 接入：`milkdownAdapter` 持有守卫与基线；`getPreservedMarkdown()` 产出应持久化的文本（未触碰块回填原文），`isSameContent()` 供宿主判断外部回声是不是自己写的；`loadMarkdown` 区分外部写回（重置基线）与本地改动（沿用基线）；`NoteEditor` 的保存取值改走 `getPreservedMarkdown`，外部回声判断改走 `isSameContent`。
  - 依赖：新增 `remark-parse@11` 与 `unified@11`（unified 生态，非编辑器依赖；对应设计冲突项 C2，已在本文档登记）。
- **关键决策**：
  - **编辑态仍是规范序列化文本，只有持久化文本回填原文**。这样光标与选区逻辑零改动（偏移空间不变），版本历史与同步出去的正文又保住原始字节。代价：编辑态正文与落盘正文可能存在纯表现差异（如列表符号），渲染结果一致。
  - 等价判据用 mdast 而非字节比对：PoC 证据里 8 类规范化全部落在 mdast 不可见的层面，结构判据正好覆盖，且用户真实改动必然改变结构。
  - 有序列表不切到项级：插入一项会让后续项的序号整体位移，逐项回填会写出 `1,1,2` 这类错位。
- **顺带修掉的既有缺陷（非本次需求引入）**：
  - `getSelection` / `setSelection` 用 `doc.cut(0, pos)` 换算 markdown 偏移，切点落在**列表内部**时 Milkdown 的 gfm 预设序列化任务列表项会读取空父节点并抛 `Cannot read properties of undefined`。而这两处在每次键入/点击（`refreshSlash`）时都会调用——**光标停在列表项里就会中断编辑**。已加兜底：切点失败时按正文字符占比折算，保持与真实偏移同一量纲；`setSelection` 目标落在表格这类非行内内容时退回第一个段落开头，不再抛错。
- **验证**：
  - `pnpm --filter @menote/web typecheck` 通过；`pnpm --filter @menote/web build` 通过；`node --test src/web/test/*.test.mjs` **68 项全绿**（新增 12 项 `roundtrip.test.mjs`）。
  - 新增 `src/web/test/roundtrip.test.mjs`：直接拿 PoC 的 `poc/evidence.json` 当回归语料——**8 类规范化全部回填原文**，另覆盖列表项局部改写、任务勾选、插入段落、有序列表序号不写错、表格插行分隔行不错位等。
  - 新增 `src/web/poc/guard-check.mjs`（不在 pnpm test 套件内，属接入证据）：在 jsdom 里用**真实 Milkdown** 走一遍——序列化器把 `| --- |` 改成 `| -- |`、`-` 改成 `*`，持久化文本逐字节保留原文（`| --- | --- |`、`| 苹果 | 3 |`、`- 甲项`），改动段落用新文本；5 项全过。
- **遗留**：
  - 浏览器真实走查未做（编辑一段含表格与列表的笔记，确认版本历史里不再出现纯格式噪声 diff）。
  - 守卫每次保存要解析两遍全文，长文档的耗时留 W3 一并优化（基线工具已就位）。
  - 编辑态正文与落盘正文存在表现差异（列表符号等），需要在浏览器里确认用户是否感知。

  - `src/web/src/features/editor/milkdownAdapter.ts`：新增 `getTableContextAt(cell)` 与 `runTableCommand(command, cell)`；单元格 DOM→文档位置用 `view.nodeDOM` 反查（`posAtDOM` 在自定义节点视图下不可靠）。
  - `src/web/src/components/ui/ContextMenu.tsx`：新增 `disabled` 菜单项（置灰、跳过回调、键盘导航跳过）。
- **键盘（需求 §4.3 第 3、7 条）**：
  - Tab / Shift+Tab 在单元格间移动：Milkdown gfm 预设自带，已生效。
  - **末格按 Tab 追加一行**（本组件接管；否则表格最后一格是死路，Tab 出不去）。
  - **首格按 Shift+Tab 焦点进入工具条**，此后可用键盘走完全部命令；Esc 回正文。工具条在**光标位于表格内**时也显示（不只 hover），键盘用户看得见。
  - 不引入全局快捷键：Tab/Shift+Tab 是表格内的既有约定，避免与浏览器、系统快捷键打架。
- **关键决策**：
  - **不用 prosemirror-tables 的行命令，自行按真实节点结构实现**。Milkdown 的 gfm 预设把表格拆成 `table_header_row`（表头）与 `table_row`（数据行）两种行节点，且表头行只接受 `table_header` 子节点；prosemirror-tables 的 `addRowBefore/After` 按「引用行」复制节点类型，插到表头附近会产出 `table_header` 塞进 `table_row` 的非法结构。Milkdown 自己的 `addRowWithAlignment` 也是绕开这点（新增行一律用数据行 + 数据单元格），本实现照同一思路：新增行一律数据行 + 数据单元格，新增列在表头行插 `table_header`、数据行插 `table_cell`。
  - 表头行上方不能插行、表头行不能删、只剩一行数据不能删行、只剩一列不能删列——都由 schema 的内容约束（`table_header_row table_row+`）决定，宁可拒绝也不产出非法结构。
  - 对齐写回靠单元格的 `alignment` 属性（Milkdown 的属性名是 `alignment`，不是 `align`）；Markdown 序列化只读**表头行**的对齐，所以表头行与数据行同步写。
  - 工具条定位用表格的 `getBoundingClientRect`，容器为 `.mn-editor-wrap`（`position: relative`）。
- **顺带修掉的既有缺陷（非本次需求引入）**：
  - **程序化改文档后 `getMarkdown()` 仍返回旧内容**：Milkdown 的 `markdownUpdated` 监听器有 **200ms 防抖**，表格命令 dispatch 之后缓存还是上一版，防抖窗口内保存会存到旧内容。已在命令执行后同步作废内容缓存（下次读取重新序列化）。
  - `clearTableFormat` 把 `forEach` 的第二个参数当成索引——它其实是**子节点在行内容里的偏移量**，导致清格式时定位错位（新写的单测直接把它抓了出来）。
  - W0 遗留：性能诊断面板的 CSS 用了字面量 `22rem` / `100%`，破共享结构门禁（`src/shared` 结构测试），已改为走 token（新增 `--app-perf-panel-width` / `--app-perf-panel-z`）。
- **W1 × W2 的交互缺陷（本轮发现并修掉）**：
  - **改列对齐后持久化文本会把新对齐丢掉**。W1 的回填按「表格行」比对结构键，而**列对齐只体现在表头行与首个数据行之间的分隔行**（mdast 的 `align` 挂在 table 节点上，不在行上），行结构键没变 → 旧分隔行被当成「未变」回填 → 存盘后对齐消失。
  - 修法：空隙签名不再只看行数，**含表格分隔行时改看分隔行的对齐标记**（`:-` / `:-:` / `-:` / 无标记）；对齐一致才沿用原文分隔行，不一致就用新文本。只看宽度的规范化（`---` → `--`）仍按「未变」保留原文，不产生噪声。

  - `pnpm -r typecheck` 通过；`pnpm build` 通过（仅既有 lucide `use client` 与大 chunk 提示）。

### 2026-11-03 · W3b 编辑态增量序列化（FR-EDT-10）

- **版本**：项目 `0.1.22 → 0.1.23`。
- **范围**：需求 §5.3 的 **(b) 编辑态增量**。负责人 2026-11-03 决定「现在就做 A+B」：(A) 去掉键入路径上的整篇序列化，(B) 往返守卫免二次解析。**块级增量序列化（自己按块调各节点的 toMarkdown runner）不做**——要重写 Milkdown 序列化层，回归面覆盖所有语法，收益只在超长文档上体现。
- **做了什么 · A：键入路径不再整篇序列化**
  - **不订阅 `markdownUpdated`**：Milkdown 的 listener 插件**只有注册了 `markdownUpdated` 才会调用序列化器**（`serializer(doc)`），所以原来每次变更停顿（listener 内部 200ms 防抖）都会整篇序列化一次。改订阅 `updated`（文档级事件，不触发序列化）。
  - **`onInput` 契约改为脏信号**：`(markdown: string) => void` → **`() => void`**，只报「正文变了」，不带正文。落盘、导出、切换编辑/预览、离开文档前一律走 `registerGetMarkdown` 这个**全量出口**（该出口原样保留）。
  - **`getMarkdown()` 改为现算**：不再有「靠事件更新」的缓存，杜绝读到旧内容。
  - **`getPreservedMarkdown()` 的新鲜度改用 doc 比较**（`doc.eq(lastGuardDoc)`）：不依赖事件是否触发。
  - **`refreshSlash()` 不再取整篇正文**：它挂在 keyup 上，每次按键都调一次整篇序列化。新增 `EditorAdapter.getSlashContext?()`，所见即所得下用**编辑器原生选区**算「/」过滤词（行内按下态仍走 `activeMarks()`）；源码态仍按文本算（textarea 读 `value` 是 O(1)）。
  - **宿主侧改用脏计数触发自动保存**：`NoteDocument` / `EncryptedNoteView` 的自动保存 effect 依赖从「正文」改成「脏计数」，800ms 防抖不变；正文在保存时从编辑器取全量。
- **做了什么 · B：往返守卫免二次解析**
  - `preserveUnchanged` 在拼装回填结果时**同步产出单元数组**，`RoundTripGuard.update` 直接用它推进基线 → 每次保存少一次整篇 remark 解析。
  - **难点：回填会改变列表分组**。旧原文写 `- 甲`、新文本写 `* 乙改`，回填后 `- 甲\n* 乙改` 在 Markdown 里是**两条列表**，结构键从「列表项」变成「整条列表」，不能直接沿用新文本的键。新增列表键修正：按回填结果里真实的分组给键；列表项**带缩进**时（缩进决定该项是不是上一项的子项，而缩进落在空隙里）无法在不解析的前提下还原分组 → 该路径老实退回一次整篇解析（罕见）。
- **连带影响（已处理）**
  - `draft` 不再实时更新后，**属性区与 AI 面板回传的 `next` 是基于「上次保存的正文」拼的**，直接落盘会覆盖用户尚未保存的正文编辑（数据丢失）。`saveFullMarkdown` 改为**正文以编辑器的最新内容为准**，frontmatter 仍取 `next` 里的那份（属性区管 YAML）。
  - AI 面板提交给模型的正文改为**打开面板时取一次编辑器最新正文**，不再用旧 `draft`。
  - 底栏「X 字符」变成**上次保存时的字数**，输入过程中不实时跳动（有意取舍，已在代码注释写明）。
