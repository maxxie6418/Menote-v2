## 1. TP4.1 往返保真校验层

### 1.1 现状基线

- 编辑器底座是 Milkdown（`@milkdown/kit` 7.23，`src/web/package.json`），preset 为 `commonmark` + `gfm`（`src/web/src/features/editor/milkdownAdapter.ts:41-42`）。

- TP4 于 2026-11-02 修过一次「整篇重载导致选区错位」，改用 ProseMirror 原生事务（见 [开发记录](20261101-TP4-开发记录.md) 2026-11-02 节），**但序列化仍是全量的**。
- 现有 PoC 证据在 `src/web/poc/`，记录了 15 项语料 0 内容损坏、8 项等价规范化（`milkdownAdapter.ts:14-16` 注释）。
- 现有测试：`src/web/test/markdown-edit.test.mjs`、`frontmatter-table.test.mjs` 等 10 个 `node --test` 文件（`src/web/package.json` 的 `test` 脚本）。

### 1.2 问题

Milkdown 是「AST ↔ Markdown」双向序列化器，序列化结果**不保证与输入逐字节一致**。已知会被改写的常见形态：

| 形态 | 典型改写 |
| --- | --- |
| 无序列表 | `- item` ↔ `* item` |
| 有序列表 | 编号被重排为连续序列 |
| 表格 | 分隔行填充对齐空格（`\|---\|---\|` → `\| --- \| --- \|`） |
| 引用 | `>` 引用块的空行位置 |
| 代码块 | 围栏语言标注、缩进 |
| 行内转义 | `*`、`_`、`#` 等被加反斜杠 |
| 空行 | 段落间空行数量被规整 |
| 硬换行 | `\` 或尾随双空格被规整 |

这些改写单看无害，但叠加起来会破坏三件事：

1. **Git 式可比较性**：同一篇内容每次保存都产生 diff，版本历史（FR-VER）被噪声淹没。
2. **往返安全（FR-EDT-5）**：「不得损坏 YAML、GFM 表格、代码块、附件引用及任何不认识的 Markdown 内容」——现有保障是一次性 PoC，**没有常驻校验**。
3. **可移植性（C-1）**：内容真相是标准 Markdown，编辑器不应顺手规整它。

### 1.3 目标

在编辑会话内建立一道**常驻校验**：用户未触碰的内容，序列化后必须与原文保持等价；不等价时回填原文，绝不产出损坏内容。

### 1.4 规格

1. **等价判据用 mdast 结构**（实现口径，2026-11-03 落地）：Milkdown 序列化器的 8 类规范化（列表符号、表格填充与分隔行宽度、setext→ATX、缩进代码块→围栏、硬换行风格、转义等）在 mdast 上**不可见**，因此「结构相同」即判「未变」；用户真实改动必然改变结构，不会被误判。
2. **切分粒度**：顶层块；**无序列表切到列表项**、**表格切到行**（改一项不牵动整张列表）；**有序列表保持整块**——项序号随位置变化，逐项回填会写出 `1,1,2` 这类错位。
3. **对齐策略**：最长公共前缀 + 最长公共后缀，中段长度一致则逐单元配对，否则中段整体采用新文本（保守，绝不产出错位内容）。
4. **空隙处理**（块间空白、表格分隔行）：纯空白空隙沿用原文（空行数量差异是表现层差异）；含结构行的空隙只在形状一致时沿用原文，否则用新文本——保证分隔行不会错位。
5. **等价白名单**：允许的规范化差异由 mdast 判据隐含定义，不再单独维护字节级白名单；PoC 的 8 项等价规范化即其验收语料。
6. **编辑态与落盘的关系**（实现口径）：**编辑态正文仍是规范序列化文本，只有持久化文本回填原文**。这样光标与选区的偏移空间不变（零回归），而版本历史与同步出去的正文保住原始字节。
7. **只在会话内**：校验层是编辑器内存态，不落库、不进 outbox、不进备份。
8. **fail-closed**：无法一一对应时保留可信托管结果（不产出错位内容），并在诊断探针里留痕。

### 1.8 顺带修掉的既有缺陷（2026-11-03 发现）

`getSelection` / `setSelection` 用 `doc.cut(0, pos)` 换算 markdown 偏移。切点落在**列表内部**时，Milkdown 的 gfm 预设序列化任务列表项会读取空父节点并抛 `Cannot read properties of undefined`；而这两处在每次键入/点击（`refreshSlash` → `getSelection`）时都会调用——**光标停在列表项里就会中断编辑**。

已加兜底：切点失败时按正文字符占比折算（与真实偏移同量纲，宁可偏一点也不抛错）；`setSelection` 目标落在表格这类非行内内容时退回第一个段落开头。此项非本需求引入，属实施 W1 时发现的阻断性缺陷，随 W1 一并修复并记入开发记录。

## 2. TP4.2 单文件 HTML 导出

### 2.1 现状基线

- 现有导出只有两种：`exportNoteZip`（`.md` + `attachments/`，`src/web/src/services/attachmentService.ts:124`）与 `exportNoteMarkdown`（纯 `.md`，`attachmentService.ts:144`）；入口在 `src/web/src/features/notes/NoteDocument.tsx:379-382`。
- FR-SYNC-6 规定 Markdown 与 JSON 为导出格式；FR-SYNC-9 规定默认 zip、可选纯 `.md`。
- **缺口**：没有「发给一个人看」的形态。zip 要解压，`.md` 要渲染器。

### 2.2 目标

一篇 Note 导出为一个**自包含 `.html` 文件**：双击即在任何浏览器打开，图片在文件里，样式在文件里，不连 Menote、不连网络也能读。

### 2.3 规格

1. **单文件**：CSS 内联、附件以 base64 data URI 内嵌、附件引用一律解析为 data URI。
2. **与预览一致**：复用 `MarkdownView`（`src/web/src/features/markdown/MarkdownView.tsx`）的渲染管线与 `md-*` 样式，保证「所见即所得 = 导出所见」。
   - 实现路径：浏览器端用 `react-dom/server` 的 `renderToStaticMarkup` 渲染同一套 `components`（`react-dom` 已在依赖中），样式取 `src/web/src/styles/` 中 `md-*` 的**静态快照**（不读 CSS 变量运行时值，改为按当前主题生成一份字面量样式）。
3. **安全**：
   - 导出内容中的所有 HTML 片段必须转义/白名单化，**不带脚本**；
   - 页面内嵌 CSP：`default-src 'none'; img-src data: https:; style-src 'unsafe-inline'`；
   - 远程图片（`http(s)://`）**不内嵌**，保留为链接并在页面上标注「需要联网」；
   - 附件 data URI 单文件上限与总包体上限需设阈值（建议单附件 10MB、总量 50MB），超限改为保留相对路径并提示。
4. **加密笔记**：内容仍为密文时**不提供导出**，提示先解锁（沿用 FR-SYNC-9「导出加密笔记须先解锁」）。
5. **定位**：HTML 是**分享件**，不是备份。明确不进入 FR-BAK-6 的同构备份快照链路，不进 R2，不进 D1。
6. **入口**：文档栏「导出」菜单下增一项，与 zip / md 并列。

## 3. TP4.3 崩溃恢复快照

### 3.1 现状基线

- 保存链路：编辑态变更 → `onInput` → 既有自动保存/outbox → IndexedDB（Dexie）+ Worker 同步。
- 现有本地表见 `src/web/src/db/localDb.ts`（items / outbox / meta / version / topicWrap 等）。
- **缺口**：浏览器崩溃、标签页被杀、系统休眠后，未落盘（或未同步成功）的输入会丢。

### 3.2 目标

在**不破坏内容真相与安全红线**的前提下，给编辑中的正文留一份本地恢复副本。

### 3.3 规格（安全优先）

1. **快照是恢复副本，不是内容真相**：
   - 只写本地 Dexie，**绝不进 outbox、不进同步、不进 R2/D1、不进备份快照**；
   - 命名与表结构上与 `items` 表隔离，避免被同步逻辑误扫。
2. **写入时机**：编辑态有输入时，按**节流**写入（建议 5 秒一次 + 离开文档时一次）；写入内容为「当前正文 + 文档 ID + 时间戳 + 文档标题」。
3. **加密笔记（红线，已定口径）**：
   - **快照一律用该篇笔记的内容密钥加密后落盘**，明文不落盘（AGENTS.md §10：密文边界覆盖缓存与历史版本）。
   - **解锁状态才可写**：解密后内存中持有内容密钥 → 可加密快照并写入；锁定状态无密钥 → 不写、也不产生明文。
   - 因此「加密笔记解锁时可恢复、锁定时不可恢复」是**自然结果**，无需额外的状态判定分支，也不会出现「解锁时是明文快照」的中间态。
   - 技术区分方式：快照表存 `keyFingerprint`（该篇密钥的指纹）与 `cipher`（密文）；恢复时按当前笔记的密钥解密，密钥不匹配则丢弃该快照（不报错阻断）。
   - 加密笔记的正文在解锁后本来就在内存里，快照加密用的是同一把密钥，不引入新的密钥生命周期问题。
4. **恢复流程**：进入某篇 Note 或应用启动时，若发现比本地已存内容更新的快照 → 弹一次提示「发现未保存的内容（时间），是否恢复」：
   - 恢复 → 走**既有保存链路**写回正文（不另起写入路径）；
   - 忽略 → 删除该快照；
   - 不自动恢复，避免覆盖用户已在别处的改动。
5. **生命周期**：恢复或忽略后即删；超过 7 天的快照自动清理。
6. **体积上限**：单篇快照上限建议 1MB，超限不写（长文不值得）。

> **与负责人问答的对应**：负责人问「加密笔记在加解密状态下是否可以具备临时快照和恢复，技术上是否好区分」。结论：**好区分**——区分点是「有没有内容密钥」，不是额外的状态字段；实现上采用「快照加密落盘」，用户侧体验是「解锁即可恢复」，且明文不落盘。

### 3.4 落点

| 位置 | 内容 |

## 4. TP4.4 表格块操作菜单

### 4.1 范围界定（重要）

只做 **Note 正文内的 GFM 表格块**。**不涉及 TP2 的 `type: "table"` 整页表格文档**——那是另一种内容形态，TP4 设计 §3 已明文把它的结构化编辑入口从 Note 文档栏撤下。两者不混。

### 4.2 现状基线

- Milkdown 的 `gfm` preset 已提供 table 节点与命令（`milkdownAdapter.ts:41-42` 的 `.use(gfm)`），格式栏的「表格」按钮已能插入 3×3 空表（`milkdownAdapter.ts:135-142`）。
- **缺口**：表格一旦插入，行列操作只能靠手改 Markdown。

### 4.3 规格

1. **触发**：编辑态鼠标移入表格块 → 表格上方浮出一条轻量工具条；同时支持右键菜单（两者同源命令集）。
2. **命令集**（首版固定）：

   | 组 | 项 |
   | --- | --- |
   | 行 | 在上方插入行、在下方插入行、删除本行 |
   | 列 | 在左侧插入列、在右侧插入列、删除本列 |
   | 对齐 | 当前列左对齐 / 居中 / 右对齐 / 默认 |
   | 其他 | 清除本表格式 |

3. **键盘**：Tab 在单元格间移动，Shift+Tab 回到上一格；末格按 Tab 追加一行。**仅所见即所得态**（源码态 textarea 不做）。
   > **实现口径（2026-11-03 W2 落地补充，不改本条结论）**：末格按 Tab 追加一行由表格块操作组件接管；因为表格内 Tab 被「换格」占用，键盘进入工具条另用**首格按 Shift+Tab**（焦点进工具条，Esc 回正文），不引入全局快捷键；工具条在光标位于表格内时也显示，不只在 hover 时出现。
4. **写回**：结果必须是**标准 GFM 表格**；列对齐写回 `\| :--- \| :---: \| ---: \|` 形式。
5. **与校验层协同**：表格改动必然引起序列化差异，TP4.1 的回填机制保证未改动的表格不被顺带重排。
6. **样式**：工具条走 `app-*` token，不硬编码色值（AGENTS.md §5）。
7. **可访问性**：每个按钮有 `aria-label`，浮出可用键盘聚焦（focus-within 保持显示）。

## 5. TP4.5 增量渲染与渐进渲染

### 5.1 现状基线

- 编辑态：每次文档变更 → `markdownUpdated` → **整篇** `getMarkdown()` 序列化 → `onInput` → 上层自动保存（`milkdownAdapter.ts:37-39`、`NoteEditor.tsx:214-223`）。
- 预览态：`MarkdownView` 每次 markdown 变化 → **整篇** ReactMarkdown 重渲染（`MarkdownView.tsx:53`）。
- 需求说明书开放项 #14「编辑流畅性量化指标（键入延迟、滚动帧率基线）」排在 M2/M3（`wiki/Menote_V2_需求说明书_v1.2.md` 第 400 行），NFR-10 已立项但无基线数据。
- TP4 设计 §10 明确「量化基线留 M3」。

### 5.2 目标

长文档（目标 ≥ 5 万字 / ≥ 2000 块）下：打字不卡、预览先出可视区、极端超长文档有兜底降级。

### 5.3 规格

分三块，**按此顺序**做：

**（a）量化基线与诊断工具（前置，不可跳过）**

- 建立一份固定语料（长文 / 超长文 / 表格密集 / 大量图片引用），脚本化测量：
  - 编辑态单次按键耗时（序列化 + 上抛 + 保存入队）；
  - 预览态单次渲染耗时；
  - 首屏可交互时间；
  - 长任务（`PerformanceObserver('longtask')`）条数与总时长。
- **诊断模式实现**（已定口径）：性能监测**默认关闭**，仅在诊断开关打开时启用，做到零常驻开销。
  - 开关方式：URL 参数 `?perf=1` 或设置内的隐藏开关；关闭时**不注册任何 observer、不打点**。
  - 采集手段：`performance.mark/measure` + `PerformanceObserver('longtask')`；只在诊断模式安装，采样为聚合计数，不逐条写日志。
  - 产出：诊断面板显示汇总（次数 / 平均 / P95 / 最长），可一键复制 JSON。
  - 语料加载：诊断模式下一键把固定语料灌入当前编辑区，便于复现同一场景。
- 产物：基线数值写入开发记录，作为本项与后续优化的对比基准。

**（b）编辑态增量**

- 按键**不立即**整篇序列化：改为防抖（建议 300ms）后序列化，并记录**脏块区间**。
- 保存、导出、切换编辑/预览、离开文档前，仍走**全量**序列化（现有 `registerGetMarkdown` 已是保存前取值，正好是全量出口）。
- 与 TP4.1 共用「脏块」概念：校验只跑脏块 + 其邻块，全量校验仅在落盘出口执行。

**（c）预览渐进渲染**

- 首选**纯 CSS 方案**：`content-visibility: auto` + `contain-intrinsic-size`，浏览器只布局可视区；不引入虚拟滚动框架。
- 兜底：超过阈值（建议 20000 字符或 3000 块）的文档，**先渲染可视区**，其余在空闲时（`requestIdleCallback`）补齐；补齐前显示占位。
- 极端兜底：超过 200000 字符时，提示「文档过大，已切换轻量模式」，只渲染纯文本（与 splat 的降级思路一致）。

## 6. TP4.6 智能标点（默认关闭）

### 6.1 现状基线

- 渲染层 `md-*` 样式已由 tokens 驱动（FR-STYLE-1）。
- 需求说明书**无**排版标点相关 FR；FR-STYLE-2（样式后台编辑）排在 M4，样式偏好归属账号并跨设备同步（v1.25）。

### 6.2 目标

提供一个**可选、默认关闭**的「排版标点」偏好：开启后，预览/阅读/导出 HTML 中的正文标点呈现为排版形式；**Markdown 源码与编辑器内正文永远保持原字符**。

### 6.3 规格

1. **默认关闭**：关闭时行为与今天**完全一致**（零回归风险）。
2. **只改渲染层**：替换发生在渲染管线，不回写 Markdown、不进编辑器文档（符合 C-1）。
3. **替换集合（完整中文标点，已定口径）**：

   | 原文 | 渲染为 | 说明 |
   | --- | --- | --- |
   | `"` | `“` `”` | 中文双引号，**成对**（按前后文配对，单个不成对的引号原样保留） |
   | `'` | `‘` `’` | 中文单引号，成对；英文所有格（`'` 紧跟字母且右侧为非引号语境）按 `’` 处理 |
   | `---` | `——` | 中文破折号（占两字，GB/T 15834） |
   | `--` | `–` | 一字线（连接号），仅在**非水平线**语境 |
   | `...` | `……` | 中文省略号（六点） |
   | `……` | 保持 | 已是中文省略号，不重复处理 |

4. **不替换的位置（必须排除，否则破坏内容）**：
   - 代码块与行内代码；
   - URL 与链接地址（含图片地址）；
   - HTML 块；
   - **单独成行的 `---`**（水平线）与表格分隔行 `|---|`；
   - YAML frontmatter 区域（属性区内容一律不动）。
5. **引号配对规则**：以**块**为单位做配对（段落/列表项/表格单元格各自独立配对），奇数个引号时**最后一个不成对的引号原样输出**（不做猜测性改写）。
6. **开关位置**：设置 → 外观（与样式编辑器同区），归属账号、跨设备同步（沿用 FR-STYLE-2 的偏好同步口径）。
7. **不做全角化**：本条**不包含**中文全角标点（`，`→`，`、`。`→`。`）、不做顿号/书名号替换、不做标点挤压、不做中英文之间自动加空格——那属于 pangu 类排版范畴，会大面积改写正文，风险与收益不匹配。如需扩展另开条目。
