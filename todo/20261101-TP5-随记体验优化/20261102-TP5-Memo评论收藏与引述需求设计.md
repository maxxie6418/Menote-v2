## 1. 需求背景

在 Memo 时间线中增加类似 Twitter 的轻量互动体验，让用户可以回到自己的历史记录，继续补充、收藏和引用。此能力属于 Memo 的扩展，不增加新的顶层内容形态，也不改变 Memo 快速记录和时间线浏览的基本定位。

## 2. 已确认的产品规则

1. **评论是 Memo 下的后续发言列表**。当前仅支持用户对自己的 Memo 评论自己：例如原 Memo 发布一个月后追加一条评论，再过一个月继续追加评论。所有评论直接挂在 Memo 下、按时间排列；评论不能再回复或产生子评论。评论是后续发言，不覆盖或改写原 Memo 正文。
2. **引述要引用原文内容**。用户可基于一条既有 Memo 发起引述，并在新发言中展示所引的原文内容。
3. **入口位置**：评论、收藏、引述等操作参考 Twitter，放在用户自己发言的气泡框底部。点击评论或引述后均在原卡片内展开编辑，不弹窗、不打开独立窗口；收藏即时切换。
4. **收藏**：可收藏 Memo，以支持历史回顾。
5. **编辑与删除**：Memo 原文及评论均可编辑、删除；编辑后显示更新时间。评论无子评论，因此删除评论只删除该评论。
6. **回收站**：Memo 移入回收站时评论随 Memo 隐藏，恢复 Memo 后评论重新显示；永久删除 Memo 时一并清除其评论。
7. **引述快照**：发布时冻结原文快照并永久保留。来源 Memo 被删除后仍显示快照并标注「来源已删除」，隐藏来源跳转。
8. **讨论显示**：时间线中的评论默认折叠；点击卡片评论按钮后在原卡片内展开。评论新增、编辑、删除均在原页面完成，不离开时间线。
9. **搜索、备份和 MCP**：评论与引述应纳入搜索和备份/恢复；MCP 默认访问范围不扩大。

## 3. 交互结构

- 时间线中的 Memo 作为发言气泡显示；气泡底部放置评论、收藏、引述入口。
- 评论以原 Memo 为唯一根形成平铺列表；不建立评论间父子关系。
- 引述形成新的发言，并展示被引用的原文内容；新发言与来源 Memo 保持关联，便于回到上下文。
- 收藏状态属于 Memo，可从后续回顾入口或筛选中找到已收藏 Memo。具体收藏列表入口沿用现有回看/收藏导航设计，后续实现时核对当前导航状态。

## 4. 数据与架构影响

现有 `Item` 已有 `starred` 字段，可承载 Memo 收藏状态；目前结构设计对 Memo 评论串及引述关系没有定义。实现前需要细化共享契约及本地/服务端持久化：

- 评论需有稳定 ID、所属 Memo、正文、创建/更新时间和删除状态；作为独立记录保存，不写入 Memo 原文，也不包含父评论字段。
- 引述需保存来源 Memo 关系和被引用的原文快照。发布后快照永久冻结，原 Memo 后续编辑不影响旧引述；来源删除时保留快照并显示删除状态。
- 本地 IndexedDB、共享类型、Worker API/服务/DB、同步增量与冲突处理均需覆盖新增记录或关系；前端仍按 `UI → services → db → IndexedDB` 分层，Worker 仍按 `routes → services → db` 分层。
- 评论、收藏状态和引述关系需要纳入导出、备份、恢复与删除语义。Memo 进入回收站时评论保留但不显示；恢复后重新显示；永久删除 Memo 时评论一并清理。引述快照独立保留，来源 Memo 删除后不删除快照。
- 当前 Memo 不进入加密作用域（FR-ENC-1）；新功能应继续遵守既有可见性、安全与同步边界，不扩大 MCP 对 Memo 的默认访问范围。

## 6. 已定实现口径

- 评论列表按创建时间升序；评论无回复按钮、无父级关系、无层级缩进。
- 删除单条评论只影响该评论。Memo 软删时暂时隐藏其评论，恢复时重新显示；永久删除 Memo 时清除评论。
- 引述作为新的 Memo 发言，正文与原文快照分开存储；快照冻结，来源删除不影响快照。
- 用户收藏 Memo 复用现有 `starred` 字段，并出现在统一收藏视图和首页计数。
- 评论与引述不增加 MCP 可见范围。
