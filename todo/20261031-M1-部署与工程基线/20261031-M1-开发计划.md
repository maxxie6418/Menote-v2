# M1 开发计划与交接指南

- 状态：规划完成，开发任务未开始；M1 状态以 [总计划](../PLAN.md) 为准。
- 目标：建立可构建、可部署、能安全自检的空应用与工程基线，挂载 Resource Monitor 基础模式，为后续内容开发保留可演进的契约和视觉基础。
- 基线：先读本计划和本里程碑[开发记录](20261031-M1-开发记录.md)，再读[需求说明书](../../wiki/Menote_V2_需求说明书_v1.2.md)、[工程结构设计](../../wiki/Menote_V2_工程结构与组件设计_v0.2.md)、[产品主文档](../../wiki/Menote_核心重设计方案_讨论汇总_v0.7.md)及 [AGENTS.md](../../AGENTS.md)。产品冲突以主文档为准并提醒负责人；本计划不替代需求。
- 本阶段只用测试数据。M2 前不宣称账号、笔记、同步、加密或备份业务已可用；M4 才执行完整发布候选验收。

## 接手时先做什么

1. 检查当前分支、工作区和既有文件；不要覆盖用户的未提交或未跟踪内容。按 AGENTS.md 在 `dev` 开发；合并 `main` 需负责人明确指示，正式 Workers 跟踪 `main`。
2. 核对工作项状态及依赖，阅读开发记录；开始时更新开发记录和总表，推进中及时追加命令、结果、决策、问题及下一步。暂不能验证的标未验证，不填成功。
3. 查包管理器和运行时版本、云端访问与隔离环境；仅在确有权限和目标时操作外部资源。账号级条件不可用时先完成本地工作并记录阻塞。
4. 当前视觉基线见 [视觉规范](../../wiki/DESIGN.md)和[原型](../../wiki/design.html)，但界面仍可能变化；按下文边界设计，不把样稿当成不可变需求。

## 界面可调整的实现原则

- `app-*` 承担外壳视觉，`md-*` 承担正文渲染；颜色、字体、尺寸、间距、圆角等集中在 tokens 和组件样式层。断点与布局尺寸集中管理，不能散落于业务判断。
- 容器负责组合可替换区域，控件只表达状态和事件；服务负责获取、处理数据，UI 不直接访问网络、IndexedDB、密钥。视觉变化不改变数据契约、权限规则或服务行为。
- 保持合理抽象：使用现有组件、CSS 变量与组合即可，不提前建设拖拽布局器、通用主题引擎或大量占位业务模块。示例数据与真实状态明确区分。
- 视觉参考用于确定当前外观方向，后续可调整；桌面以 1920×1080 视口核对，同时检查窄屏可操作、深浅色、焦点和文字对比度。记录设备、浏览器、视口与截图；未执行不标通过。
- 视觉规范所述侧栏顺序与 FR-IA-4 不一致，搜索入口未定；涉及这些行为前通知负责人确认，不自行改写产品结论。M1 可先做不依赖该决策的通用空壳。

## 安全与部署约束

- 唯一必填应用 Secret 是 `AUTH_PEPPER`；缺失必须 fail-closed，不写入仓库、公开配置、页面或日志。密钥设计不得削弱 AGENTS.md 内容加密红线。
- D1/R2 自动预配、迁移、重复部署和账号前置条件须以当期官方文档及隔离账号实测；失败不得显示就绪。迁移需要处理并发、部分失败和旧新版本兼容。
- 自检页面不公开敏感诊断细节；UI 不承担权限防线。预览和迁移测试环境首次启用前验证无法写入生产资源。
- 生产部署跟踪 main；隔离环境可用于验证开发成果，但不能冒充正式部署通过。M1 真实导入验证若受账号、R2 开通、平台能力或 main 合并授权阻碍，要列出证据和缺失条件。

## M1 联合验收清单

每项标注通过/失败/未执行，附开发记录、命令或人工步骤、环境及可复现结果；不要用单元测试声称云端实测通过。

- [ ] 工作区干净安装、dev 和构建可运行；web/worker 使用同一 shared 契约；必要冒烟通过。
- [ ] 空库初始化、重复迁移、升级及失败重试符合预期；并发和不兼容版本不得误报就绪。
- [ ] 缺失 Secret、D1/R2 或迁移失败时清晰提示且安全拒绝敏感操作；正常时健康页可用；日志和页面无密钥。
- [ ] 全新或隔离 Cloudflare 账号验证自动资源、仅一个应用 Secret 和 workers.dev 空应用；重复部署保留绑定；账号级限制有明确说明。
- [ ] 预览环境首次启用前证实 D1/R2 与生产隔离；Workers 正式部署分支为 main，受授权约束的操作如实记录。
- [ ] Monitor 展示可获得的数据并正确标识来源、估算、时间和阈值；不可获得值不冒充真实账单；采集故障不阻断应用。
- [ ] 样式 tokens 分层，布局可调整；桌面及可执行的响应式、浅深色、键盘和对比度检查有证据；待确认的信息架构不被悄然定稿。
- [ ] 检查根目录白名单、行数、跨 feature 深引用、UI 直连数据层、样式硬编码，以及共享类型和 Worker 分层；现有目录冲突单列处理结果。
- [ ] 七项工作及总表状态一致；列出未完成项、阻塞原因、M2 接续内容及交接人可复现步骤。

## 交接记录最小格式

每次交接在本里程碑[开发记录](20261031-M1-开发记录.md) 追加日期、当前状态、已完成的具体文件/行为、需求编号、关键决定和依据、执行过的命令及结果、未验证项及原因、风险/待负责人确认的问题、下一步及依赖。记录测试环境和资源类型，但不记录 Secret、令牌或其他敏感值。结构检查若发现历史内容冲突，先报告负责人，不擅自移动或删除。

### Schema 迁移框架

- **状态**：未开始
- **目标**：完成 M1 所需的Schema 迁移框架并形成可交接的验证证据。
- **需求与输入**：FR-DEP-4/7；工程设计第 4、5 章
- **依赖**：TP1；初始业务 schema 与 TP6 对齐；部署及自检分别由 TP2/4 集成。

## 范围与实施步骤

1. 设计版本命名、执行顺序、版本记录、未知版本处理、失败状态和受控重试；明确执行入口、并发启动以及旧代码遇到新 schema 的处理。
2. 基于 D1 实际事务和执行限制核验迁移方案：版本记录与迁移结果须一致；若无法原子完成，设计可恢复策略，不能假定事务能力。
3. 实现顺序迁移、失败停止、已成功版本跳过以及初始化入口；保证重复和中断后可安全重试，不在 routes 写 SQL。
4. 引入 TP6 的初版迁移并明确所有权，避免两套 schema；保持未决设计可演进。
5. 提供自检可消费的 schema 状态，不泄露 SQL 或内部敏感细节。

## 验收与交付

- 空库初始化、重复运行、顺序升级均可复现；模拟迁移中断/失败后不错误推进版本。
- 测试并发初始化、未知或过新版本及失败后的恢复路径；不将不兼容 schema 标为就绪。
- 记录本地及 D1 实测边界，不能实测的项目单列；保留非破坏性升级说明。

### Monitor 基础模式

- **状态**：未开始
- **目标**：完成 M1 所需的Monitor 基础模式并形成可交接的验证证据。
- **需求与输入**：FR-MON-1/2/3/5/6/7；NFR-6
- **依赖**：TP3、TP6；面板使用 TP7 的基础组件，M1 仅覆盖实际存在的指标。

## 范围与实施步骤

1. 划分采集、归一化、可更新额度/周期/阈值、存储与展示边界；定义应用身份与来源元数据，保持模块不依赖笔记业务。
2. 盘点当前真正可采集的请求或操作计数及估算依据；无法从零配置获得的账户用量、CPU、计费等标为不可用，未启用服务不显示虚假零值。
3. 实现低频采样、合并写入和查询缓存，计入自身消耗；异常不可阻断空应用核心路径。
4. 提供按实际数据可用程度展示的资源视图、时间/来源/估算标识与可调阈值（70/85/95 默认）；账户额度共享及预警并非收费硬限制需清晰可见。
5. AI、图片或其他后续功能的预算保护随功能接入，不伪称 M1 已保护不存在的调用；官方 API/只读 Token 增强在 M4。

## 验收与交付

- 注入可控测试样本，核对统计来源、时间、阈值和估算标识；未知指标与未启用服务不伪造。
- 验证配置可更新、采集失败时应用可用，评估监控写入频率及成本。
- 保持不新增必填 Secret；记录实际采集指标、不可获得项和 M4 接续事项。

## 范围与实施步骤

1. 抽取语义化 `app-*` 外壳与独立 `md-*` 渲染 tokens，集中管理颜色、尺寸、间距、字体、圆角与状态；shadcn 映射放 tokens/UI 层。可调整默认值，不将具体像素或颜色嵌入业务组件。
2. 提供轻量应用布局壳及必要基础控件，以组件组合和样式变量承载布局；业务逻辑、网络/数据库访问留在 service，不将视觉方案做成业务判断。避免为可能的调整预建通用页面搭建器或复杂配置框架。
3. 同一结构支持浅/深配色，基本焦点、键盘与可读对比度；窄屏应可操作，尺寸和断点集中管理。状态、内容及展示分离，换布局或 token 不要求改数据契约。
4. 只做 M1 所需的空壳、健康页和监控基础控件；交互样例明确标识为样例，不把未实现功能呈现为可用。
5. 侧栏顺序与搜索位置须按既有冲突处理：在负责人确认之前不根据视觉稿自行改写 FR；保留可调整组合边界。

## 验收与交付

- 修改集中 token 能改变外观且不影响逻辑；渲染与外壳样式可独立调整；抽查无组件样式硬编码。
- 核查浅/深色、键盘焦点和基本对比度；以 1920×1080 视口检查桌面，并记录可执行的窄屏检查和截图；未验证不标通过。
- 应用壳可构建，核心健康/监控状态可访问；不提前实现 M2/M3 业务或把探索稿具体尺寸写成不可变验收条件。
