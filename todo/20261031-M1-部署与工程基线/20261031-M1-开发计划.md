- 状态：M1 各工作项已完成并验收（2026-10-31）；M1 状态以 [总计划](../PLAN.md) 为准。
- 目标：建立可构建、可部署、能安全自检的空应用与工程基线，挂载 Resource Monitor 基础模式，为后续内容开发保留可演进的契约和视觉基础。
- 基线：先读本计划和本里程碑[开发记录](20261031-M1-开发记录.md)，再读[需求说明书](../../wiki/Menote_V2_需求说明书_v1.2.md)、[工程结构设计](../../wiki/Menote_V2_工程结构与组件设计_v0.2.md)、[产品主文档](../../wiki/Menote_核心重设计方案_讨论汇总_v0.7.md)及 [AGENTS.md](../../AGENTS.md)。产品冲突以主文档为准并提醒负责人；本计划不替代需求。
- 本阶段只用测试数据。M2 前不宣称账号、笔记、同步、加密或备份业务已可用；M4 才执行完整发布候选验收。

## 接手时先做什么

1. 检查当前分支、工作区和既有文件；不要覆盖用户的未提交或未跟踪内容。按 AGENTS.md 在 `dev` 开发；合并 `main` 需负责人明确指示，正式 Workers 跟踪 `main`。
2. 核对工作项状态及依赖，阅读开发记录；开始时更新开发记录和总表，推进中及时追加命令、结果、决策、问题及下一步。暂不能验证的标未验证，不填成功。
3. 查包管理器和运行时版本、云端访问与隔离环境；仅在确有权限和目标时操作外部资源。账号级条件不可用时先完成本地工作并记录阻塞。
4. 当前视觉基线见 [视觉规范](../../DESIGN.md)和[原型](../../wiki/design.html)，但界面仍可能变化；按下文边界设计，不把样稿当成不可变需求。

## 界面可调整的实现原则

- `app-*` 承担外壳视觉，`md-*` 承担正文渲染；颜色、字体、尺寸、间距、圆角等集中在 tokens 和组件样式层。断点与布局尺寸集中管理，不能散落于业务判断。
- 容器负责组合可替换区域，控件只表达状态和事件；服务负责获取、处理数据，UI 不直接访问网络、IndexedDB、密钥。视觉变化不改变数据契约、权限规则或服务行为。
- 保持合理抽象：使用现有组件、CSS 变量与组合即可，不提前建设拖拽布局器、通用主题引擎或大量占位业务模块。示例数据与真实状态明确区分。
- 视觉参考用于确定当前外观方向，后续可调整；桌面以 1920×1080 视口核对，同时检查窄屏可操作、深浅色、焦点和文字对比度。记录设备、浏览器、视口与截图；未执行不标通过。
- 负责人确认侧栏顺序以视觉规范为准，需求说明书与主文档已同步；搜索入口位置仍待定。M1 先做通用空壳。

## 安全与部署约束

- 唯一必填应用 Secret 是 `AUTH_PEPPER`；缺失必须 fail-closed，不写入仓库、公开配置、页面或日志。密钥设计不得削弱 AGENTS.md 内容加密红线。
- D1/R2 自动预配、迁移、重复部署和账号前置条件须以当期官方文档及隔离账号实测；失败不得显示就绪。迁移需要处理并发、部分失败和旧新版本兼容。
- 自检页面不公开敏感诊断细节；UI 不承担权限防线。预览和迁移测试环境首次启用前验证无法写入生产资源。
- 生产部署跟踪 main；隔离环境可用于验证开发成果，但不能冒充正式部署通过。M1 真实导入验证若受账号、R2 开通、平台能力或 main 合并授权阻碍，要列出证据和缺失条件。

1. 设计版本命名、执行顺序、版本记录、未知版本处理、失败状态和受控重试；明确执行入口、并发启动以及旧代码遇到新 schema 的处理。

## 验收与交付

- 记录本地及 D1 实测边界，不能实测的项目单列；保留非破坏性升级说明。

- **目标**：完成 M1 所需的数据契约 v1并形成可交接的验证证据。
- **需求与输入**：需求说明书第 5 章、FR-SYNC、FR-ENC、FR-USR、C-7；工程设计第 5 章
- **依赖**：仓库骨架；与 迁移框架 协同确定迁移责任；M2 同步与加密专项仍待细化。

## 范围与实施步骤

1. 将需求和工程设计中的实体字段、归属、版本/删除状态及共享消息归纳到 shared；注明已定产品规则、初版技术结构和待定项。
2. 设计同步消息初版及错误/分页字段，前后端引用同一类型；不得将未讨论的事务、冲突解决细节标为定稿。
3. 提供与初版共享实体一致的 D1 迁移 SQL，协调迁移框架执行；明确身份归属、索引及后续迁移策略。
4. 为内容密文及密码/恢复码包装预留可演进字段，禁止明文主密码、恢复码或内容密钥；不提前定稿 KDF 或包装协议。
5. 记录长期离线、墓碑/附件回收、复活、密钥轮换等必须由 M2 专项确认的缺口，避免不兼容假设进入正式数据。

## 验收与交付

- shared 类型编译，web/worker 引用同一契约；表结构、字段与需求映射可追溯。
- SQL 经迁移框架空库/重复执行验证；未定字段和兼容性策略有记录。
- 检查无敏感明文样本与硬编码密钥；列出 M2 专项输入与阻断点。

### 数据契约与初版表映射（M1 草案）

下表用于追溯现有结构，不表示对应业务、访问权限或加密协议已经实现。SQL 均由同一迁移框架执行，已发布的迁移不改写；以下时间字段初版使用 Unix 毫秒。

| 需求与实体 | 共享类型 | D1 迁移 | 当前边界 |
| --- | --- | --- | --- |
| FR-USR-1～3：用户 | `User` | `0003_users.sql` | 不含登录凭据或认证流程；用户隔离仍须在服务端查询实现。 |
| FR-IA-1/3、FR-VER-6：主题与分组 | `TopicNode` | `0004_topics.sql` | 含用户归属、父节点、深度和软删除字段；父子层级合法性及权限仍须服务端校验。 |
| 需求 5.1/5.2、FR-SYNC-1/2、FR-ENC-1/5：Memo / Note / 表格 | `Memo`、`Item`、`StoredContent` | `0005_items.sql` | 用户归属、版本、墓碑、引用与明文/密文互斥列为初版；不是加密或同步实现。 |
| FR-SYNC-7/8：附件元数据 | `Attachment` | `0006_attachments.sql` | 仅元数据与用户归属；密文寻址、引用计数和清理须在 M2 专项确认。 |
| FR-VER-1/5：版本快照 | `ItemVersion`、`VersionSnapshot` | `0008`～`0011` | 普通与加密快照列互斥，并阻止加密条目保留明文历史；不验证密文真实性。 |
| FR-MCP-2/6：令牌与审计 | `McpToken`、`McpAudit` | `0012_mcp_tokens.sql`、`0013_mcp_audit.sql` | 令牌仅预留密文列；生成、加密、可见性与审计服务未实现。 |
| FR-BAK-1/2：备份目标 | `BackupTarget` | `0014`、`0016`、`0017` | 凭据仅预留密文列；旧记录升级后默认不启用，备份与恢复未实现。 |
| FR-USR-2/3：设置 | `UserSetting` | `0015_user_settings.sql` | 用户归属及普通/敏感列互斥；设置分类、凭据加密和权限未实现。 |
| FR-MON-1/3：监控样本 | `MonitorSample`、`MonitorSummary` | `0001`、`0002`、`0007` | 当前仅安装级测试采样；正式用户隔离和账户级用量尚未接入。 |
| FR-SYNC-3～5：同步消息 | `SyncPage`、`SyncTombstone`、`OutboxOperation` | 尚无 outbox / 同步迁移 | 仅消息草案；游标、错误/409 详情、事务与冲突协议未定，不可作为正式同步实现。 |

`StoredContent` 的密文字符串与 D1 BLOB 之间的编码、内容哈希的加密边界、密码/恢复码包装和密钥轮换均须在 M2 专项设计及安全评审后确定。M1 不存储主密码、明文恢复码或明文内容密钥；上述占位字段本身不提供密码学保证。

### 样式 token 层与 UI 基础

- **状态**：已完成（2026-10-31）
- **目标**：完成 M1 所需的样式 token 层与 UI 基础并形成可交接的验证证据。
- **需求与输入**：FR-STYLE-1、C-5、NFR-8；视觉参照 `DESIGN.md` 和 `wiki/design.html`
- **依赖**：仓库骨架；健康页与监控可复用，搜索入口位置待定。

## 范围与实施步骤

1. 抽取语义化 `app-*` 外壳与独立 `md-*` 渲染 tokens，集中管理颜色、尺寸、间距、字体、圆角与状态；shadcn 映射放 tokens/UI 层。可调整默认值，不将具体像素或颜色嵌入业务组件。
2. 提供轻量应用布局壳及必要基础控件，以组件组合和样式变量承载布局；业务逻辑、网络/数据库访问留在 service，不将视觉方案做成业务判断。避免为可能的调整预建通用页面搭建器或复杂配置框架。
3. 同一结构支持浅/深配色，基本焦点、键盘与可读对比度；窄屏应可操作，尺寸和断点集中管理。状态、内容及展示分离，换布局或 token 不要求改数据契约。
4. 只做 M1 所需的空壳、健康页和监控基础控件；交互样例明确标识为样例，不把未实现功能呈现为可用。
5. 侧栏顺序遵循已同步的 FR-IA-4；搜索入口位置待定，保留可调整组合边界。

## 验收与交付

- 修改集中 token 能改变外观且不影响逻辑；渲染与外壳样式可独立调整；抽查无组件样式硬编码。
- 核查浅/深色、键盘焦点和基本对比度；以 1920×1080 视口检查桌面，并记录可执行的窄屏检查和截图；未验证不标通过。
- 应用壳可构建，核心健康/监控状态可访问；不提前实现 M2/M3 业务或把探索稿具体尺寸写成不可变验收条件。
