## 2026-11-16：Flomo 导入 + 随记标签正文化（0.2.99）

- **来源**：负责人要求把账户菜单里已就位的导入入口接成可用功能——把 Flomo 导出的压缩包导入随记；同时提出「标签不要单独一排，挪到正文里，以后在正文里随便哪里写标签都行」，并确认：完全落成随记、保留原始创建时间、正文保留 `#标签` 原文（同时提取成标签）、图片一并导入而语音等类型跳过、导入条目统一加 `#flomo` 来源标签。
- **真实导出核对**：负责人提供一份真实导出包（`flomo@MaxxieL-20261116.zip`，197 条 / 14 图 / 6 标签）。解包后确认结构与公开解析器一致，但有两处关键细节：结构化标签在 `div.memo[data-tags]` 上，正文里同时留着 `#标签` 原文；图片路径多一层用户 ID 目录（`file/<日期>/<用户ID>/<hash>.jpg`）；纯图片条目的 content 是空的，个别条目字面量写着 `null`。导出包放在工作区 `.temp/`（已加入 `.gitignore`，结构门禁按本地产物登记），全程只在本机解析，未上传任何服务器。
- **标签口径（shared `memoTags.ts`）**：`extractTags` / `appendTags` / `toggleTagInText` 三个纯函数，前后端共用（Web 保存随记、Worker MCP 建随记同一份规则）。识别规则：`#` 紧跟非空白字符，且前面不是 ASCII 字母/数字/路径字符——因此 Markdown 标题（`# 标题`）、URL 锚点（`example.com#a`）、`C#` 都不误判；标签名尾部的中英文标点不计入。
- **标签正文化落地**：`tags` 字段退化为从正文解析出的索引。`createMemo` 与 `saveItemContent`（随记）按正文回写标签；`MemoCard` 去掉标签行，改为把存量标签补到正文末尾后展示与编辑（编辑保存一次即落库）；随记输入框与引述面板的标签控件从「勾选状态」改为「点标签即在正文写入/移除 `#标签`」；Worker MCP `create_memo` 也把传入标签写进正文，扩展快速入口与前端口径一致。
- **标签改名/移除同步改正文**：标签管理器明确管「普通空间和随记使用的标签」，移动端条目的标签编辑也会改随记标签；若只改 `tags` 字段，下次保存正文时标签会被正文覆盖回旧值。因此新增 shared 的 `renameTagInText` / `removeTagFromText` / `setTagsInText`，标签管理器改随记时写正文（普通文档仍走标签字段），移动端随记标签编辑改为整组替换正文标签。
- **解析器（`lib/flomoParse.ts`）**：`fflate` 解包 → 取包内最大 HTML + `file/` 附件目录 → `DOMParser` 取 `div.memo` → 时间按本地时区解析 → 正文 HTML 转 Markdown（段落、加粗、斜体、删除线、列表、引用、链接、行内代码；外来文字色映射到 Menote 白名单最近色，其余样式丢弃但文字保留）→ 图片转占位符。纯函数、可单测。
- **导入服务（`services/flomoImportService.ts`）**：图片走既有 `uploadAttachment`（受账号附件策略与 20 MiB 硬上限约束），正文按占位符替换为 `attachments/<sha>--<name>` 引用；条目批量落库（每 50 条一个事务，条目与 outbox 同事务写入）；去重键为「创建时间 + 正文哈希」，重复导入同一包全部跳过；单条失败不中断整批，结果给出成功/跳过/失败与图片上传计数。
- **界面**：`features/import/FlomoImportPanel.tsx` 接入账户菜单导入窗口——选包 → 摘要（条数/时间范围/标签数/图片数）+ 前三条预览 → 确认导入 → 进度条 → 结果。Obsidian / Notion 仍显示「即将开放」。
- **验证**：`pnpm -r typecheck` 通过；`pnpm build`（含 Worker dry-run）通过；`pnpm test` 全绿——shared 19 / web 146 / worker 100（新增 shared 标签用例 8 条、解析器用例 4 条、导入服务用例 3 条、导入面板 UI 用例 2 条）。真实导出包本机回归：197 条、14 张图零缺失、6 个标签与导出页筛选下拉一致、时间范围 2020-12-09 → 2026-05-18，无空条目。

## 2026-11-16：文档「查看源码」按正常显示区域铺开（0.2.100）

- **来源**：负责人走查反馈——表格的「查看 Markdown 源码」已正常，但**文档（Note）模式的源码仍只占一小块窗口、内部滚动**，要求源码按正常显示区域铺开显示。
- **根因**：源码 textarea 挂在 `.mn-editor-host`（flex 列）里，`flex: 1` 只在父级是 flex 容器时生效。文档形态下 `.mn-doc-main` 是普通块（`inkstand-pages.css` 里作为纸面卡片），`.mn-docbody` 又是唯一整页滚动容器，flex 高度无处伸展，于是 textarea 停在 `min-height: var(--app-editor-min)`（12rem）——看上去就是「一小块窗口里滚动」。表格源码视图没有这个问题，它走的是 `doc.css` 里表格专属的「文档区 flex 列 + 网格自身滚动」范式。
- **做法**：把表格那套范式搬到文档形态。`NoteDocument` 根节点补 `data-editor`（wysiwyg / source），`doc.css` 新增源码态规则：纸面 `.mn-doc-main` 改列向 flex 并 `align-self: stretch`（撑满文档区行高），标题/属性/标签等固定块 `flex: none`，编辑器外层与宿主 `flex: 1 1 auto` 吃掉余下高度；窄屏（compact/tablet/mobile）文档区不是栅格，改用列向 flex 铺开。所见即所得形态不受影响（规则只认 `[data-editor="source"]`）。
- **量测**：临时搭了一个复刻文档区结构的静态页（本机 HTTP 服务 + 内置浏览器量高，已删除临时文件，`.temp/` 仍只剩原始导出包）：改前源码区 192px（=12rem）、改后 303px 并随窗口铺满，窄屏 474–482px；量测期间文档区不再整页滚动，源码自身滚动。
- **验证**：`pnpm -r typecheck` 通过；`pnpm test` 全绿——shared 19 / web 148 / worker 100（新增 web 用例 2 条：源码态标记与铺开样式的静态契约）。
- **文档 / 版本**：项目补丁版本 `0.2.99 → 0.2.100`；需求说明书未改（源码态属 FR-EDT-3 既有形态，本次只修显示区域，不改行为口径）。
- **合并与推送**：dev 上提交 `6ec382b`（fix: 文档源码视图按正常显示区域铺开（TP15，0.2.100）），经负责人指示快进合并到 main（外来提交清点：dev 相对 main 仅本任务一笔），已推送 origin/dev 与 origin/main；main 推送触发 Workers 正式构建。
- **遗留**：真实应用内走查（文档 → 更多 → 源码）待负责人验收；浏览器真机走查（导入窗口、标签正文化后的随记卡片与输入框）仍未做。
