## 2026-11-04：空拉取误报成功修复（0.2.10）

**问题定位**：绑定只负责补齐收藏列和「行 ID」，不会导入收藏。用户确认收藏夹 ID 为 `0`（Raindrop 全部收藏），手动拉取仍记成功且计数全 0。检查发现 API 客户端只判断 HTTP 状态码；Raindrop 返回 `result: false` 且没有 `items` 时，分页代码会把响应当空收藏列表，随后写入 `ok` 运行记录。这样会掩盖令牌/接口错误。

**修复**：`raindropApi.call` 现在在处理数据前检查 `result: false`，并使用服务端错误描述抛错。令牌验证失败会拒绝保存；拉取失败会记为失败并在设置页同步记录显示原因，不再伪报“成功 0 条”。根包补丁版本 `0.2.9 → 0.2.10`。

**验证状态**：本轮未运行测试或构建；需部署包含该修复的 Worker 后再手动拉取，观察同步记录是正常计数还是明确错误。

- `raindropApi.ts`：`getRaindrop` / `createRaindrop` / `updateRaindrop`（PUT 只带差异键）、`findRaindropByLink`（精确链接全量扫描，不用搜索语义）、`diffFieldKeys`。`type` 不在可写键里（Raindrop 自行判定）。`capturedAt` 任一侧为空或不可解析时视为通配相等：不把空的「采集时间」推上去覆盖远端 `created`，也不让服务端补的时间戳把未填时间的行永远标脏。
