## 1. 负责人本轮决策（2026-11-03）

1. **中间件表模型**：专门用一张 Menote 表格文档作为网页收藏中间件；Raindrop 与浏览器插件都往里写，网页端（Menote）在该表内编辑。
2. **自动拉取**：绑定后定时把 Raindrop 收藏拉进该表。此条是对主文档 7.4「首版手动上传/下载」边界的修订，需求说明书与主文档需同步登记。
3. **反推云端备份**：表内修改后的数据反推回 Raindrop 作为云端备份；反推数据必须干净准确，**不得损坏 Raindrop 线上数据**。
4. 浏览器插件收藏继续写入该表（TP3 首版已实现，本任务包不动插件链路，仅补行 ID 列，见 3.3）。

**第二轮补充决策（2026-11-03，四点确认全部通过）**：

5. 行 ID 列在表格中**可见**；令牌采用 Test Token 粘贴录入；拉取频率默认每小时、绑定级可关；推送冲突行报告后人工处理，不自动选边。
6. **同步记录**：保留最近同步运行记录，逐次记下推了几条（创建/更新）、拉了几条（新增/更新）、冲突、失败数与结果状态，设置页可查。
7. **拉取快照兜底**：每轮拉取在 Menote 侧（R2）留存远端原始 JSON 快照作为风险兜底；内容无变化时复用上一份快照，按保留策略清理过旧快照。
8. **插件开关**：设置新增插件开关，启用才显示 Raindrop 设置页，不启用不显示；开关任何状态都**不得影响应用本身的使用**（连接器关闭时定时任务跳过、路由 fail-closed，其余功能零感知）。

## 3. 总体设计

### 3.1 数据流

```text
Raindrop.io ──定时拉取──▶ ┌────────────────────┐ ◀──收藏网址── 浏览器插件
      ▲                    │ 中间件表（绑定的表格文档）│
      └──手动预览+确认上传── └────────────────────┘
                             Menote 网页端编辑
```

- **拉取自动、推送手动**：首版刻意不对称。拉取只改本地表（出错可恢复）；推送写远端（出错难恢复），必须经预览确认。

### 3.2 绑定与元数据（存 D1，不写入 Markdown 正文，主文档 7.3/v0.7 定稿）

- `raindrop_bindings`：user_id、table_item_id、collection 范围（默认全部）、字段映射（首版固定为收藏标准列）、令牌密文、拉取频率、绑定状态、last_pull_at / last_push_at。
- `raindrop_sync_rows`：binding_id、menote_row_id、raindrop_id、baseline（上次成功同步时的字段快照 + 内容 hash）、status（`synced` / `dirty` / `conflict` / `orphaned` / `remote_missing`）。
- `raindrop_sync_runs`：binding_id、direction（`pull` / `push`）、起止时间、status（`ok` / `partial` / `failed`）、分类计数（拉取新增/更新、推送创建/更新、冲突、远端消失、失败）与摘要——同步记录 UI 的数据源，设置页可查最近若干次。
- 令牌：首版由负责人在 Raindrop 设置页创建 Test Token 后粘贴录入；AES-GCM 加密存 D1，默认不明文展示、支持事后查看与复制分发（同凭据回显标准），不进日志；OAuth 作为后续可选增强。

### 3.3 行身份（关键前置）

- 绑定表格自动补一列**「行 ID」**（短随机 ID）；插件写表格路径（`mcpBookmarkFormat` COLUMNS）同步补齐该列；绑定流程对存量行一次性回填。
- 行 ID 是 Markdown 行与 D1 账本之间的唯一锚点；**绝不按行位置或 URL 推断行身份**（主文档 7.3：仅凭 URL 不足以保证可靠匹配）。
- 待负责人确认：行 ID 列在表格中可见（推荐，备选方案均有脆弱性）。

### 3.4 拉取（自动）

1. 分页拉取远端全量（约 414 条 ≈ 每页 50、9 页；范围按绑定的 collection）。
2. 逐条分类：
   - 账本已知 `raindrop_id` 且远端内容有变 → 重写对应行；
   - 已知且远端无变 → 跳过；
   - 未知 `raindrop_id` → 追加新行并登记账本；
   - 本地行已绑定但远端已消失 → 账本标记 `remote_missing`，行内容不动，拉取报告列出。
3. **不静默覆盖本地编辑**：某行本地有未同步修改（内容 ≠ baseline）且远端也有变化时，保留本地、标记 `conflict`，由推送预览/报告人工处理；其余远端变化正常落表并刷新 baseline。
4. 同 URL 疑似重复：新拉取行与本地未绑定行同 URL 时**不自动合并**，照常追加并在报告列「疑似重复」（主文档 7.3：不自动把同 URL 当同一书签）。
5. 写表格一律走 `applyOperation` 契约；遇冲突本轮跳过、下轮重试，绝不静默覆盖。
6. 每轮成功后把远端原始 JSON 快照写入 R2（主文档 7.5：同步≠备份，需独立快照）：内容 hash 与上一份相同则复用不重复写；按保留策略（保留最近 100 份）清理过旧快照；设置页可见最新快照时间，作为远端数据的风险兜底。
7. 频率默认每小时（复用现有 cron），绑定级可调、可关；令牌缺失/无效或插件开关关闭时跳过并记录，fail-closed 不刷错误。
8. 每轮运行无论成败都落一条 `raindrop_sync_runs` 记录（含分类计数），设置页可查。

### 3.5 推送（手动反推，云端备份）

1. 用户在设置/表格页触发「同步到 Raindrop」→ 服务端基于 baseline 算差异：
   - 未绑定行 → 将创建；
   - 已绑定且行内容 ≠ baseline → 将更新（列出到字段级）；
   - 其余行不动。
2. 预览确认后逐条调用 Raindrop 单条接口（创建 `POST /raindrop`、更新 `PUT /raindrop/{id}`）；「采集时间」映射 Raindrop `created`（TP3 可行性文档定稿；真实账号验收验证 UI 展示）。批量接口字段覆盖不全，不用于全字段推送。
3. 干净准确性保障（本任务包核心验收）：
   - **只推 diff 字段，不整条盲写**；成功后才写 `raindrop_id` / 刷新 baseline；
   - **创建防重复**：创建请求超时或结果未知时，先按 URL 精确回读远端——已存在则绑定既有 `_id`，绝不重复创建；
   - **推送前回读防覆盖**：每个 dirty 行先 GET 单条回读远端当前值，与 baseline 比对；远端 ≠ baseline（远端也变了）→ 该行标记 `conflict` 不自动推，报告人工处理（落实主文档 7.4「不静默覆盖」）；
   - 限速节流按官方限额分批；逐条失败单独记录、可续传，不回滚批次已成功部分；
   - **熔断**：单次待推数量异常（如 > 绑定行数的 50%）要求二次确认；
   - **不提供远端删除**：本地删行 → 账本标记 `orphaned`，远端不动（主文档 v0.7 定稿：首版无远端删除入口）。
4. 结果报告：创建/更新/冲突/失败分明，含远端 `_id`，可追溯。

### 3.6 安全红线对照

- 令牌密文存储、默认不明文展示（可事后查看/复制分发）、不写日志（同 `mcpTokenCrypto` 标准）；
- 推送请求/响应不落正文日志，只记 ID 与结果；
- 绑定目标必须是明文表格文档且在权限范围内（校验同 `readMcpBookmarkTarget` 一类）；
- 私人空间与加密内容不受连接器影响；令牌缺失 fail-closed。

### 3.7 设置页与插件开关

- 设置新增**插件**开关（默认关闭）：启用后设置页显示 Raindrop 面板（令牌录入、绑定配置、拉取频率、立即拉取、同步记录、快照信息）；关闭则整块隐藏。
- 开关只 gate 连接器自身：关闭时定时任务跳过、Raindrop 路由拒绝服务，**应用其余功能零感知、零依赖**（表格文档与插件收藏在未启用/断开状态下照常工作）。
- 绑定流程：选择目标表格文档（下拉或填链接/ID）→ 服务端校验明文表格 → 自动补「行 ID」列并回填存量行 → 首轮拉取。
