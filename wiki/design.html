01

首页

默认落点 · 单栏一屏装下 · 每张卡都是一次点击
首页不是仪表盘：它只放两样——能力地图（能做什么，每张卡一个动作）和状态快照（有多少，一行说明）。回顾类统计已经在 Memo 工作栏里，再画一遍就是两套排序规则。
单栏且不滚动：一列自上而下四块（行动 / 状态 / 最近编辑 / 浏览入口），在 792 高度内一屏装完，不产生滚动条；窗口更矮时才退化为可滚动。首页的价值是「一眼看全」，看不全就白做了。
侧栏暂时没动：最近编辑与收藏仍留在原位（FR-IA-4 的回看区），与首页的状态卡并存——侧栏给直达入口，首页给快照。谁让位等入口用顺了再定，不在这次一起砍。
分段变三格：首页 | 笔记 | Memo，三个目的地互斥。树上的层级选中与它用不同的选中语言（白底橙条 vs 白底阴影），可以同时存在而不互相误读。
待整理仍在侧栏：收件箱 / 草稿箱是待办队列，计数必须常驻可见，不能等用户进首页才发现。
冷启动不空壳：全 0 时行动条照常在（记 Memo / 新建笔记 / 搜索），状态卡显示 0，最近编辑区换成一句引导，不出现死面。
待你确认：本页改了两条定稿表述——①侧栏新增「首页」入口，视图切换为「首页 | 笔记 | Memo」；②默认落点由「清单第一行」改为「首页」。需求说明书 FR-IA-4 与主文档 2.3 我没有擅自改，确认后再同步。
02

主界面 · 浅色

侧栏 / 笔记清单 / 文档，三栏三密度
A4 形态切换补齐了缺的那一半：原来侧栏只有「Memo 时间线」一个形态入口，Note 形态没有入口，所以从 Memo 回不去——这是信息架构缺口，不是样式问题。
为什么用分段控件：树上的选中项表达「位置」，形态切换表达「换一种内容形态」，两者正交。若也做成带橙条的导航行，会与树的选中打架（DESIGN §4.2 三种选中必须区分）。
A6 由并排白块改两行：中文标签＋计数在 114px 里已经贴边；并排两块还借用了「侧栏选中 = 白底」的语言，读起来像同时选中了两项。
为什么紧贴主题树：待整理的唯一终点是归类，归类发生在下面的树里。放在树之上的最后一段，动作和目标是相邻的。
计数只给收件箱上橙：收件箱是外部／Agent 推来的未知增量，需要提示；草稿箱是自己建的已知存量，自己心里有数。两个都上橙，橙就不再有指示意义。
清空即退场：计数归零后收件箱不再高亮，不再留「0」占位；队列本身常驻，不做自动过期删除（FR-IA-2）。
待你确认：新增 A4 会改动 FR-IA-4 的侧栏条目表述（原为「Memo 时间线／最近编辑／收藏」），并按主文档 2.3 的导航顺序调整。这是对定稿的补充，我未擅自改动需求说明书与主文档；确认后再同步。

04

Memo 时间线

顶栏（返回＋视图切换）/ 工作栏 / 时间轴 / Todo 浮条，不打开完整编辑器
两个返回入口分工：侧栏 A4 是「换形态」，常驻、双向，滚到多深都在；顶栏 D4 的「← 笔记」是「回去」，就地在内容区左上角，回到你刚才那篇的确切位置。
为什么不做「首页」：桌面端三栏本身就是主界面，再造一个首页会让「主题树在哪」变成第二个问题。返回的目标是「上次那篇笔记」，不是一张概览页（首页概念只在移动端成立）。
就地返回不抢戏：24px 高、无底色、无边框，只在悬停时浮出浅底；它与右侧的视图切换同一行，但颜色更弱——返回是退路，不该比内容更响。
位置记忆：切到 Memo 再回来，树上的选中项与清单滚动位置都不变，筛选不被清空。
键盘：⌘1 笔记 / ⌘2 Memo，与 A4 等价；Esc 不承担返回，避免与关闭浮层冲突。
05

Memo 图册 · 图片瀑布流

同一批 Memo 附件的另一种排布，不是独立图库类型
3 列 masonry：列数固定，图片按原始宽高比落位，缩略图不裁切——裁切会让人认不出自己的素材。
懒加载占位保比例：未进视口的图只画骨架，但占位块按原比例预留高度，滚动时不跳版。
不是独立类型：瀑布流不新增内容形态，图册 = Memo 附件的筛选视图。点任一张回到它所属的 Memo 原位。
归属仍在 Memo：每张图下保留来源 Memo 的时间与标签，删除/改状态在原条目里生效，图册不产生第二份状态。
加密条目不出现：私人空间与单篇加密 Memo 的附件在图册中按可见性谓词整体排除，不做缩略图缓存。

浅色 · 常态滑块 6px，轨道透明，对纸面 1.75:1

材质工作流

材质不靠单张贴图堆细节。基础层只负责底色与粗糙度，细节层用平铺遮罩控制磨损位置，混合层解决边缘过渡——三层各自可替换，改一处不会全盘崩。

任何一层出问题，都能单独回滚，不需要重做整份材质。这是分层的第一条纪律。

滚动条常态刻意压到 1.75:1，低于 3:1。它不该与正文争夺注意力，只有当指针移上去时才升到 3.29:1——那时它才需要被看见。

全局接管：侧栏、清单、文档、编辑器、Memo 时间线、todo 侧板、状态页、设置对话框、代码块、宽表格、版本对比，共 11 处滚动容器。
布局稳定：槽位由 scrollbar-gutter: stable 恒定预留，滚动条出现与否不改变内容宽度，正文不重排。
移动端：触屏由 data-pointer="coarse" 判定，交回系统覆盖式滚动条，不占布局宽度。
Firefox 降级：标准属性无法做内缩，发丝线宽度不可得，仅保颜色；Chrome 121+ 用 @supports not selector() 隔离，避免标准属性反向覆盖伪元素。
不与橙色争：滚动条只用中性灰，不使用强调色——它是结构件，不是可点击目标。
