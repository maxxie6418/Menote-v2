01

首页

默认落点 · 单栏一屏装下 · 每张卡都是一次点击
零卡片描边：上一版一屏 15 个描边盒子，同样的灰度、同样的圆角、同样的尺寸，看久了像格纸。现在全页没有一个 1px 描边——分区靠留白、发丝线和一层凹陷底色。
黑体管标题，等宽管数据：主锚点是 27px 无衬线日期标题，第二锚点是等宽数字带。等宽只出现在数字上（时间、计数、篇数、快捷键），一眼就知道那是可数的量。
可点的东西是块，能读的东西是字：动作区三块凹陷底色（要能被瞄准），状态区一排等宽数字 + 竖发丝分隔（要被读数）。两者不必长得一样。
侧栏顶部原来连着三个框：灰槽 + 白块 + 虚线输入框。视图切换改成文字标签 + 橙下划线，顶部少一个灰盒子；Memo 记录条从「装好的输入框」改成「虚线提示行」，点了才展开。
树要分出层级：一级主题 600 墨色、分组浅一档小一档——一串同粗的灰字像清单不像目录。
选中不再贴橙条：行选中（主题树／回看／待整理／清单）改用底色浮起——侧栏是灰底，白块天然浮起；清单是白底，淡橙底才看得见。左边那根色条贴着圆角会弯成括号，既突兀又不属于本项目的选中语言，整个去掉。
待你确认：本页改了两条定稿表述——①侧栏新增「首页」入口，视图切换为「首页 | 笔记 | Memo」；②默认落点由「清单第一行」改为「首页」。需求说明书 FR-IA-4 与主文档 2.3 我没有擅自改，确认后再同步。
02

主界面 · 浅色

侧栏 / 笔记清单 / 文档，三栏三密度
A3 视图切换补齐了缺的那一半：原来侧栏只有「Memo 时间线」一个形态入口，Note 形态没有入口，所以从 Memo 回不去——这是信息架构缺口，不是样式问题。
为什么用分段控件：树上的选中项表达「位置」，形态切换表达「换一种内容形态」，两者正交。若也做成带底色的导航行，会与树的选中打架（DESIGN §4.2 选中必须区分）。
A7 由并排白块改两行：中文标签＋计数在 114px 里已经贴边；并排两块还借用了「侧栏选中 = 白底」的语言，读起来像同时选中了两项。
为什么紧贴主题树：待整理的唯一终点是归类，归类发生在下面的树里。放在树之上的最后一段，动作和目标是相邻的。
计数只给收件箱上橙：收件箱是外部／Agent 推来的未知增量，需要提示；草稿箱是自己建的已知存量，自己心里有数。两个都上橙，橙就不再有指示意义。
清空即退场：计数归零后收件箱不再高亮，不再留「0」占位；队列本身常驻，不做自动过期删除（FR-IA-2）。
待你确认：新增 A3 会改动 FR-IA-4 的侧栏条目表述（原为「Memo 时间线／最近编辑／收藏」），并按主文档 2.3 的导航顺序调整。这是对定稿的补充，我未擅自改动需求说明书与主文档；确认后再同步。

Memo 时间线

顶栏（返回＋视图切换）/ 工作栏 / 时间轴 / Todo 浮条，不打开完整编辑器
两个返回入口分工：侧栏 A3 是「换视图」，常驻、双向，滚到多深都在；顶栏 D4 的「← 笔记」是「回去」，就地在内容区左上角，回到你刚才那篇的确切位置。
为什么不做「首页」：桌面端三栏本身就是主界面，再造一个首页会让「主题树在哪」变成第二个问题。返回的目标是「上次那篇笔记」，不是一张概览页（首页概念只在移动端成立）。
就地返回不抢戏：24px 高、无底色、无边框，只在悬停时浮出浅底；它与右侧的视图切换同一行，但颜色更弱——返回是退路，不该比内容更响。
位置记忆：切到 Memo 再回来，树上的选中项与清单滚动位置都不变，筛选不被清空。
键盘：⌘1 笔记 / ⌘2 Memo，与 A3 等价；Esc 不承担返回，避免与关闭浮层冲突。
05

Memo 图册 · 图片瀑布流

同一批 Memo 附件的另一种排布，不是独立图库类型
3 列 masonry：列数固定，图片按原始宽高比落位，缩略图不裁切——裁切会让人认不出自己的素材。
懒加载占位保比例：未进视口的图只画骨架，但占位块按原比例预留高度，滚动时不跳版。
不是独立类型：瀑布流不新增内容形态，图册 = Memo 附件的筛选视图。点任一张回到它所属的 Memo 原位。
归属仍在 Memo：每张图下保留来源 Memo 的时间与标签，删除/改状态在原条目里生效，图册不产生第二份状态。
加密条目不出现：私人空间与单篇加密 Memo 的附件在图册中按可见性谓词整体排除，不做缩略图缓存。

材质工作流

材质不靠单张贴图堆细节。基础层只负责底色与粗糙度，细节层用平铺遮罩控制磨损位置，混合层解决边缘过渡——三层各自可替换，改一处不会全盘崩。

任何一层出问题，都能单独回滚，不需要重做整份材质。这是分层的第一条纪律。

滚动条常态刻意压到 1.75:1，低于 3:1。它不该与正文争夺注意力，只有当指针移上去时才升到 3.29:1——那时它才需要被看见。

侧栏树区、清单、文档、编辑器、时间线、todo 侧板、状态页、设置对话框、代码块、宽表格、版本对比——十一处滚动容器共用同一套令牌，任何一处新增都不必重复声明。

槽位由 scrollbar-gutter 恒定预留：内容从短变长时，滚动条出现不改变可用宽度，正在阅读的段落不会突然换行。

05

交互与状态

两个操作互不阻塞；所有失败都在原位给一句话原因和一个下一步，不弹 alert，不整页遮罩。

01
点「剪藏此页」

校验连接 → 注入提取（模板 → 站点适配 → Readability）→ 有图且已授权时上传附件 → clip_page 写入。

02
成功

chip 变为「已剪藏 · 刚刚」，提示条给「已剪藏到收件箱」+ 查看入口。再点一次会新建一篇文档，不覆盖旧文档。

03
失败

提示条一句话原因（Token 失效 / 无权限 / 超时 / 无正文）+ 重试或前往设置，页面其余部分保持可用。

04
点眼睛区

新标签页打开预览，正文不进 URL 参数。预览页可编辑并提交编辑后的文本；提交成功后回写本地记录，主界面下次打开即显示已剪藏。

05
状态来源

三枚 chip 全部来自本地 menotePageActions（上限 500 条，按 URL 去 hash）。清扩展数据、换设备或超出上限后状态即丢失，这是刻意的取舍。
