## 1. 产品概述

### 1.1 定位

Menote 是面向个人的记录、整理、检索与阅读工具：**Memo（非正式随手记录）+ Note（正式文档）** 双内容形态，固定加密主题与单篇密码保护，结构化存储与增量同步，S3/WebDAV 远程备份，MCP 对外 Agent 接口，Cloudflare 免费层一键部署。不向项目管理、数据库自动化或工作流平台扩展。

### 1.2 内容形态

| 形态 | 定位 | 使用方式 | 存储原则 |
| --- | --- | --- | --- |
| **Memo** | 非正式、即时、轻量 | 时间线浏览、快速录入、原位修改 | 数据库独立记录；正文为 Markdown 字符串 |
| **Note** | 正式、长期、可整理 | 按主题组织、完整编辑、阅读检索 | Markdown（含 YAML frontmatter）为规范格式 |

- todo 是 Memo 的辅助组织方式，不是第三种顶层内容；Note 的 YAML `status` 不进入 Memo todo 面板。
- 附加视图（todo、瀑布流）与收集入口（收件箱、草稿箱、剪藏、Android）均依附于两种形态；加密是 Note 的能力，不制造第三种内容形态。
- **多用户**：默认单用户使用；多用户间数据完全独立、互不共享（见 FR-USR）。

### 1.3 范围外（明确不做）

任意主题整体加密；表格公式/自动化/跨表关系/数据库式工作流；Memo 按月物理文件存储；实时双向同步（连接器首版为自动定时拉取 + 手动反推上传，v1.27）；用户可装插件生态（首版内置适配器先行）；跨用户协作或内容共享；**V1 数据迁移（V1 无存量内容，V2 为全新数据起点）**。

### 3.7 加密与隐私（FR-ENC）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-ENC-1 | 两种作用域：**固定私人空间主题**（唯一、可含分组、主题级锁定/解锁）与**普通主题内单篇密码加密**（留原位、单篇解锁）；不做任意主题整体加密；Memo 不入私人空间 | P0（M2） |
| FR-ENC-2 | 必须是**真实内容加密**：未经授权不能通过任何接口获取正文、附件明文；每篇独立内容密钥，私人空间内由主题密钥包装（不以"整主题一个大文件"为目标） | P0（M2） |
| FR-ENC-3 | **三凭据分离**：登录密码 ≠ 私人空间密码 ≠ 单篇密码，互不连坐；两种解锁作用域相互隔离。私人空间密码最少 4 位、单篇密码最少 6 位，均不另加大小写、数字或符号要求；这只放宽记忆门槛，正文仍真实加密。登录口令仍至少 8 位 | P0（M2） |
| FR-ENC-4 | 锁定策略：新会话默认锁定 + 不活动超时自动锁定（默认 15 分钟、可配置）+ 随时手动锁；单篇默认离开该笔记即重新锁定（未保存改动的安全处理由实现保证） | P0（M2） |
| FR-ENC-5 | **标题明文**：加密笔记标题保持明文（锁定态列表可辨识、可按标题检索）；正文与附件始终密文；缩略图、历史版本、缓存只处理密文；服务端存储与列表接口中标题为明文元数据（已知并接受的边界） | P0（M2） |
| FR-ENC-6 | **单一恢复码体系**：全账户一个高熵恢复码；启用加密的内容密钥一律双包装（密码 + 恢复码，明文码永不入库）；遗失密码凭码解锁/重设；换码统一重包装；恢复码遗失 = 内容永久不可解（强提示）；单码泄漏爆炸半径 = 全部加密内容（UI 明示）。**服务端托管解密/后台密钥重置不作为当前机制**（当前恢复路径 = 恢复码），列为可选后续方向——若引入须专项安全审查（C-7） | P0（M2） |
| FR-ENC-7 | 解锁 ≠ 分享：本机解锁不放宽服务端访问控制；分享机制独立设计；是否支持加密内容在线共享待后续确定 | P0 |
| FR-ENC-8 | 加密封装、密码派生、密钥算法（AES-GCM + Argon2id/PBKDF2 等选型）属技术设计，实施前勘查 V1 隐私锁/单篇门禁实现并核实三凭据分离 | P0（M2） |

验收：三凭据互不影响；锁定态检索/缓存/缩略图/历史均为密文；恢复码解锁/重设/换码全链路可用；未授权接口取不到明文（含解锁状态下经 MCP）。

## 5. 数据规格（定稿口径）

### 5.1 Memo 记录字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 全局唯一、生成后不变；同步与引用锚点 |
| `content` | string | Markdown 正文，唯一内容真相 |
| `tags` | string[] | 内容分类标签；任务状态不用标签表达 |
| `status` | `todo`/`doing`/`done`/`null` | 任务状态；null 为普通 Memo |
| `attachments` | 附件引用[] | 指向附件存储的引用 ID |
| `source` | string | 来源：手动 / Agent / 采集 |
| `createdAt` / `updatedAt` | timestamp | 创建与最后修改 |
| `deletedAt` | timestamp/null | 回收站与同步墓碑 |

（具体表结构、索引与迁移属技术设计；备份 JSON 必须完整覆盖上述字段。所有记录按用户隔离，FR-USR。）

### 5.2 Note

Markdown + YAML frontmatter 为规范内容；属性区类型定义存 YAML 保留命名空间；表格主体文档的 `fields:` 存字段定义。

### 5.3 附件

R2 内容寻址（sha256）去重；md 引用 `attachments/<sha256>--<原文件名>`；引用对齐用正文哈希列表；加密附件密文存储。

### 5.4 备份包

结构化 JSON（记录、主题树、附件清单、密钥包装元数据：密码包装块 + 恢复码包装块）+ 附件文件 + manifest（逐文件版本、长度与哈希，COMPLETE 存 manifest 哈希）；每次推送生成独立时间戳目录，目录内按月分片；按用户隔离。

### 5.5 凭据清单

| 凭据 | 展示策略 |
| --- | --- |
| `AUTH_PEPPER` | Cloudflare 平台机制（设置后平台不提供读取）；应用侧不涉及回显 |
| 登录密码 | 不存储明文；无法回显 |
| 私人空间 / 单篇密码 | 不存储明文；无法回显 |
| 恢复码 | 明文码不入库；仅在设置/轮换时展示一次 |
| **MCP 令牌** | **支持事后查看与复制分发**（可逆加密存储） |
| **备份目标凭据** | 加密存储；默认不明文展示，支持事后查看与复制分发 |
| **监控增强 Token（可选）** | 同备份目标凭据 |

1. **一键部署（发布候选门 = M4 末）**：FR-DEP-11 六条场景全过；
