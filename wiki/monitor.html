资源状态页方案

对应 FR-MON-1~7。先查了 Cloudflare 侧的接口能力，结论决定布局：配额拿不到，成本数据每日才更新，所以这张页不能做成"实时仪表盘"，只能做成"用量 + 估算 + 滞后声明"。

页面分三层信息：账户本月成本 → 各产品用量与估算占比 → 本项目在账户内的占用。刷新设置与口径声明放在最底部，不抢视线。

技术条件核对

设计前逐项查过官方文档。结论里有两处会直接改变产品形态：配额没有接口，成本数据每日更新。下面这张表就是页面能显示什么、不能显示什么的边界。

数据接口与标识权限 / 频率 / 限制
账户成本与计费用量 GET /accounts/{id}/billable-usage
（Billable Usage API，Alpha）		 Billing Read；每日更新；仅自助账户，企业合约不支持；返回 FOCUS 字段（ServiceName / ConsumedQuantity / ContractedCost / CumulatedContractedCost）

d1StorageAdaptiveGroups（databaseSizeBytes）		 同上；按 databaseId 过滤；保留 31 天

本应用自身计数 Worker 内部埋点 → MonitorSample 表 零配置可用；只反映本应用，不代表账户总量（FR-MON-3）
五条必须先接受的前提：
1. 没有配额接口。所有百分比都是「用量 ÷ 本地常量」，必须标注估算，不能写成官方口径。
2. 成本每日更新。页面不能承诺"实时消费"，结论行要写滞后声明，否则用户会当成账单。
3. 一个 Token 两个权限。Billing Read 与 Account Analytics Read 缺一不可，配置页要说明，否则用户配了也拿不到数据。
4. 免费额度内可能不产生计费行。成本显示 $0 不等于没有用量，界面要用"用量"而非"费用"作为主指标。
5. Token 不是部署 Secret。按 C-7 存库加密、默认脱敏、可回显复制；不配也能用基础模式，不阻断一键部署（FR-MON-4）。

桌面端见 monitor-desktop.html：同一套信息层级横向展开为三行（四张卡 / 趋势与明细 / 底部设置条）。组件与令牌复用 mobile.html。
