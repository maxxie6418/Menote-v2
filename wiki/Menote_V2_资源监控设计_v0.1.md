## 1. 定位

资源监控与笔记业务解耦（FR-MON-1）。它回答三个问题：**这个月花了多少、哪项资源吃紧、本项目占了多少**。它不回答：精确账单、实时消耗、额度硬限制。

移动端是查阅主力，因此移动版信息密度最高、只保留判断所需的最小集；桌面版横向展开，补趋势与时间范围。

---

## 2. 技术条件（设计前逐项核对）

| 数据 | 接口 | 权限 | 频率 / 限制 |
| --- | --- | --- | --- |
| 账户成本与计费用量 | `GET /accounts/{id}/billable-usage`（Billable Usage API，Alpha） | `Billing Read` | **每日更新**；仅自助账户，企业合约不支持；返回 FOCUS 字段 |
| Workers 请求 / 错误 / CPU | GraphQL `workersInvocationsAdaptive` | `Account Analytics Read` | 按 `scriptName` 过滤；可查三个月，单次跨度 ≤ 1 周 |
| D1 读写行 / 存储 | `d1AnalyticsAdaptiveGroups`、`d1StorageAdaptiveGroups` | 同上 | 按 `databaseId` 过滤；保留 31 天 |
| R2 容量 / 操作 / 流量 | `r2StorageAdaptiveGroups`、`r2OperationsAdaptiveGroups`、`r2BandwidthUsageAdaptiveGroups` | 同上 | 按 `bucketName` 过滤；保留 31 天 |
| **套餐配额** | **无公开接口** | — | 必须由应用维护常量表 |
| 本应用自身计数 | Worker 埋点 → `MonitorSample` | 无（本地） | 零配置可用（FR-MON-3） |

### 2.1 五条必须先接受的前提

1. **配额没有接口。** 所有百分比都是「用量 ÷ 本地常量」，界面必须标注估算，不能写成官方口径。
2. **成本每日更新。** 页面不能承诺实时消费；结论行要写滞后声明，否则会被当成账单。
3. **一个 Token 两个权限。** `Billing Read` 与 `Account Analytics Read` 缺一不可，配置页必须写明，否则用户配了也拿不到完整数据。
4. **免费额度内可能不产生计费行。** 成本显示 $0 不等于没有用量，主指标应当是「用量」而不是「费用」。
5. **Token 不是部署 Secret。** 按 C-7 存库加密、默认脱敏、可回显复制；不配也能用基础模式，不阻断一键部署（FR-MON-4）。

> 额度常量会随官方调整失效，建议写死在代码里并在设置页留一句「额度以官方为准」，而不是做成可配置项——配置项会让用户以为填了就是准的。

## 3. 页面结构

### 3.1 移动端（`monitor.html`，三屏）

| 屏 | 内容 |
| --- | --- |
| 01 官方模式 | 来源条 → 本月费用 → 四张产品卡（2×2）→ 本项目占比 → 自动刷新 → 口径声明 |
| 02 基础模式 | 无 Token：来源条变灰点，卡片标签换 `本地`，数值换「本周累计 + 估算日均」，多一行「接入官方数据」 |
| 03 监控配置 | Token（脱敏 / 查看 / 复制 / 替换）· 账户 ID · 刷新 5/15/30/60 · 阈值预设 |

### 3.2 桌面端（`monitor-desktop.html`，单屏三行）

1. **四卡一行**：费用（含 14 天迷你柱）+ Workers / D1 / R2（补次要指标：错误率、写入行、存储）。
2. **趋势 + 明细**：7 天请求柱状（含日期轴）+ 本项目表格（资源 / 标识 / 用量 / 占账户），未启用项显式列灰。
3. **底部固定设置条**：刷新 / 阈值 / 数据来源，不随内容滚动。

桌面多出两件东西：趋势图（纵向空间换来的）、「概览 / 近 7 天 / 本月」时间范围切换。

## 4. 口径规则

三类数据必须可区分，不得混成看似精确的账单（FR-MON-5）。界面用卡片角标实现：

| 标签 | 含义 | 来源 |
| --- | --- | --- |
| `官方` | 官方接口实测 | GraphQL Analytics 或 Billable Usage |
| `估算` | 按公开额度推算 | 用量 ÷ 常量表 |
| `本地` | 仅本应用统计 | `MonitorSample` 表，不代表账户总量 |

**分摊规则**：本项目区只显示「账户内占比」，不重复配额。账户额度共享，把 100k 请求/日 当成 Menote 独占是错的（FR-MON-2）。

**柱状图规则**：桌面趋势图按 7 天峰值归一，必须标注「纵轴 0–x · 非额度比例」，否则会被读成接近上限。

---

## 5. 刷新与预警

- **自动刷新**：关闭 / 5 / 15 / 30 / 60 分钟（FR-MON-5）。它控制后台采样频率，不等于数据源更新频率。
- **手动刷新**：顶栏按钮；不改变自动频率。
- **阈值**：70 / 85 / 95 % 三档预设（FR-MON-6），桌面上可精确调整。
- **预警不是硬限制**：只提醒，不阻断写入；统计存在延迟，界面必须写明。
- **保护动作**（FR-MON-6）：AI 接近预算暂停自动/批量推理、暂停非必要图片转换、后台任务限流；配额不足优先保证阅读与编辑。

---

## 6. 安全

- Token 只读、只给两项权限（见 §2）。
- 存库加密，列表不展示明文，支持事后查看与复制复用（C-7）。
- 不配置 Token 时走基础模式，不伪造数据、不静默降级到「看起来有数据」。
